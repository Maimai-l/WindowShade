# 屏幕距离：人体工学和桌子

2026-10-04。这是人体工学与桌面常见尺寸的对照，不是 Apple 对 Mac 的官方屏幕距离，也不是已经做出来的功能。没有改 App，没有在这台 Mac 上测量。

Mac 上没有官方的英寸阈值。见 [screen-distance.md](screen-distance.md)。各档面板的 1 角分类比线大约 34–40 公分，见 [screen-distance-by-size.md](screen-distance-by-size.md)。本文不把 50–100 公分写成 Apple 的屏幕距离，也不把类比线写成「人该坐在这里」。

1 吋 = 2.54 公分，只用于把出处里的英寸换成公分。出处自己写了成对的英寸和公分时，两数都留，不另造第三个官方厘米数。

## 观看距离

先分开两种文本。标准写进正文的数，和教学网站的常见建议，不是同一层。

[人机界面指南](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos) 写坐在桌前大约 1 到 3 英尺，约 30–91 公分。那是内容该做多大，不是警报，也不是上表里的人体工学标准。见 [screen-distance.md](screen-distance.md)。

50–100 公分是 HFES 摘录和 OSHA 教学页都写过的一段。它是坐着工作的距离。不是 Apple 的屏幕距离，也不是「近于它就贴太近」。

## 脖子

这一节只记出处怎么摆屏幕、怎么评估静态姿势。不写成诊断，也不写已经能减少颈椎病。

视线角和颈屈曲不是同一个角。OSHA、Cornell 写的是眼睛看向屏幕中心的角度，或屏幕上缘相对眼高。ISO 11226 写的是头相对躯干的屈曲。AirPods 的俯仰又是第三件事，见后文。

| 出处 | 哪种文本 | 原文里的数 |
| --- | --- | --- |
| [ISO 11226:2000](https://www.iso.org/standard/25573.html) 表 3，[预览摘录](https://standards.iteh.ai/catalog/standards/iso/0bd9cbcd-32e5-4fa3-94ca-5ff699c55588/iso-11226-2000) | 静态工作姿势的评估标准。2026-04 起标记为将修订，这次引用的仍是 2000 版正文摘录 | 颈要先对称（没有轴向扭转，也没有侧屈）。颈屈曲或伸展是 β−α：大于 25° 为 not recommended；0° 到 25° 为 acceptable；小于 0°（伸展）为 not recommended。正值叫屈曲。这不是眼睛到屏幕的公分 |
| 同上，目录站的概述 | 概述页的话，不是这次核到的标准正文句子 | 概述写静态姿势指维持超过 4 秒。不把 4 秒当成提醒阈值 |
| [OSHA 显示器页](https://www.osha.gov/etools/computer-workstations/components/monitors) | 教学页 | 屏幕上缘在眼高或略低于眼高。屏幕中心通常在水平眼高以下 **15 to 20 degrees**。向下的观看角在四种参考姿势里都不要大于 **60 degrees**。屏幕太高会仰头，太低或太偏会让头、颈处在别扭的姿势 |
| [OSHA 补充说明](https://www.osha.gov/etools/computer-workstations/additional-information) | 教学页 | 头和颈竖直，与脊柱成一线，不要弯，不要扭。屏幕放低到上缘不超过水平视线，以免仰头 |
| [Cornell DEA](https://www.ergo.human.cornell.edu/ergoguide.html) | 教学页 | 坐稳后，眼睛对准机壳顶缘往下大约 **2–3 吋** 的那一点（不是面板顶）。屏幕中心大约在水平线下 **17–18 度**；同一页后文写大约 **17.5 度**。太低会向前探颈，并造成颈屈曲；太高会仰头 |

ISO 11226 没有把「大于 25°」写成颈椎病。它是静态姿势评表上的 not recommended。本文停在这一句。

## 桌子

深是前后，宽是左右，高是台面到地面。EN 527 写死了一部分。60 / 70 / 80 公分深、120 / 140 / 160 公分宽里，有的是标准，有的只是货架上的尺寸。

[EN 527-1:2011](https://cdn.standards.iteh.ai/samples/26022/6cc3729a004c4ce9a231c68a38e8620c/SIST-EN-527-1-2012.pdf) 的表 1，单位毫米：

| 项 | 标准写了什么 |
| --- | --- |
| 固定高度，坐姿，Type C | 台面高 **740 ± 20**，即 720–760 毫米（72–76 公分） |
| 坐姿可调，Type A | 至少能覆盖 **650–850** |
| 坐站可调 | 至少 **650–1250** |
| 最小台面深 | **800**。注 f：有些情况 **600** 可以接受，例如用 17 吋或更小的平面屏、台面不靠墙、且不是两人对坐。这些限制要随产品说明。70 公分不在这句里 |
| 台面宽 | 注 2：**没有规定宽度**。宽和形状随任务变 |
| 坐姿容膝宽，固定高度 | 最小 **850**。这是膝下的空档，不是台面宽 |

[ANSI/BIFMA X5.5-2021](https://www.bifma.org/page/StandardsShortDesc) 是桌子的安全、耐久和结构测试。[公开转载](https://studylib.net/doc/28440326/ansi-bifma-x5.5-2021--desk-and-table-products-)把 desk 定义成主工作面高度在 **660–965 mm（26–38 in.）**。那是这套测试覆盖哪些产品，不是「建议把桌子做成 72–76 公分」。72–76 公分对上的是 EN 527 的 740 ± 20。

## 从桌深推到眼睛

人坐下来，眼睛不在桌后缘。外接屏幕可以往后放。笔电的屏幕钉在键盘后面，不吃满桌深。两件事分开算。

外接屏幕、屏幕尽量靠后时，本文用的式子是：

眼睛到屏幕前表面 ≈ 桌深 − 身体占位 − 整机深度

它是下面这句的收法。完整写法先列出来，避免把没测的项收成一个数：

眼睛到屏幕前表面 ≈ 桌深 − 身体占位 − 键盘前缘到桌沿 − 键盘深度 − 键盘后缘到屏幕前表面的空隙

屏幕后缘已经贴住桌后缘时，最后一项空隙和整机自己的前后尺寸合成「整机深度」。条件有两条：整机后缘贴着桌后缘；规格上的深度等于面板前表面到整机后缘的距离。第二条规格没写。所以算出来的是上界，不是坐下来量到的距离。

| 项 | 范围 | 出处 | 这次怎么用 |
| --- | --- | --- | --- |
| 桌深 | 60、70、80 公分三档 | 上节。60 有注 f 和 LAGKAPTEN；70 是 RIDSPÖ，标准最小值不是 70；80 是 EN 527 最小值，也是 TROTTEN / BEKANT | 三档都算。70 公分是市售，不是标准最小值 |
| 身体占位 | **未知** | 坐进桌子后，眼睛的铅垂面落在桌前沿后方多少，这次没有对上标准数。EN 527 的容膝深是台面底下的空档，不是这段 | 不代填。上界表把这项当成 0，并写明那是眼睛正在桌前沿正上方 |
| 键盘前缘到桌沿 | **未知** | OSHA、EN 527、HFES 摘录都没有写死这段空隙的公分 | 不代填 |
| 键盘深度 | Apple Magic Keyboard，带或不带数字键，都是 **11.49 公分（4.52 吋）** | [不带数字键](https://support.apple.com/en-us/121954)、[带数字键](https://support.apple.com/en-us/121953) | 口头常说的 15–20 公分，这次没有对上标准，也不对上这把键盘。不拿 15–20 进算式 |
| 屏幕到桌后缘的空隙 | **未知** | 没有写死要留多少 | 上界假设后缘贴齐，空隙按 0 |
| 整机深度 | Studio Display 倾斜支架 **16.8 公分**；高低可调支架 **20.7 公分**；27 吋 iMac（2020）支架深 **20.3 公分** | 下节 | 用来当上界里的整机深度。面板在这段深度里偏前还是偏后，规格没写 |

上界 = 桌深 − 整机深度。眼睛在桌前沿正上方、后缘贴齐。人坐进来，身体占位大于 0，距离只比上界更短。短多少未知。

| 60 公分 | 43.2 公分 | 39.3 公分 | 39.7 公分 | 上界。已经靠近或短于 27 吋那条 40.1 公分的类比线，短于 OSHA 写的 50 公分近端 |

| 80 公分 | 63.2 公分 | 59.3 公分 | 59.7 公分 | 上界。眼睛若真在桌前沿正上方，可以落进 50–100 公分。身体占位一减，可能掉出这段 |

## 距离和头的朝向

坐姿是两件事叠在一起：眼睛到这块屏幕有多远，头有没有长时间低着。远近关系眼睛。低头关系颈。AirPods 只能碰后一件里的朝向，碰不到公分。

### 耳机给的是朝向

[CMHeadphoneMotionManager](https://developer.apple.com/documentation/coremotion/cmheadphonemotionmanager) 流出的是 [CMDeviceMotion](https://developer.apple.com/documentation/coremotion/cmdevicemotion)：姿态 attitude（含俯仰 pitch）、角速度 rotationRate、用户加速度 userAcceleration。WWDC23 说，空间音频的动态头部追踪用的就是这套设备运动算法；这个类把同一套数据开放出来：姿态、用户加速度、角速度。[口述在这里](https://developer.apple.com/videos/play/wwdc2023/10179/)。

这里面没有眼睛到屏幕的公分。俯仰是耳机相对参考系的角度，不是 ISO 11226 的 β−α。接口不量躯干倾角，就不能把 pitch 换成颈屈曲。

| 事实 | 出处怎么写 |
| --- | --- |
| 哪些产品 | 支持页：AirPods 3、AirPods 4、AirPods 5、AirPods Pro、AirPods Max 用空间音频和头部追踪。要戴上，并且连着这台设备。[支持页](https://support.apple.com/guide/airpods/control-spatial-audio-and-head-tracking-dev00eb7e0a3/web)（该页写明指南对应 iOS 27 等）。WWDC 说接口的对象是支持空间音频动态头部追踪的音频产品，举例 AirPods Pro |
| 要不要连着 | 要。数据在音频设备连上这台 iPhone、iPad 或 Mac 时才有。自动入耳检测开着时，取出耳机算断开。接口从 iOS / iPadOS 14 起，macOS 14 起 |
| 是不是空间音频的副产品 | 用户开关有三档：Off 两者都关；Fixed 开空间音频、关头部追踪；Head Tracked 两者都开，声音像从这台 iPhone 或 Mac 出来。WWDC 说接口放出的是动态头部追踪那套数据。选了 Fixed 之后接口还流不停，口述没有写。**未知** |

| 许可 | 要运动数据的用途说明。没许可就没有流 |

镜头被挡住时，眼睛距离未知。见 [screen-distance.md](screen-distance.md)。耳机的朝向填不上这个洞，距离也填不上朝向。

### 两件一起看

距离用两条已有的线，都标出出处，不混成一条。

- 贴太近：近于 [screen-distance-by-size.md](screen-distance-by-size.md) 里该面板的 1 角分线，大约 34.4–40.1 公分。
- 坐姿距离：ISO 303 的 40–75 公分，以及 HFES 摘录 / OSHA 教学页的 50–100 公分。近端取 OSHA 写的 50 公分来对照。这不是提醒线。

头的俯仰只在有头部追踪、并且耳机连着这台 Mac 时才有。pitch 向下是头低了。它不是颈屈曲的度数。一下子低头看键盘，和长时间对着低屏幕，要分开。分开用的秒数，Apple 没有公布。**未知。** 以后若要一个初值，必须标成初值，不能写成和 iPhone 屏幕距离一样，也不能写成 ISO 11226 的秒数。

| 距离 | 头 | 坐姿在说什么 |
| --- | --- | --- |
| 近于类比线，或近于人体工学近端 50 公分 | 保持平视 | 贴得近。颈的负荷不一定是低头。距离和低头是两件 |
| 落在人体工学的坐姿距离里 | pitch 长时间向下 | 多半是屏幕太低，或笔电直接放在桌上。头在低着。pitch 仍不是 β−α |
| 近于类比线 | pitch 向下 | 两件一起。坐姿最差的一格 |
| 未知，或镜头被挡 | 没有头部追踪的耳机，或耳机在别的设备上 | 朝向未知，或距离未知，或两者都未知。未知不要写成坐得正，也不要写成够远 |
| 不由这一格决定 | 低头只是看一眼键盘 | 和长时间低着看屏幕分开。持续多久算长，未知 |

### 不越过的界

和 [screen-distance.md](screen-distance.md) 对齐。还没做。

- 头部朝向不能写成眼睛到屏幕的公分。
- 不能当成是谁。耳机在动，不是身份。
- 不能取消「人走远了」的锁，也不能参加那次倒数。
- 不能让番茄钟停下、跳过或结束。
- 提醒若有，只长在已有的刘海。不盖住桌面，不新建一套窗口。
- 文案不诊断颈椎病，不写已经减轻了颈的负担。用 [copy-guide.md](copy-guide.md) 里已有的词。
