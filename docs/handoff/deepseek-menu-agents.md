## A1：编程会话（纯逻辑）

新文件：`prototype/Core/AgentSessions.swift`、`tests/AgentSessionsTests.swift`、`tests/run-agent-sessions-tests.sh`。

- 输入：hook 事件，用一个与具体助手无关的结构表示，字段为助手（claudeCode / codex）、会话 id、项目目录、事件种类（开始、用户发了话、工具前、工具后、停止、要批准）、命令或文件（一行）、时间。另外还有“批准的回答”和“超时”。
- 输出：会话表，每个会话的状态是在跑 / 等你 / 完成 / 断了；刘海该显示什么（紧凑、展开、短暂提醒）；批准请求。
- 规则：
  - 要批准的请求有唯一编号；回答必须对上编号才生效，用一次作废；
  - 2 分钟没回答就超时，结果是“交回终端”；
  - 风险分级照规格：推送、删除、联网、改项目外的文件算高风险，其余算普通。规则写成表，便于以后改；
  - 会话 10 分钟没有任何事件，标成“断了”，不删；
  - 同一个项目有几个会话时，按会话 id 区分，不按项目名合并。
- 测到：上面每条；乱序事件；重复事件；回答一个已超时的请求。

## A2：`ws-hook` 小命令行和本机 socket（App 层 + 一个小可执行文件）

- 小命令行：读标准输入里助手给的 JSON，转成 A1 的事件，经 Unix socket 发给 WindowShade。
  - socket 放在 `~/Library/Application Support/WindowShade/` 下，权限 0600；
  - 连不上就立刻退出，按“放行给原来的流程”的方式返回（照 Claude Code / Codex 的 hook 约定）；
  - 要批准的事件等 WindowShade 回答，最多 2 分钟；
  - 不读、不写别的文件，不联网，不打日志。
- 先看 `prototype/build.sh` 怎么收集源文件，别让第二个 `main` 编进主程序。小命令行单独编译，放进 `WindowShade.app/Contents/MacOS/`。
- “连接 / 断开”：
  - 改 `~/.claude/settings.json` 和 `~/.codex/config.toml`，**写之前生成差异给用户看**（先返回差异文本，由界面层显示），用户确认后才写，写之前把原文件备份到同目录；
  - “断开”只删自己加的那几行，用一个标记识别；
  - hook 的字段名、配置格式没有官方文档依据的，标“待对照官方文档”，**不要编**。
- **这个包改的是用户的配置文件，风险高**：只写代码和测试（用临时目录里的假配置文件），不在真实的 home 目录里执行。
- 检查：`./build.sh --check`；用假配置文件的测试。

## A3：刘海里的编程会话（App 层）

- 在已有的实时活动里加一种 `agent`，排在“番茄钟”之后。照规格的紧凑、展开、等你、完成四种样子画；只有“等你”会主动展开。
- 点卡片“过去”：调用 WindowShade 已有的找窗口、放回窗口能力（读 `prototype/WindowBrowser/` 和刘海那一排的代码，用已有入口）。按 pid 或终端 App 加窗口标题找到那扇窗。找不到就激活那个 App，不报错弹窗。
- 批准按钮这一步只把“允许 / 不允许 / 去看看”交回 A1；Touch ID 和授权账由主模型接（A4）。
- 符号和文案照规格；“等你”的琥珀点、转圈都用 Core Animation。
- 检查：`./build.sh --check`；在报告里写清用假事件怎么在开发版里触发每种状态。
