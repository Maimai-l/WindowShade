## 先看哪里

`VALIDATION.md` 是本次实跑记录。`integration/MAC-ACCEPTANCE.md` 区分仍欠源码、SDK未编译与真机未测试。`integration/package-status.json` 给每个包标了实际完成粒度。不能把包目录存在、说明写齐或禁用控件出现当作相应功能实现。

## 合并方式

推荐使用统一总包。其 `candidate-repo/` 已按三份的次序组成完整仓库副本，可直接看差异；`WS2-STAGING.json` 标注原文件改动和新增文件来源。该副本未构建，不要替换正在开发的真实仓库。

本份单独使用时，与前两份放在独立目录，执行：

```sh
python3 tools/stage-all.py --repo /原始repo绝对路径 --part1 /第1份绝对路径 --part2 /第2份绝对路径 --out /全新候选repo路径
bash tests/run-core.sh
```

工具只接受本次委托的1079文件固定快照，校验SHA256和唯一原文锚点。已有输出、来源变化、合同冲突均停止。它不修改原repo、真实home、CLI配置或系统设置，不启动助手，不签名、安装或提交。对已更新的工作区须先人工合并，不提供强制覆盖开关。

合同只保留 `prototype/Core/Contracts.swift` 一份。D6新版替代第二份CodexWire。独立helper在 `tools/ws2-hook/`，其 `@main` 不进入App的源码扫描。不要用本份 `patches/files/` 整文件覆盖前两份改动；统一工具逐条组合补丁。
