# 设备输入：把可观测输入接成有限动作

## 五层分别回答不同问题

GameController/IOHID/CGEventTap 回答“收到了什么”；设备登记回答“是哪一次附件”；交互租约回答“现在控制哪个界面”；语义路由回答“这个按键在这里表示什么”；具体 sink 回答“当前目标能否实际执行”。一种输入来源通过测试，不等于另四层都完成。

第四份已有 WS2DeviceInputGate 和 WS2GameControllerBridge，本次 WS2DeviceActionHost 只收拢所有者和语义路由，不再创建第二套 handler。每次连接使用新 attachment UUID，设备同型号、同名称不能继承旧许可。WS2SemanticInputRouter 票据还绑定 lease、domain、targetRevision、backendEpoch 和 press ID。

票据在 release 时生成、消费一次，sink 执行前复核真实选中目标。不跨多个 await 留着一个“当时允许”的 Bool。按住 A 时切项目，松开 A 不应提交新项目；进入审批、游戏前台、锁态不明、断连或禁用时取消 held 状态。直接调用 App 方法同样可能有副作用，所以即使不发合成键盘，也不能省这些复核。

## 已定的第一条可交付映射

先把方向键接到原生列表前后项，A 打开本地已选项，B/Menu 关闭当前本地交互。A 不代表批准命令、解锁或发送草稿。指挥的提交/中断应走单独有明确目标与文案的 typed intent；未实现的 X/Y/肩键保持无动作，不自行发明模型/effort 切换。

V1 只启用一个附件和一个 lease，启用第二个先取消第一个。目标变化后要求本地重新启用，是保守工程默认。为了未来改善手感，可以增加“旧 lease cancel → 等所有轴回中/所有键抬起 → 生成新 lease → 明示交接”的状态机；不把平滑过渡做成隐式继承。

held 状态上限 32，票据历史上限 4096；耗尽后重新建立明确会话，不清空去重集后继续让旧 press ID 可用。样本率、摇杆死区和回中语义沿用原 GamepadMapping，不凭新增 wrapper 猜测硬件报告含义。

## 摇杆能力必须独立

sink.ready 可以只表示列表导航可用；motionReady 则要求真实桌面执行器存在、目标可操作、当前域为 desktop。本次在 GameController Environment 中新增 motionReady，两个判断都到位才启动连续运动。一个空闭包返回 true 会使隐藏循环持续工作，还让设置错误宣称设备可移动窗口。

真实移动 adapter 需要自己的窗口身份、几何限制、屏幕坐标变换、权限和手动干预规则。禁止让摇杆绕过已有 ShadeController/窗口动作策略，直接随意调用 AX 或私有 WindowServer。稳定后再增加触发器反馈；失焦、锁屏、关闭、断连必须恢复阻力为零，不拿“对象释放大概会复位”当协议。

## 为什么其他三种来源先不硬接

IOHIDManager 能看到设备不表示已经知道每个 usage 的意义。只对确切 VID/PID、usagePage/usage、元素和报告样本建映射；同一个硬件从不同传输路径出现也可能不同。遥控器触控面、麦克风和系统遥控按钮分别列能力，不因为按钮可读就宣布支持音频。

hidutil 写入改变系统映射，属于显式用户操作。计划必须读当前值、限定确切设备、比较预期旧值后写、保留原值。撤销时若外部软件已修改，不回写过时备份覆盖它。设备不存在或 matching 无法证明时不退成全局键盘映射。相关 runner 仍未新增。

CGEventTap 接入先证明来源和共存，不靠单个 continuous 字段把滚轮认成触控板。合成事件使用受控标签且只忽略自己的标签；系统与其他工具事件不能被一概吞掉。Tap 失效、权限撤销、休眠时清 held/修饰键状态并停止，不能忙等自动重装。私有多触点的结构和 callback ABI 未证实仍拒绝接入。这些都是独立源码/设备证据项，不算本轮 GameController 通过的一部分。

## 不要让设置页制造事实

列表来自 bridge 的真实 devices，不能预填“Apple TV 遥控器”“DualSense 已连接”。连接状态、已启用的本地 lease、可导航、可移动、可反馈是不同字段。错误文案保留可行动信息：未接动作执行器、当前是其他应用/游戏、权限未获准、目标已变化，请重新启用。不能因为桥实例存在就启用所有开关。
