# 统一生命周期与取舍：避免五个好模块拼成一个坏系统

## 谁负责取消

AppRuntime 是 App 内唯一组合点；各 feature owner 可以独立构建，但不能互相拥有第二份全局服务。授权账仍归原 AuthorizationService；普通交互租约仍归原 InteractionCoordinator；岛仍归原 WS2IslandCoordinator。设备票据只限制来源和目标，不代替这些权限服务。

取消顺序固定为：标记当前上下文不可用 → 撤销 lease/held/授权待办 → 阻止新的物理写入 → 关闭外部传输 → 等待可能已发生的窗口动作结算 → 只关闭同 owner/token 的 UI。若顺序倒过来，关闭窗口可能触发别的功能重新占岛，旧关闭回调便会误删新界面。

网络和进程采用“失败后关闭，副作用不重放”；窗口采用“停止新提交，但接住旧结果并补偿”。不能写一个通用 cancelAll 把两者都清空，因为窗口可能已经变了，必须恢复归属；批准字节已经写出则无法回收，只能查询结果。

|J20|源/目标变更时取消 held|旧 press 不落到新项目|

|J23|用户干预移除自动归属|不覆盖用户后来的操作|
|J24|unknown 阻断而非无限重试|无法确定系统结果时保留现场|
|J25|不使用 tuckAll toggle 作为 T3 命令|调用一次/两次不能改变含义|
|J26|不在 tick 扫描并收走新窗口|避免常驻干扰；每阶段明确快照|
|J27|锁态未知按不可执行|通知只能触发复查|
|J28|optional-srp 不自动入 target|依赖解析、许可、侧信道、互测分别审批|
|J29|真实设备/系统证据单列|不把合成测试、parse 和网络接通混算|

J08 和原生 Remote 协议事实不能靠偏好决定；J17 等可由主模型在获得完整测试后改变。修改时必须说明哪个不变量保持不变，不只把开关放宽。

## 全局资源与能耗

单实例不等于低功耗。本包没有瓦数、耗电改善或设备延迟的实测结论。通道使用事件驱动与最近截止；运动循环只有真实 sinkReady/motionReady/有效域才允许。应用 idle、功能禁用、界面关闭、锁屏和断连五个状态分别测唤醒数、线程、文件描述符和 resident memory。比较必须沿用 part1 BuildBaseline 的同设备/同条件，不能拿 Linux 测试耗时当 Mac 能耗。

待认证连接即使每条限长，也需全局容量。Keychain 单快照虽小，调用仍可能阻塞，先按明确本地动作触发，不在 60fps 回调中读。SRP 大整数工作需测主线程影响；未测之前不声称“丝滑”。把昂贵工作迁到 worker 时保留 generation 和回主 actor 二次复核。
