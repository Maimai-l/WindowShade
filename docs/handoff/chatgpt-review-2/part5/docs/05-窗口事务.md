# 番茄钟窗口效果：接到既有折叠事务的最终状态

## 先纠正入口理解

基线 `prototype/App/Notch.swift` 的 tuckAll 是菜单/手势的切换动作。它会记一批窗口，再调用时可能把这批放回；默认筛选还依赖指针所在屏。番茄钟需要“把这一组明确窗口变成目标状态”，不能直接复用该切换入口。tuck 也有截图和动画异步过程，返回或列表插入不代表真实窗口已隐藏。

基线不是没有事务设施：ShadeController.shade 在入口捕获已有 fold waiter token；FoldCompletion.registerFoldWaiter 返回 UUID，30 秒兜底只结算该 token；FoldTransaction 在验证隐藏或回滚时结算；ShadeState 有 foldTransactionID。WindowBrowserAppDelegate 和 EventTap 已使用等待器。第五份施工从这些点扩展，禁止再写一套绕开恢复日志的隐藏器。

仍有两个不足：某些结算按 windowID 批量通知，而新效果需要区分具体事务；Bool false 也可能来自“没有发生”“超时仍在进行”“已经回滚”等不同事实。不能把它无条件转换成 unchanged。先补结果来源和最终回读，再把它转换成新 plan 的结果。

## 一张快照不是一张所有权证书

每个目标保存 pid、processStart、windowID、windowGeneration 和 mutation revision。pid/windowID 都可能复用；标题会变，不能作身份。processStart 和 generation 缺可靠来源就不纳入自动操作，而不是填 0。用户已经手动收起的窗口不属于本轮；用户在本轮操作后手动恢复/移动过的，也不再属于本轮恢复责任。

Receipt 只记录真实已完成的操作，含 run token、effectGeneration、beforeRevision、afterRevision。新计划串行调度，每次只有一个物理操作在途。阶段切换先处理旧回执再收新目标；晚到的旧收起成功仍会获得旧回执，随后做补偿恢复，而不是因为任务取消就忘了它已经改变窗口。

需要区分结果：completed(afterRevision) 代表确认完成；unchanged 代表确认没有修改；userChanged 代表用户已经接管，放弃自动恢复；unknown 代表不能确定动作或恢复结果，停止新自动效果并提示检查。不要在 30 秒超时后假写 completed，也不要一律 unknown 然后继续批量重试。

## 顺序比动画速度更先决定正确性

专注转休息可能同时包含“恢复聊天窗口”和“收起全部”。若两个异步循环并行，最终结果取决于截图和 AX 回调的到达顺序。WS2FocusEffectPlan 明确设置阶段屏障：先恢复旧阶段，确认结果，再开始新阶段。即使同一窗口还在新目标集，也先处理旧归属，不把旧回执移花接木成新阶段完成。

专注期间结束、锁屏或进入休息时，不 cancel 一个 Task 就遗忘它。执行器保留在途操作完成路径；mayCommit 在最后物理操作前复核当前阶段。已经提交到系统的动作可能仍完成，必须接住回执。锁中不自动恢复可能暴露的窗口；解锁只有经现有可靠锁态确认才恢复调度，不使用屏保通知直接当已解锁。

App 退出或崩溃时依赖既有 DurableShadeJournal 的恢复体系，不能仅靠本次内存 receipt 声称跨重启回滚保证。本轮 receipt 未写入该日志。若需要跨重启继续番茄钟效果，要另做迁移与归属设计；V1 不恢复计时任务中的未决自动动作，先完成已有窗口恢复流程。

## 候选目标怎样产生

现有 `Core/MagicTiling.swift` 的 role(bundleID:category:) 可作聊天类候选，不是隐私白名单。它的 chat 表是平铺分类的实现细节，不能拿它当“所有敏感 App 已收起”的承诺。V1 由用户明确开启效果；无稳定分类证据的 App 跳过，不猜聊天内容，不读窗口正文。

“全部”也要有范围：本包建议只对当前可见空间中经既有策略判定可操作的普通窗口，排除本 App 浮层、系统授权、已经收起/最小化、未知身份、无法回读和已有用户事务在途的窗口。多显示器使用显式屏幕集合，不能用指针位置默默改变同一轮目标。是否将所有显示器纳入属于产品选择，默认沿当前明确选定范围，不新增跨 Space 操作。

效果能力未完成时，计时照常，设置写“窗口效果尚未接入，当前只计时”。短暂权限失败不重置整轮计时，不修改用户窗口，不把开关自动改成新的承诺。提示音走既有音效控制并尊重用户设置，不在每秒 tick 创建播放器。

## 单纯复用 hideTookEffect 还不够

现有 offscreen 分支在读不到 AX 几何时会返回 true，用于既有隐藏逻辑。本轮强所有权回执不能据此确认完整身份/归属。具体端口必须另有可验证的终态；读取失败记 unknown，不因为旧 helper 返回 true 就声称窗口由本轮安全收起。

窗口效果端口仍是本份明确的源码缺口。本次已把 plan/executor 写好并测了迟到完成、顺序屏障和手动接管，但没有改私有隐藏后端，没有编造真实 AX 完成结果。施工单给出具体旧函数与新增结果类型，执行模型在 Mac 完成这一处后，才把 motionReady/效果能力打开。
