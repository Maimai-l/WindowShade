# Owned 助手进程：消息真正写出去以后不能撤回

## 选择唯一所有者

本次 WS2OwnedCodexSession 拥有一个 Process、一条 stdout 管道、一条 stdin 管道、一个 CodexWire、一个审批宿主和一个最近截止任务。不能用一份 Wire 发普通消息、另一份 Wire 发允许响应；请求 ID、连接代次、thread/turn 和 pending 状态会脱节。原 WS2ProcessChannel 不在本次修改范围，新的 owned 路径明确使用 WS2DuplexProcess。

旧式“串行队列里读一整行，读完才执行下一个写任务”会造成双向依赖：助手等批准，宿主等下一行，两边一起等。新通道分别监听可读与可写，单次处理有限字节，把剩余工作交还事件循环。测试真的启动 Python 子进程读 stdin、写 stdout，未假称启动了 Codex。

当前官方 stdio 描述是按行 JSON。落地契约仍是附件固定的 0.153.0 schema，而不是今天网页新增的全部方法。当前资料用来复核生命周期，不把新字段硬塞给旧 schema。[S09][C-CodexWire]

## 四个时间点，四种不同承诺

|时间点|代码返回代表什么|绝不能据此显示什么|
|---|---|---|
|审阅完成|用户看过并选择了这个完整目标|已执行|
|授权账 consume 成功|这份绑定完整目标的 grant 被消费一次|管道已写成功|
|admitWireFrames 成功|整个有限批次进入本连接队列|助手已收到/执行|
|write 全部成功|这些字节交给本地管道|工具已完成|

命令的最终状态由有效的 app-server 事件确认。消费 grant 后入队失败，关闭这次会话，不把 grant 放回账本。半截 JSON 后断管同样不重试 accept。已经写出的字节不能因系统随后锁屏而收回，这一现实边界必须留在产品说明里。保证的是写入前尽可能近的检查和不再继续写，不是把已发生的副作用倒流回去。

## 最后一道检查必须挨着 write

每批消息记录 context、thread、turn、connection 和 deadline。队列真正可写时再检查：owned session 未关闭、AuthorizationService 当前解锁、mayOperate 仍成立、上下文和 thread/turn 未变化、当前时刻早于截止。绑定闭包执行失败就关流，不能仅跳过批准消息让后面一条普通消息继续。

WS2Clock 带起点，所有 deadline 都使用同一实例；不要拿 Date、不同 ContinuousClock 包装或进程 uptime 与之混算。新进程通道默认 2 MiB、32 条上限，JSON 行上限 1 MiB，单次事件处理上限 64 KiB。批次原子准入，部分写入保留偏移。数字均为本项目保守限制，不声称来自协议标准或性能测量。

每个过期请求都有明确任务，不要求不断发 tick 才会超时。锁屏、睡眠、用户停止、项目撤销、进程退出时先失效授权/lease，再停止 writer，之后清 UI。重复 close 是幂等的。新 UI 可能已经显示另一功能，旧 onEnd 不能无条件 dismiss 当前岛。

## 进程身份和环境也有边界

启动只能来自本地显式入口。传入经选择和验证的绝对 executable 路径、项目目录以及明确的环境集合，不拼 shell 字符串，不跑 `/bin/sh -c`，也不借 `open -a` 猜可执行文件。开发机用绝对路径解决找不到 CLI，不能借机让后台进程继承全部环境秘密。真正需要哪些 provider/auth 配置，按用户选的 CLI 和同意的项目范围决定。

认证材料仍由对应官方 CLI 的既有登录方式管理；WindowShade 不收集或导出它的 token。启用辅助功能权限不等于允许任意项目读写。初次所有权确认包括可执行文件身份和真实 cwd；启动后项目 UI 改名不能悄悄替换已审核的 cwd。

当前通道把 stderr 接到 null，避免泄漏和阻塞，但这会丢诊断。要加诊断时独立有界读取、明确脱敏和用户导出，不能把 stderr 混进 JSON 帧，也不能默认收集完整提示或密钥。主进程停止只终止自己创建的 Process；不 pkill 所有 codex、不给其他终端发信号。该实现没有超时 SIGKILL 升级或子进程树清理，加入前必须证明 ownership。

## 初始化与恢复的具体顺序

按唯一 Wire 的 begin/start 流程完成 initialize 响应，再发 initialized 和 model/list。选项来自真实列表中的 model 和 reasoning effort，不能把营销名称或历史记忆写成固定参数。thread/start 成功后持有返回的 thread ID；resume 也要等待对应确认，不因本地存在一个旧 ID 就启用提交。

turn/start 把完整草稿一次绑定到当前 thread。运行中 steer 必须带 expectedTurnId；旧 turn 的迟到回执不更新新草稿。interrupt 的请求确认不是最终完成；界面直到有效结束事件才退出运行态。断连后可让用户明确恢复 thread，但不恢复旧审批、不重复最后一次 turn/start，也不重放已经消费的 accept。

一次性普通命令之外，文件审批、网络审批、持久规则、批量永远允许仍明确不支持。缺可信 diff 就拒绝，不拿模型摘要代替真实差异。外部 Claude hook 的 invocation 生命周期和回复协议与 owned Codex 不同，不能直接复用同一个 accept 编码器或假定有另一扇原生批准窗接棒。
