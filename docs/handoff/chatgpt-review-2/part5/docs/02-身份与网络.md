# 持久身份与网络：让断线、撤销和重启各有确定含义

## 一个持久快照，两个不同版本

WS2PeerRepository 把本机长期标识、签名 seed、peer 公钥、enabled、awaitingVerification、全局配对标记和失败计数放在一个有界快照里。快照 revision 表示一次持久修改；peer revision 表示这份设备授权身份的代次。Pair-Verify 捕获后者，设备被撤销或换身份后旧连接的 token 就不再匹配。不能把设备名称、IP、蓝牙地址、RSSI 或一个 UI 列表行号用作这个 token。

每次修改先在局部副本上算完，验证、编码和持久写入都成功才替换内存快照。读取失败时不调用 provision“修复”；只有真的不存在且用户明确首次配置时才允许创建。损坏、锁中、签名变更造成的不可访问都应停止相关功能，不能用空列表覆盖原密钥。

Keychain 候选使用自有 service/account、data-protection keychain、不同步、WhenUnlockedThisDeviceOnly。它选择的是部署策略；真实签名、SDK 和系统行为必须用原 App 身份验收。只将 errSecItemNotFound 视为不存在，其他 OSStatus 全部保留；不在回调里弹交互认证，不回退到 legacy keychain 或 UserDefaults。[S07][S08]

不要写“多项 Keychain 操作具备数据库事务”。本次是单条有界值和单进程唯一 writer 的 persist-before-publish 设计，不提供多进程 compare-and-swap。若未来由 helper 同时写，就必须先增加 IPC 单写所有者，不让两个仓库各自持有旧副本。

## 撤销的两种结果

点击撤销时，先停止接收该 peer 的新动作，撤销 lease 和 held presses，再把新 revision 的禁用墓碑写入仓库，最后取消现有网络会话并更新 UI。当前仓库的成功路径会立即调用 onInvalidateAll；失败路径也停用本进程所有远端活动。

持久写失败必须显示“撤销未保存，远端控制已暂停”，不能显示“已撤销”后悄悄恢复监听。旧磁盘状态可能还启用着；同 UID 恶意进程、历史备份回滚和进程外篡改不在本仓库的保证内。因此下次恢复必须先完成真实持久撤销，不能因为当前对象 blocked 被清空就继续用。不要给不可访问的钥匙串做自动删除重建。

禁用墓碑会占用 16 个 peer 的容量。本份没有悄悄删除它们来腾位置，也没有允许同标识重配覆盖。产品需要一个本地受控的“重新配对/清理旧设备”事务：明确选择旧标识，确认旧连接已结束，重新走 PIN 和 M5，替换时分配永不复用的新 revision。这个事务仍需落源码，不能用公开 `enroll` 绕过冲突检查。

`current(identifier,key,revision)` 只查询已保存授权是否仍有效，不代表当前连接已经完成 Pair-Verify。输入准入还必须持有该连接经验证的 peer、完成 session、当前 lease 和有效动作域。awaitingVerification 不允许 UI 提前宣称远端可控。

## TCP 的 ready 与产品的 ready

WS2CompanionTCPTransport 只接一个已经 accepted 的 NWConnection，不建立 Apple TV 身份、不发布 Bonjour、不解释 OPACK、不决定 frame 是否允许。它负责有限收发和生命周期。NWConnection 的 ready 是网络层就绪，不能把它直接连到 RemoteSessionGate 的 verified flag。[S06]

外层拥有者建议状态为 accepted → pairing 或 verifying → negotiating → active → closing → closed。未认证只接受当前状态允许的握手消息；认证后也只接受版本明确支持的 session 与输入方法。plain frame 不能在 active 状态成为免认证后门。一个 session 能够解密，仍不说明它有某个应用动作权限。

网络回调都明确 start 在 main queue，才允许已有 assumeIsolated 写法。不得把 NWConnection 改到后台队列却只保留断言来压住 Swift 并发报错。昂贵 SRP 运算将来若移到专用 worker，结果携带连接代次、PIN 窗代次和截止时间，回 MainActor 后重新检查，再推进状态。

## 背压、截止与 nonce

每个 TCP 会话队列上限 256 KiB、16 条，局部 frame payload 仍沿用旧候选 64 KiB；字节流分段 64 KiB。一次只挂一个 receive 和一个 send。对端不读会吃满队列并关闭连接，不能无限缓存遥控输入。握手最初 10 秒，只有经过验证的状态进展能修改协议截止；任意垃圾字节不能延长存活。全局接入上限需 listener 另外实现，单连接有界不等于整个进程有界。

`contentProcessed` 只说明本地网络栈消费了发送内容，不能表示原生 Remote 收到、更不能表示动作执行。先把旧记录完整送完再送新记录，队首过期时关整条流，不能从已加密序列中跳掉一条。加密 nonce 一旦占用，即使入队失败也不回退计数器；关闭并在全新验证连接中生成新密钥。[S06]

网络结果有明确的“不知道”：发送中断、电源休眠或旧连接迟到回调，都可能让对端已经执行而本机没收到结果。任何有副作用的应用动作不得自动换连接重试。本地 writer 不承诺 exactly-once；需要协议自身提供不可复用 request ID、服务端去重和明确响应才能讨论更强保证。

## 发现层的事实边界

服务类型、TXT、系统版本行为、OPACK method 和 iPhone Remote 选择服务的规则都属于兼容性事实。不要填一个看似合理的 Apple TV 型号或标识骗过选择器，然后把发现成功记为配对成功。本轮保留精确证据缺口，提供连接层和内层握手用于受控探针。[S04]

记录证据时保存系统 build、硬件型号、工具版本、协议阶段、公开字段长度和时间；不保存 PIN、seed、共享密钥、原始授权命令或用户音频。第三方例子本身也可能有错误，按实际字节重新计算 frame length，不抄展示段落中的冲突数字。
