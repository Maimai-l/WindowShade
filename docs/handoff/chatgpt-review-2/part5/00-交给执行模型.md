# 第五份：把五条调用链接到真实结果

交接对象：接手 WindowShade 2 的执行模型。基线是第四份统一包的 `candidate-repo/`，不是公开仓库当前 HEAD。原工程、前三份的共享合同、授权账、单一刘海宿主都保留。本包提供源码增量、确定的工程默认、独立测试和逐文件施工单。不要重写本文充当实施结果。

先读 `CHANGELOG.md` 和 `REMAINING.md`。然后在全新目录运行 `python3 tools/stage.py --base /第四份/candidate-repo --out /新目录/candidate-repo`。它校验整份基线和补丁哈希，拒绝已有输出。实际工作区已往前走时，不用此脚本覆盖；按 manifest 的 baseSHA 做三方合并。第五份不向 GitHub 提交、不碰真实 home、不启用远端监听、不发布版本。

## 先做能独立交付的一条完整路径

优先执行 `workorders/03-真实助手进程.md`。新的 `WS2DuplexProcess` 已有真实子进程管道测试，`WS2OwnedCodexSession` 把它同第四份审批宿主和唯一 CodexWire 接起来。剩下是 AppRuntime 的唯一实例、用户启动入口、真实项目范围、锁态撤销和 Mac 构建。先完成 initialize → model/list → thread → turn → 完成/中断，再开放普通命令的一次性批准。这个顺序不依赖手机配对、手柄或窗口效果，可以单独合并和验证。

接着做设备的“本地启用一个手柄 → 原生列表导航 → 退出即撤销”闭环，按 `workorders/04-生产输入.md` 接 `WS2DeviceActionHost`。摇杆移动能力单独判断，未接真实窗口执行器时保持 false，不能用空回调伪装成功。最后接窗口效果，按 `workorders/05-窗口执行器.md` 改实际事务边界，不能直接调用有切换语义的 tuckAll。

配对和网络可以并行做隔离探针，但不能先广告 Bonjour 再补认证。首次配对有完整内层消息编排、持久状态合同、M5/M6 签名加密层以及外部 SRP 库的原创建议适配器。外部依赖仍须解析、审核、Mac 编译和独立向量互测；没有这些，不能把 PAKE 边界换成哈希或恒 true。`optional-srp/` 故意不进应用自动编译目录。

## 已经替你定下的做法

优先消除状态错配，不增加外部能力承诺。保留 3 次失败、冷却 300 秒的代码规则，纠正第四份文字里的 5 次/60 秒。PIN 窗 60 秒；失败预算是本机全局，不按对端 IP 清零。重启看见未完成配对标记，重新冷却 300 秒。

V1 一次只启用一个手柄和一个交互租约。换目标、项目、后端代次或锁态时撤销，要求本地重新启用。它牺牲少量便利，但不让旧按键落在新项目上。这是本包建议的安全工程默认，不是 Apple 的系统限制；主模型若改为更顺滑的交接，必须保留 cancel、neutral 和新 lease 后才能恢复的规则。

真正尚不能由资料推导出的部分保留为证据门禁：原生 iPhone Remote 是否接受这个 Mac 服务端、确切服务 TXT/session/OPACK 行为、特定 HID 设备 usage、私有多触点 ABI。不得编造一个值来填平清单，也不要把“苹果遥控器客户端能连 Apple TV”当成相反方向成立的证据。

## 每次提交必须能回答

这段代码由谁创建、谁关闭？输入来自哪个已验证来源？最后一次权限/目标复核发生在物理写入前哪里？返回值表示入队、内核接收、远端处理，还是动作最终完成？锁屏和切换目标插在任意 await 后会怎样？失败后是否还会重试？测试使用真实系统还是替身？

每个提交附具体路径、命令、退出码和原始日志。功能状态分成“源码缺口”“SDK 尚未编译”“系统/设备尚未验证”三栏。默认关闭不证明编译正确，Python 向量通过不证明 Swift 加密实现正确，成功写管道不证明命令已经执行。剩余项不能压缩成一句“等真机”。
