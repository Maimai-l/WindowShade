# 工单 P5-05：T3 端口接到真实 Fold 结果

这是第五份最需要主模型审定并在 Mac 上实施的工作。纯核和串行宿主已经交付，物理隐藏/恢复端口未实现。不要再从零寻找旧函数，按以下点接线。

## 必须阅读的确切旧文件

`App/Notch.swift`：tuck、finishTuck、restore、tuckAll；`App/ShadeController.swift`：shade、completionTokens、capturing/failed/folded 生命周期；`App/FoldCompletion.swift`：registerFoldWaiter、settleFoldWaiter(s)；`App/FoldTransaction.swift`：scheduleFoldVerification、revealOverlayAfterVerification、rollbackFoldTransaction；`WindowBrowser/WindowBrowserAppDelegate.swift`：windowBrowserBeginFold；`WindowBrowser/WindowBrowserTargetResolver.swift`：现有目标校验；`WindowShade.swift` 的 ShadeState 与 foldWaiters；`Core/ShadeModels.swift`；`Recovery/DurableShadeJournal.swift`。完整行号及哈希由 code-map 给出。

## 新结果合同，不改成随意延时

建议在既有 FoldCompletion 中扩展 typed result，而不另开无关总线。结果带 operation token、foldTransactionID、WindowKey/身份、成功/回滚/中止/未知原因和回读后的 revision。现有 Bool caller 保持兼容包装，别为了新功能破坏 EventTap/WindowBrowser。

shade 起始已经捕获 waiter tokens，应把新 waiter 与本次事务 ID 绑定。所有终态分支只结算捕获到的本次 token，不让按 windowID 批量结算误命中新 waiter。异常兜底 30 秒只说明等待期限耗尽；必须走状态回读和归属核对，不宣称动作未发生。

foldTransactionID 与 effectGeneration 不互相替代：前者描述底层一次折叠，后者描述本轮番茄钟阶段。映射记录在端口 pending table，key 为 plan.Operation.id，值是身份、beforeRevision、请求事务、waiter token。先注册等待器再发起动作，以免同步完成丢回调。

## 具体端口的执行逻辑

建议新增 `App/WS2FocusMutationAdapter.swift` 实现 WS2FocusMutationPort。只复用原 shade/unshade 与恢复日志流程，禁止直接调用系统私有隐藏器绕开原兼容策略。

收起：检查 mayCommit，使用现有 TargetResolver 的真实身份核对，确认当前无用户事务、窗口未本来已收起，读取 beforeRevision，登记待办及 waiter，最后再次 mayCommit 后发明确目标动作。操作真正完成且本次事务仍匹配，递增 mutationRevision 再回 completed。身份不符返回 userChanged/unchanged 的明确原因；结果不明返回 unknown。

恢复：检查 receipt 的完整身份和 afterRevision、当前底层 foldTransactionID 归属；在最后 unshade/restore 前再次核对。用户已展开/移动/另做一笔操作就返回 userChanged，移除本轮所有权，不恢复它的旧几何。真正恢复成功再发 completed；恢复失败且窗口依然保持本轮折叠归属时不能假写 unchanged 后无限循环，转 unknown 并阻断后续自动动作。

缺失 AX 元素/几何、NSRunningApplication/WindowKey 无法确认 processStart、系统锁态未知，都不得用 0 或当前时间补身份。当前 `hideTookEffect` 在某分支读不到几何会返回 true；强回执不能只依赖这一项。具体 SDK 回读失败需独立报告。

## 接入同一个计时宿主

`WS2AppRuntime` 已有 focusWindowEffects closure。将它绑定到唯一 WS2FocusEffectExecutor，不创建新 timer。用现有 FocusTimer run token 和阶段变化生成目标计划。先完成旧阶段 receipts，再进入新阶段；不对一个 effects 数组中的 restore/tuck 开并行 Task。

目标解析与执行分开：目标集是明确用户范围内的真实普通窗口；聊天分类可用 MagicTiling.role 的已有结果作候选，但不能称隐私防护。读取目标快照后每次物理动作仍核对实时身份和 revision。新窗口进来不要每秒重扫自动收走；同一阶段默认只操作进入阶段时的合格快照，用户另行触发才刷新。

锁定调用 executor.suspend；已提交动作的完成仍要结算；只有现有可靠锁态确认解锁后才 resumeAfterVerifiedUnlock。结束计时调用 end，等待旧 receipts 恢复结算；关闭计时卡片不等于结束。Runtime 停止与崩溃恢复仍接原 DurableShadeJournal，不能只 clear receipt 来遮住尚未恢复的窗口。

## 真机时序表

|插入事件|预期|
|---|---|
|截图未完成时结束计时|最后提交前 mayCommit 拒绝；若已有提交，迟到完成进补偿|
|专注→休息，聊天窗口也在全部集合|恢复旧归属完成后才开始新收起|
|用户手动展开/挪动后结束|不再恢复旧位置，不重新收起|
|windowID/PID 复用|完整身份不符，拒绝|
|30 秒 waiter 兜底但动作迟到|回读、标未知/补偿；不结算到新事务|
|恢复部分失败|冻结新效果，告知检查，不循环重试|
|锁中回调|不显示敏感内容、不继续自动窗口操作|
|多屏/切 Space/截图权限撤销|只处理明确范围，保留原兼容降级；未知不猜|
