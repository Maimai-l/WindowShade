# 工单 P5-03：在原生界面启动和停止一条 owned Codex 会话

## 先组合，不重做

新增 `App/WS2OwnedCodexSession.swift`、`Support/WS2DuplexProcess.swift`、`Core/WS2BoundedOutbox.swift`，替换 `App/WS2CodexApprovalHost.swift`。所有普通命令通过 host 的 beginProtocol/startThread/resumeThread/startTurn/steer/interruptTurn；Wire 只有 host 里面的一份。不要给 UI 暴露 writer 后让视图自己拼 JSON。

## 精确落点

在 `App/WS2AppRuntime.swift` 增加一个私有 ownedSession 引用以及三个本地入口：启动、向当前会话发送 typed intent、停止。AppRuntime 已持有 `clock`、`island`、weak owner。真实认证宿主是 `owner.notch.authentication`，定义在 Notch.swift，不要再创建第二个 NotchAuthenticationController。

启动方法接收一个经本地选择/审核的 executable、workingDirectory、environment 和已绑定的项目 Context。使用 WS2OwnedCodexSession 的现有构造器；scopeStillValid 读实际审阅目标与项目范围；mayOperate 读真实权限/撤销状态，不返回恒 true。currentContext 来自运行中的实际会话/project store，不读“当前鼠标指向的窗口标题”。当前 Runtime 没有 live project store，须在同一 owner 补该依赖和 revision，不造一个假项目。

先 stop 旧会话，再创建新的 connectionID；保存强引用之后调用 start。onEnd 仅在 stored connectionID 与结束对象相同才清空引用，不让旧进程迟到 EOF 清掉新会话。事件回调更新既有 AgentSessions/ConductorNotch 的 typed 状态，再调用 showSessions/showConductor。UI 打开/关闭不能反向启动或终止一个并未选中的进程。

在 `WS2AppRuntime.setLockReason` 的锁定/未知分支，和 willSleep 处理分支，先停 ownedSession 再 invalidate island。Runtime.stop 也显式 session.stop；当前新通道不靠 deinit 回收，漏掉此调用会留下源/管道生命周期问题。通知解除只是触发重新核对，不自动重启助手。

## 所有 scope 回调必须这样判定

scopeStillValid：审阅 provider/connection/thread/turn/project/cwd/command/environment 范围仍匹配已显示的完整目标；UI 正在审阅的是同一 request；锁态已知解锁；该项目没被删除或更换；授权操作类型仍是已支持的一次性普通命令。

mayOperate：本地功能还启用、项目授权还有效、应用仍持有当前 owned session、进程代次没有被撤销。若范围变化不反映在 WS2.Context，必须增加 revision 或让 mayOperate 立刻失效。不能把上次检查结果缓存到下次 write。

当前进程传输只验证绝对可执行路径和基本参数，不验证代码签名与项目政策。产品入口须在启动前完成这些判定并绑定，不能因为 Foundation Process 能运行就视为安全选择。

## 真正执行的验收顺序

第一阶段不发允许消息。用用户明确选定的隔离测试目录和 CLI，完成初始化、列表、thread 创建、普通无副作用请求、完成、中断、停止、退出。记录 CLI 实际版本并与固定 schema 比较；若版本不同先生成差异记录，不猜最新 schema 可以向后兼容。

第二阶段才使用本地演示目录中的无害命令请求。UI 完整显示目标；按真实 Touch ID/用户确认流程消费现有授权账；真实 emit 一次 accept；运行日志只记录 request ID 的脱敏摘要、阶段和成功/错误，不记录命令全文。取消、授权过期、锁中回调、更换项目、过时 turn、断管都不得发允许消息。

第三阶段在“消费 → 准入 → 真正 write → 后端处理 → 完成通知”之间逐点注入失败。对已写或结果不明的请求显示“执行状态尚未确认，请查看会话”，不主动重试。重新连上后只恢复用户选定 thread 的观察/新操作；旧批准永远失效。

## 固定帧处理

CodexWire 出站帧已含 LF，新 host 必须调用 admitWireFrames。入站通道回调给不含 LF 的单条内容，WS2OwnedCodexSession 再加一次 LF 交 Wire。字符串内合法 JSON `\n` 是转义字节，不等于原始分隔 LF。数字和字符串 ID 保留原类型。

stdout 必须全部是协议；stderr 当前丢弃。插件或 wrapper 在 stdout 打 banner 属于协议错误，不跳过任意非 JSON 行以“增强兼容”。最大消息/队列限制超出就关闭，并明确报错。不要自动退回 shell 或另一助手协议。

交回材料：实际构建命令、真实 CLI 版本、初始化和状态转换日志、分层测试、主应用锁态回归、当前不可支持的审批种类。没有设备或钥匙串依赖，应该优先完成这条路径，而非等待整包其他模块全部成熟。
