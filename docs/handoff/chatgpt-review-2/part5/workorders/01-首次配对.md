# 工单 P5-01：首次配对内层与依赖准入

## 本包已交付的范围

`prototype/Support/WS2PairSetupServer.swift` 已实现 M1/M3/M5 顺序、连接占用、输入上限、错误清理、M6 之前保存 peer。`WS2PairSetupCrypto.swift` 已有 M5 验签和 M6 加密候选。`optional-srp/Sources/WS2SRPAdapter/WS2SRPAdapter.swift` 是绑定已审查外部提交的适配器，不在应用 target。当前没有生产 SRP 实例工厂，也没有原生 Remote 成功记录。

## 按这个顺序实施

1. 不改 App，运行 `tools/prepare-srp-probe.py --out /新的外部目录/srp-probe`。在有网 Mac 中 `swift package resolve`，保存真实 Package.resolved。执行生成 README 的严格构建命令，核对 SRP product/API/CryptoKit 类型关系，不往 App 增添假的 protocol stub。
2. 审核 resolved 的所有依赖、许可证和 BigNum 后端。记录二进制目标、架构、最低系统和动态库来源。依赖构建脚本不得顺便改生产 app 的签名。审核未完成前适配器继续留隔离目录。
3. 用独立参考客户端对 Swift server adapter 互测。必须覆盖前导零 A/B/S、错误 PIN、A=0/A=N/超长 A、错误 proof、原始 K 长度。把参考端随机数做成测试可注入，生产构造器不加固定 seed 入口。Swift adapter 的 key 与 serverProof 都要逐字节比较。当前 Python 测试尚未执行这一步。
4. 运行 `tests/run-mac-crypto.sh /候选repo`。这是固定 K 的 CryptoKit 分层测试，不能代替第 3 步。再把真实 adapter 与该层接上做完整内层 M1–M6。
5. 主 App 只保留一个 PeerRepository 和 PairingAdmission。本地“开始配对”入口调用 openByLocalUser；网络 M1 仅 claim 已打开窗口，不能自身创建 PIN。每条连接创建一个 server 和一个 crypto engine，连接取消必调 server.cancel。
6. 完成 local re-pair 工作项后，才准入重复标识的恢复流程。当前 enroll 会拒绝已有标识，包括被撤销的墓碑。不能为了演示成功删除冲突 guard。

## 实例归属和调用契约

```text
WS2AppRuntime（建议新增唯一配对 owner）
  ├─ WS2KeychainPeerStorage：自有 service/account，不同步
  ├─ WS2PeerRepository：load/provision 由明确本地流程选择
  ├─ WS2PairingAdmission：唯一全局 PIN 窗与失败计数
  └─ 每个 accepted connection
       ├─ 独立 SRP adapter/临时密钥
       ├─ WS2PairSetupCrypto（读取同一份持久本机身份）
       └─ WS2PairSetupServer（同一 connectionID）
```

公开给 UI 的数据只包含 PIN 窗是否存在、剩余秒数、失败/冷却状态；不要把 Snapshot 全部挂到可打印的 view model，其中有私钥 seed。当前 Admission 没有完整可观察 UI 状态 API，实施者应增加只读 PairingPresentation，不重新推断计时、也不导出秘密字段。

新增本地状态 API 的要求：配对窗口 token 单独生成；UI 重开返回同一窗口事实，不自动重置；结束只关闭与 token 相同的 PIN 界面；冷却用单调截止驱动更新；关闭 PIN 页是否保留窗口由明确取消动作决定，取消不能抹掉失败预算。

## UI 文案定稿

本地操作标题“配对遥控设备”，说明“在你正在连接的设备上输入此码。请勿发送给其他人。”显示恰好四位并保留 0。错误码不回显 proof、公钥全文或 PIN。达到上限：“尝试次数过多，5 分钟后可重新配对。”窗口自然到期：“配对码已过期，请在此 Mac 上重新开始。”保存失败：“未能保存设备，配对没有完成。”M6 发送结果不明：“设备信息已保存，尚未确认对端收到；请重新连接或在此处处理未完成配对。”

## 故障注入和停止线

M1 占用后第二连接不得偷走 PIN 窗；M3 计算期间过期不得返回 M4；M5 合法 AEAD 但签名错误必须拒绝；保存异常不发 M6；保存成功而网络失败不得删掉已提交 peer 装作没发生；重启看到未完成标记冷却；取消三次连接不能获得无限尝试；同标识异公钥不覆盖。

交付要求：真实依赖锁、Swift 编译输出、独立互测 transcript 的非秘密字段及摘要、人工向量结果、失败状态 UI。原生 Remote 互操作需要额外设备证据，未取得就写未验证，不用内层测试替代。
