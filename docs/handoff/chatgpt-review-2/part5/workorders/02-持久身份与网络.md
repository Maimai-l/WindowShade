# 工单 P5-02：Keychain、监听所有者与协议会话

## 已有与新增文件

新增 WS2PeerRepository、WS2KeychainPeerStorage、WS2CompanionTCPTransport；复用第四份 WS2CompanionFrame、Pair-Verify/会话密码学与 RemoteSessionGate。它们仍缺一个拥有 NWListener、连接集合和协议状态的唯一 owner，以及受限 OPACK/session codec。该 owner 是待写生产代码，不是运行探针就会出现。

## 储存先验收，监听最后开放

先在同一真实 App 签名下创建专用测试 service，验证不存在、已存在、锁中、读写失败、损坏、重复创建、旧证书权限差异；测试不接触生产 service。禁止使用 sudo 或把系统钥匙串安全属性改宽来消除报错。保存一份 OSStatus 到原因的有限映射，未知码只显示存储不可用，不进行“清空后再试”。

建议新增 `App/WS2RemoteRuntime.swift`：由 AppRuntime 强持有；构造时仅配置，不开始广播。用户本地启用且 storage load 成功后，才在兼容性被批准的 profile 下启动 listener。disable/stop 顺序为停止接收新连接、撤销输入 lease、取消 PIN 窗、关闭连接、清理临时密钥，最后停止发现。读写错误调用同一个 stop 网络路径，不把异常吞掉后继续在线。

每个连接对象带 transport.connectionID、peer identifier/key/revision、protocol phase、protocol deadline 和临时验证状态。只在真实 Pair-Verify 成功后填 verified peer，且每条输入到达时再问 repository.current。current 只是存储查询，不能由任何 plain 字段直接制造已验证连接。

## 外层 codec 实施合同

首次实现先使用事实已确认的 message/profile；未知 tag、方法、能力不准默认允许。OPACK 限制建议：最大嵌套 8、容器最多 128 项、字符串和 data 最长 16 KiB、总 payload 不超过既有 64 KiB；这是本包工程限额，需在互操作时记录合法超限证据才调大。引用表数量也要有界，未知引用与重复键拒绝。不要让“忽略未知字段”变成重复 key 覆盖鉴权字段。

配对阶段仅将外层 `_pd` 中已限长的 TLV 交内层 server；响应包重新按实际编码长度构造头。状态转换完成才 setProtocolDeadline；不能每次收到数据就续期。frame type 与 session method 的具体允许表写入 profile 数据和测试，不写散落魔数。没有原生来源证明的服务 TXT/profile 仍不注册到生产 Bonjour。

listener 总上限建议 4 条未认证连接、2 条已认证连接，同时只允许 1 个配对 claim。超额立即 cancel，不创建昂贵 SRP 对象。总上限是新增 owner 应实现的要求，当前单 TCP transport 不含这一功能。awaitingVerification 的 peer 允许做 Pair-Verify，但不得仅因已登记就接收输入。

## 明确处理三个恢复场景

A：peer 保存失败。停止网络、保留旧快照，不发成功；用户解锁钥匙串后显式重试，不自动重建身份。

B：peer 保存成功但 M6 丢失。UI 留 pending 记录；允许现有对端通过新连接验证。需重新配对时进入本地确认流程，不能删墓碑或从本轮临时共享密钥恢复会话。

C：撤销保存失败。当前进程先停用远端，再显示“撤销未保存”。不得报告已永久撤销。恢复监听前先成功保存撤销；下次重启可能仍读到旧状态，这一风险必须由恢复入口解决，不能靠内存 blocked 掩盖。

## 重新配对与容量管理仍需写的事务

建议新增本地 replacement token，绑定旧 identifier、旧 peer revision、当前 PIN 窗和目的。M5 验签后使用 token 对比旧状态，再以新的全局 revision 替换该墓碑。token 单次消费，窗口取消/过期/锁屏立即废止。不能提供一个公网传入 `replace=true` 的 enroll 参数。

清理墓碑必须先撤销所有引用旧 revision 的连接，再持久修改；revision 永不因删除重设为 1。容量满时停止配对并提示在本机管理设备，不后台随机剔除一台。当前 API 没实现 replacement/token/清理，主模型实现时应扩展同一个 repository，而非另存一份 UserDefaults 名单。

## 验收

单字节拆包、连续多帧、错长度/超长、空数据+EOF、握手闲置、同连接重入、缓慢读取、send error、过期后回调、撤销后旧 peer 输入都要测。网络测试 separate from 密码学；native Remote 另留系统 build 与握手阶段记录。TCP ready 和 contentProcessed 只能分别记为“传输可用”“本地发送已处理”，不记认证或执行成功。
