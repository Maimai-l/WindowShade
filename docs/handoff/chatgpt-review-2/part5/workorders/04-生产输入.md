# 工单 P5-04：一个 GameController 所有者和一个实际 sink

## 已有代码

替换 `App/WS2GameControllerBridge.swift`，新增 `App/WS2DeviceActionHost.swift`、`Core/WS2SemanticInputRouter.swift`。保留现有 Core/WS2DeviceInputGate 与 GamepadMapping。新增 host 仍需由 Runtime 持有，并缺原生 view/store 的具体 WS2DeviceActionSink 实现；这两项是源码工作。

## 第一条闭环只做列表导航

在原 AppKit 设置页开启此功能时创建/启动唯一 host。devicesChanged 更新真实列表，Enable 按 attachment UUID 调 enable；关闭功能调 stop。不要在每次 view render 都 new 一个 bridge，不能仅在 view 消失时释放引用而不 stop。

新增建议文件 `App/WS2DeviceSelectionSink.swift`，实现现有 WS2DeviceActionSink 协议。持有可弱引用的当前原生选择控制器和被 Runtime 持有的 selection revision。previous/next 调它的有界选择动作；cancel 只关 lease 所属交互；openSelection 调当前行的本地打开动作。ready 需要视图仍在有效宿主且支持这些动作。motionReady 在真实桌面端口完成前固定 false，这里 false 是能力未提供，不是假成功。

具体旧界面入口为 WS2AgentSessionView、WS2ConductorView 和 WS2IslandCoordinator。现有视图若没有键盘式 selectPrevious/selectNext，应在原视图内部新增方法并以同一数据源更新可视选择；不要模拟鼠标点击坐标，也不让手柄直接拿会话数组下标调用进程接口。

liveContext 由当前 lease 的实际 owner 构造，必须包含 attachment/lease/domain/targetRevision/backendEpoch。列表刷新若只是文字变化可保留 revision；行重排、目标替换、项目变化和后端重启必须更新相应 revision，并在发布新上下文之前调用 environmentChanged。frontIsGameOrUnknown 不能恒 false；未知状态按拒绝处理。

## 验收可以拆得很清楚

纯路由测试已经覆盖票据和上下文，但没有跑 GameController。Mac 先编译新增 Environment 初始化参数所有调用点，核对 handlerQueue 确实 main；然后用真实设备做：未启用不收动作、初次已按下按钮不触发、按下后换目标再松开、插拔同型号、关闭设置后回调、进入游戏/未知前台、锁屏、权限撤销、第二设备启用。

期望：每次最多一个语义动作，旧 press 无法作用新 lease；关闭后没有残留 movement task；背景监听状态按原持有值恢复；若其他组件也写该全局属性，应建立共享所有者，不能互相抢写。

## 再做桌面和指挥

桌面 motion sink 必须调用真实受控窗口动作，包含身份/几何/权限和节流。执行失败返回 false，由 host 禁用附件。不得执行“先返回 true，随后异步另找一个窗口”的方式；异步端口需先扩展 ticket 完成合同，把目标固定到提交时刻。

指挥域只从明确动作生成现有 typed intent。选模型/effort 的选项来源是真实后端列表；演奏式手势不能把任意按钮节奏解释成最高权限批准。运行中 interrupt 要绑定当前 turn；提交草稿必须已有完整本地草稿和本轮明确意图，A 的普通打开选择语义不自动变成提交。

HID、hidutil、CGEventTap、私有多触点仍走旧探针和 docs/04 的独立门禁。它们不是本次这个 host 的实际生产来源，不能改功能开关把未实现的桥认作已连上。
