## 网络调用顺序

read → frame decoder → 阶段/类型 gate → OPACK 提取 `_pd` → answerM1/M3 → 有界写应答；只有 M4 成功排到该连接的 FIFO 前面、连接仍当前，才安装 protected record session。加密后的 payload 再进入 OPACK 和会话路由。连接关闭先 revoke epoch/cancel inputs，后清理 buffers/keys。

建立 peer 时不可使用数据包中临时声明的 client ID 直接查到自己刚塞入的一条记录；必须是 Pair-Setup 完成后可信提交的记录。第一次配对未实现之前，生产 lookup 不允许返回测试公钥。

## 准入测试

|ID|输入/场景|必须看到|
|---|---|---|
|P4-D5-01|Python 与 CryptoKit 同一固定测试材料|共享秘密、HKDF、签名向量相符|

|P4-D5-06|取消首次配对、写 Keychain 失败|旧配对不损坏，新配对不启用|
|P4-D5-07|握手中睡眠/显示器移除/退出|PIN/临时状态清理，不能晚回调登记|
|P4-D5-08|原生 Remote 实际连接|附系统 build 和协议观察；不得只交自制客户端结果|

本份 decoder 上限64KiB、单次批量输入256KiB、最多128帧，Pair-Verify10秒。网络实现不可悄悄调大；确有必要时先给实际合法样本，单独改决定和边界测试。
