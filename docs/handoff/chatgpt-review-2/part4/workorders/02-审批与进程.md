## 真实 caller 必须提供的值

创建 host 时注入同一个 owned 进程连接 UUID、当前 CodexWire、runtime.clock、runtime.island、原 notch.authentication，以及以下四个真实 callback：

|参数|应该从哪里来|禁止的替代|
|---|---|---|
|currentContext|当前 owned 会话登记表的 provider/session/project/epoch|从 UI 标签拼一个固定 context|
|scopeStillValid|此进程已知项目根、当前真实 cwd/thread/turn、允许的本地环境|`{ _ in true }` 或仅 hasPrefix 路径判断|
|deliver|一个按连接和截止约束的单写者|无上限 async 写队列，或直接返回 true|
|closeTransport|幂等关闭此 owned 连接/子进程通道，回调不关闭其他会话|终止所有名字含 codex 的进程|

目录比较要规范化到真实目录身份并防符号链接/路径前缀歧义；`/work/a` 不能匹配 `/work/ab`。审批快照应绑定当时认可的路径，实际发送前再次确认根/会话代次。文件内容审批还不准入，不能因为路径规范化了就跳过 diff。

## 事件接线

owned stdout bytes → host.receive；onEvent 更新真实 AgentSessions/Conductor 状态，不用完成动画提前推断成功。需要弹出哪条审批由用户点击/当前会话策略选择 pending id → present(id)。每个请求独立截止，使用截止任务唤醒 host.tick；不要为了8条pending一直跑全局1毫秒轮询。超时、进程退出、锁屏、连接epoch变化时调用 host.invalidate，立即拆掉它自己持有的审阅。

当前 host 没有管理一般 turn/start 命令的公共总门面，主模型仍需让该连接的其他命令也经过同一个 CodexWire/单写者；不允许再保留另一个 mutable Wire 并行发送，这会使 request id 和 pending 表分裂。可以在 owner 中统一组合，或为 host 增加有限的 typed 操作方法，但不加 arbitrary JSON passthrough。
