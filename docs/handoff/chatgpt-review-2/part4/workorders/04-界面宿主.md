# 共享岛、会话和指挥视图的接线施工单

先确认候选中的 AppDelegate.ws2Runtime 只构造一次。WS2IslandCoordinator 替换“每个功能自己控制 NotchPanel”的新增代码，但不拆现有窗口管理系统。

## 完整候选文件

App/WS2IslandCoordinator、InteractionCoordinator、Notch、NotchAuthentication、WS2AppRuntime、WS2AgentSessionView、WS2ConductorView、WS2CodexApprovalHost、FocusTimerCard。这些文件必须作为同一增量评审，不能只拷一个新的高卡片而不拷父窗口高度更新。

FILE-MAP 提供当前行号与符号。所有旧同名文件保留一份；reference/ 和前份 packages/ 中的旧版不得再被 build.sh 收集。进入新的 context 时先撤销旧租约再换UI，不能等动画完才清权限。

## 实际接线任务

|调用位置|要做的事|不要做|
|---|---|---|
|App 初始化|确保新功能首次使用前 runtime/island 和 auth hooks 存在|等打开番茄钟才给审批安装安全hooks|
|AgentSessions 更新|store发布快照；打开的同一个view差量render|每秒重开window/抢焦点|
|用户选择会话|使用完整WS2.Context切换，清旧输入/旧cost确认|按UI标题或目录匹配|
|Conductor reducer输出|同一view render相应状态；Action交回reducer|按钮直接CLI写字符串或全局Return|
|sendDraft(text)|将编辑后的实际文本写入draft revision，重新计算cost binding|发送旧render快照|
|显示器改变|coordinator取消旧租约，必要时让用户重新打开|把未完成审批静默转移到另一屏|
|普通关闭|只撤销本view，不结束计时/杀后端|取消所有runtime任务|
|授权转场|清review自己的取消回调后取得原生认证租约|普通活动承载最高层allow按钮|

## 先解决的实际UI缺口

会话/指挥 view 已有展示入口，但 live store 订阅和普通用户入口需要接到现有菜单/活动，不要只在 DEBUG 下能打开。指挥草稿目前仍用 NSTextField，长多行草稿建议在同一 view 换成原生多行编辑区并保持完整UTF8上限；先做可编辑/可滚动和实际提交一致，再做动画。轨迹 render 依赖bounds，需在最终layout时用最新points重算，不能让首次零bounds画成一条线。

这些属于视图施工缺口，不称作“只剩审美调优”。全部权限/审批内容先做到可读、可取消、不会错位，随后再检查 Classic/Liquid Glass。不要为了现代外观修改命令审阅的纯文本安全规则。

## 验收

物理刘海/虚拟岛、两屏、拔屏、125%/200%缩放、菜单栏自动隐藏、Reduce Motion/透明度、键盘与VoiceOver分别走一次。选择超过一屏的会话时仍能滚动到最后一行；600点命令卡显示不下时不得隐藏拒绝或确认。审批出现前的held键不能触发确认。

重点回归既有“安全设置确认”“登记设备密钥”“原生Touch ID取消/失败/超时”，证明新hooks没有让原路径失效。测试需加载实际SDK并运行原授权实现；本包 Linux parse 结果不替代这一步。
