# 主模型可以直接使用的判断

**第四份是否把剩下的全做完了？** 没有。完整候选增量、决定表和测试已经交付，但首次配对、真实writer、若干输入来源和store调用者仍缺代码；不是都归到硬件验收。用REMAINING逐项判断。

**这份到底替执行模型省了什么？** 固定了Mac服务端方向、身份与动作权限分离、哪些审批准入、字段与ID怎样绑定、哪一层拥有view/输入/计时器、设置何时生效、哪个窗口能恢复、怎样处理断线结果未知。文件路径、现有入口、精确变更和测试条件都已经给出，不必再让执行模型凭印象选技术路线。

**现在最值得先做什么？** 用Mac `build.sh --check` 验收合成候选，再完成番茄钟可见性与同岛UI，然后接真实owned进程writer。原生Remote配对的未知不应阻塞这些本地闭环。

**可否把Pair-Verify的lookup指向用户输入的设备名？** 不可。它必须返回之前完成安全登记的公钥记录。临时消息带来的名字/公钥不能自产自证。没有Pair-Setup时生产来源保持不可用。

**参考库已经能连Apple TV，为什么不直接用？** 方向不同，许可证和安全实现也未整库准入；已读M6路径还存在没有验证身份签名的缺口。这里只引用固定版本协议观察。独立实现不等于协议互操作已经得到证实。

**没有Touch ID的Mac怎么办？** 沿用原授权服务不可用状态和原工具自己的审批渠道，不加本包自造的密码输入替代。明确不可用优于一个外观相同但没有原授权保证的按钮。另做认证方式属于主模型安全设计，不由执行模型临时填一个Bool。

**为什么没有全会话允许？** 单次命令的审阅不足以让用户理解后续未知动作。固定schema允许的枚举比本版产品准入宽；只采用accept/decline是本轮决定，不是协议缺功能。

**观察到会话就能停止它吗？** 不能。observed没有owned进程句柄和可验证控制通道，UI不显示停止。按PID名称遍历终止可能伤及别的会话。

**手柄复选框为什么断线后又关了？** attachment只代表这次实际连接。相同名称/型号不能证明还是此前许可的那一只，也不能证明仍是同一位用户。持久许可需要另一套稳定身份设计，本版不猜。

**为什么触发器不是退出就无条件清零？** 只能清本工具确实施加的反馈。清掉我们从未拥有的游戏反馈也是一种干扰。持有过反馈时，切域、禁用、锁屏、退出都要清理。

**可以用鼠标continuous字段区分设备吗？** 不足以作为唯一证据。未知来源保持原样；触控板惯性和外部鼠标要实际分开观察。不能把平滑算法通过当作来源桥通过。

**番茄钟收聊天的默认true现在有什么意义？** 保存下一轮的用户偏好，但未接T3时不会移动窗口，控件明确禁用并说明。真正接入才启用；不能赋空closure让它看起来可用。

**那一轮中途关设置，是否马上恢复？** 本版定为下一轮生效，不在设置回调中突然动窗口。当前轮结束仍承担原收据的恢复义务；用户手动改变过的窗口例外。

**要不要请执行模型把文件拆得更碎？** 不要为抽象而再建平行框架。只拆真正有单一所有权和可测边界的层：纯reducer、Mac adapter、真实caller、展示。已有Contract/Clock/Context/Token保持一份。

**主模型剩下真正要拍板什么？** 对上述候选合入、安全影响和真实T3执行器进行审定；批准经过许可证及向量审查的SRP依赖进入构建；对非公开协议/设备ABI的实证决定准入。不是再选热键默认、再发明审批期限或猜Nonce字节序。
