# 先执行什么，哪些问题已经替你定了

你接手的是 WindowShade 2 第四份增量。保留用户现有的 AppKit、共享合同、授权账、单一刘海宿主和前面三份成果。按下面顺序直接在隔离工作区落实。不要重做菜单、从零换框架、生成一套平行模型，或把本包的说明再改写成第五份说明来替代接线。

## 第一步：建立可比较的候选

读取 README、manifest、REMAINING；确认当前 HEAD 和用户未提交改动。已有第三份干净候选时执行 tools/stage.py。实际工作区更晚时，逐文件三方比对：本包 baseSHA、工作区版本、本包新文件。冲突的两个正确改动都保留，冲突原因写入接线记录，不覆盖原工作区来躲开合并。

运行本包三条本地测试，再用 Mac SDK 做一次整应用 `--check`。先修编译和目标成员关系，后接硬件。Swift 并发报错不要用到处添加 `@unchecked Sendable`、去掉 warnings-as-errors 或关闭 Swift 6 来消音。已有 `MainActor.assumeIsolated` 的回调必须核查其 handlerQueue/通知队列确实是 main；只有语法 parse 的文件仍可能有 SDK 错误。

## 第二步：先交付可见的番茄钟闭环

执行 `workorders/05-番茄钟.md`。两档预设固定 25/5、50/10；修改预设只影响下一轮；工具入口一按开始，运行中重开不重置；休息结束空闲；快捷键默认空。禁止增加任务输入框、统计数据库或强制安装系统快捷指令。

当前 T3 尚无生产效果适配器，默认开关的偏好值可以存在，UI 必须标明当前不移动窗口。真正完成效果适配器后再启用该控件，恢复窗口前重查所有权。单独设置 `focusWindowEffects = { _ in }` 不叫适配器就绪。

## 第三步：把已有 UI 和真实状态接起来

执行 `workorders/04-界面宿主.md`。一套 WS2AppRuntime、一套 WS2IslandCoordinator；所有具体视图由其持有。不要在一秒 tick 中重建视图；用当前活动 store 发布差量。会话和指挥入口已提供展示方法，但真实 store 的订阅和 typed intent 路由还要接。关 UI 不代表结束计时，断 backend 不得关别的 feature 后来打开的 UI。

## 第四步：接拥有生命周期的助手进程

执行 `workorders/02-审批与进程.md`。先让 owned Codex 的 initialize、model/list、thread/start/resume、turn/start、完成/中断生命周期真实通，再接审批。V1 只支持完整普通命令的一次性批准。审批摘要、窗口标题、工具自称低风险都不能替代实际命令/cwd/context。文件审批没有可信 diff 时拒绝；owned app-server 不能假定另一处有一个原生弹窗会接棒。

只有 WS2CodexApprovalHost 可以把真实 AuthorizationService.consume 的成功接到 accept。序列化器不是授权器。严格实现 deliver 的截止、连接代次和锁态复核；断线/部分写入后不重试允许消息。未完成真实 writer 前，不把候选 host 接入生产允许路径。

## 第五步：最后开放设备来源

执行 `workorders/03-输入设备.md` 和 `workorders/01-配对与传输.md`。手柄每次附件默认关闭；同型号不继承旧许可；指挥输入只产生语义意图；审批期间不收手柄确认。蓝牙名称、RSSI、出现过的设备地址都不能直接兑换 verified peer。

D5 的 Mac 是协议服务端。不能把控制 Apple TV 的客户端库接上去后宣布 iPhone Remote 能控制 Mac。Pair-Verify 已有候选代码，首次 Pair-Setup 仍需要实现；它们的验收必须分开。不能自造手机 App、把 PIN 做一次哈希当 PAKE，或通过字符串匹配把某个设备写成已认证。

## 已定默认，不用再请模型选一遍

本包明确指定了 30 秒命令审阅期限、10 秒 Pair-Verify 期限、120 秒普通交互租约上限、本地帧上限 64 KiB、审批队列 8 条、同一 input handler 所有者、断线不自动重发、无默认热键、每设备重新启用等。它们是保守工程决策，不是测量值；对应来源和调参条件在各决定表中。真正的新问题是设备事实和主模型负责的 T3/锁后端，不是让执行模型反复发明这些默认。

每个工作包交回：改了哪些路径；实际跑了什么命令及退出码；输入/输出样本；还缺哪个具体调用者或证据；是否改了数据去向。失败要保留原输出，再修复重跑。生产代码缺口、SDK 尚未编译、硬件尚未验证必须使用三个不同的状态。不要发布 1.0.16 或更改更新源。
