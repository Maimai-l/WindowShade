# 第四部分的已定决策与交接顺序

本文的“已定”是第四份候选的实施基线，不代替主模型合入审查。执行模型不必自行在多个架构间兜圈；遇到真实反证时保留证据再修订这一行。不得把“建议默认”写成设备实测。

## 依赖关系和谁拥有状态

```text
AppDelegate.ws2Runtime
  ├─一个 FocusTimerHost → 一份 FocusTimer → 现有活动 store / 卡片 / 菜单
  └─一个 WS2IslandCoordinator → 原 NotchPanel / 原 NotchAuthenticationController

owned CLI transport → CodexWire → WS2CodexApprovalHost
  → 完整 review → 同一岛的审阅卡 → 原生 Touch ID → AuthorizationService.consume
  → 当前连接有截止的 writer → 原 owned CLI

设备回调 → 当前 attachment / 输入域门控 → typed intent
  → ConductorSession 或经过授权的桌面动作适配器
  （不直接抵达 accept、shell 或密码输入）

首次 Pair-Setup [仍缺] → 已登记 peer store [仍缺]
  → 本份 Pair-Verify → 本份 encrypted record
  → OPACK/session/event adapter [仍缺] → typed intent
```

普通 UI 租约、已认证设备、助手审批票是三个独立事实，任何两个都不能互相替代。输入信号的 timestamp 在本机入口赋值；网络对端自报时间不能给本机授权延期。

## 执行节奏和失败处理

先验收单 host 番茄钟，再验收同岛审阅与真实授权账，再接 owned CLI writer，随后开放单个手柄，最后开放网络配对。这个顺序允许每一步产生可看见的成果，也把最难的非公开协议留在没有生产用户数据的测试面上。

编译失败时先以第一个错误为入口，查看 FILE-MAP 的依赖。Mac API 名字错了，只改对应桥并补 SDK 检查；不要修改纯逻辑合同来迎合一个拼错的属性。新图层盖住旧内容时先查 view 所有权、几何和约束；不要改整个岛的弹簧系统。CLI 超时先保留 connection/thread/turn/请求号的脱敏关系，不重新发送用户动作来“试试看”。
