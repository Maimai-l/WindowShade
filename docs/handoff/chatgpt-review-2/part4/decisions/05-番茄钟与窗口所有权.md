# T1 / T2 / T4：计时、视图和窗口效果分工固定下来

## 本轮修复的状态问题

旧候选在构造宿主时固定时长，设置没有驱动到实际模型。简单把 preset 改成可变也不够：假如第 24 分钟把 25/5 改成 50/10，当前截止、休息时长、进度圆环会出现相互冲突。另一个更危险的问题是中途关闭收起聊天开关，会丢掉这轮之前已经收起的窗口的恢复义务。

本份把设置分成 pending 和 active。pending 是下一轮采用的偏好；点击 start 时复制 activePreset 和 activeTuckChat；这一轮的专注、休息、进度与恢复都使用 active，直到回到 idle。configure 不重置 runID/deadline/day/ownership，也不发窗口效果。用户改设置不会突然移动窗口。

## 时钟和刷新不能揉成一个每秒减一的数字

模型使用当前进程的连续单调时间决定截止；日期只用来确定今天的计数归属。不要拿网络 timestamp 或用户调钟后的 Date 差值当这轮剩余时长。Task 的唤醒是提醒宿主重采当前时间，丢一次 tick 不能让计时慢一秒。

展开时秒级刷新，紧凑时按下一分钟边界，最后一分钟显示秒；隐藏时只等下一阶段截止，暂停没有周期唤醒。Host 自己调度下次 wake，卡片、菜单、负一屏都不能各建 Timer。进度圆环用当前阶段真实总长计算，不用修改后的 pendingPreset。Core Animation 负责中间画面，不让 Swift 每帧扣数。

当前 runtime 在卡片关闭后回 compact，但还需要把整个刘海/活动隐藏状态接到 host.presentation=.hidden；不然“模型支持隐藏少唤醒”不等于整 App 已省电。disabled 时如何结束/保留一轮须沿用主模型现有功能设置语义；本包不擅自杀掉用户当前轮次，未接部分列入 T4 剩余表。

## 快捷键与设置已经落到哪些位置

GlobalShortcuts 新增 focusTimer，沿用旧 ID1–35，使用 id36；factory binding 为 nil。EventTap 的热键入口调用同一 runtime.toggleFocus；Preferences 的 recorderRow 允许用户自己录制。开始、暂停、继续都走同一个 host。不要给默认 Option/Command 某个组合，避免抢现有工具的热键。

当前已有设置页没有单独完整的 Live Activities 新页，本份把两项控件放进第三份已有的 WS2SupplementPane，并明确其归属。不得再造另一份存储键。主模型后续把布局移到最终活动分组时，移动同一组件即可，不同时保留两个互相不刷新的副本。

保存键为 `WS2.focus.preset`（只接受 25/5 或 50/10，非法值回 25/5）和 `WS2.focus.tuckChat`（缺失时按委托默认 true）。正在运行的设置不重建 host。T3 未接时收窗口开关禁用并说明当前仅计时，不能让用户勾选后误以为窗口真的改变。

工具入口已在棚架/负一屏的工具数组加入番茄钟，布局按 tools.count 计算，避免第五个按钮仍挤进固定四等分。**独立的负一屏 idle 番茄钟卡片尚未完成**；不能把工具按钮冒充所有设计稿都已实现。它后续仍只能读/操作这一个 host。

## T3 为什么不能直接“找聊天 App 全部收起”

委托把实际窗口效果归主模型，是因为窗口管理已有复杂的前后关系、动画、恢复和私有窗口清单。新增计时器如果独立调用 AX 去收放，会与卷帘、置顶、侧拉、刘海产生两套相互覆盖的历史。用户稍微手动拖一下，计时结束又强行放回旧位置，就是典型所有权错误。

本份只补 `WS2FocusWindowOwnership` 的 receipt 机制。Identity 包括 pid、processStart、windowID、windowGeneration，Receipt 包括 runID、effectGeneration、改变前后 revision。窗口动作真正完成后才能 record；仅仅发出 AX 请求不记录成功。恢复前 take 要核对当前 live receipt，消费一次后不能重复恢复。

后续实际适配器的操作顺序应是：从共享隐私清单取得候选；确认目标进程/窗口仍是原实例；保存原布局；调用既有窗口执行器；完成回调再次确认 runID/ownership；成功才记 receipt。结束时逐项重采当前状态，仅恢复仍由这轮拥有的项目。用户关闭、手动调整、被其他功能接管，均撤销该项资格。

这是收据的核对合同，不是对系统窗口状态的原子事务。读 live revision 和实际写窗口之间仍可能发生竞争。真正 executor 必须在它自己的串行所有者内完成复核与变更，并在异步完成回调再次核对；无法建立这个边界时宁可跳过某窗口，不抢用户的新操作。上一次 pid/windowID 组合相同但进程重启了，仍是另一个窗口。

## 待接效果不能用空实现骗过可用性

`focusWindowEffects` 目前是 nil，UI 据此禁用窗口效果控件。给它赋一个忽略参数的 closure，会让 UI 误以为接好了，明确禁止。接线时应换为真实 executor 的 adapter，并补覆盖式测试：成功收起、部分失败、窗口关闭、手动拖动、别的工具改变、进程重启、计时结束与回调同刻、锁屏及 shutdown。

提示音也不要在 callback 中随意播放。效果列表的 `.playStart/.playEnd` 类事件（以实际枚举为准）只在模型明确要求时执行；睡眠恢复的晚事件不补播。声音文件授权、实际音量和减少干扰的设置仍遵循主模型现有约束。不能为了让样机看起来活泼就增加每分钟提醒。

## 验收时拍什么、量什么

同屏录下设置改为50/10而当前25分钟的截止不变，结束后的下一轮采用50/10；录下手动暂停后锁/解锁仍暂停；录下切到休息后睡眠超过期限回 idle；录下用户手动移过的窗口不被强行恢复。再用 Instruments/系统工具分别量空闲、隐藏、紧凑、展开和暂停的 wakeups/CPU，记录设备和系统 build，不写固定“省电百分比”。
