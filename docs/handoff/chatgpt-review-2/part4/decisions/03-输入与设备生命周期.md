# I3 / I5 / I8：输入来源的拥有关系比映射表更容易出错

## 这一份接到哪一层

`WS2DeviceInputGate` 是纯状态机；`WS2HIDButtonMap` 只是精确 usage 解码；`WS2GameControllerBridge` 则真正写了公开 GameController 的枚举、连接通知、输入回调、启停和反馈归零候选。最后一个仍未在 Mac SDK 编译，也未实例化接到生产设备设置页和动作 sink。不要把这三个不同层级写成“所有输入桥已接完”。

每个 GCController 对象进入列表时新建 UUID attachment。标签是 vendorName，不能据此认证用户，也不能拿两个同名手柄共用状态。断开后即使同一个实体回来，也需要新的启用操作。本版故意不持久化硬件的“始终允许”；将来确有稳定身份和产品需求时另行设计，不把 UUID 跨进程写入设置当永久设备号。

## 公开手柄桥的固定行为

start 只在用户打开设备功能时调用，不在每次 App 启动自动打开后台监控。列表里每个当前 attachment 初始关闭；setEnabled 需要 unlocked、sinkReady、明确不是游戏/未知前台，以及非审批域。没有真实动作接收器时保持不可用，不能用空闭包接上 emit 就显示开启。

controller.handlerQueue 指向 main，通知也在 main，因此回调进入 MainActor。这样设备状态、view 租约和撤销状态有一个串行所有者；不能另起 actor 同时修改同一 gate。已有桥是本进程唯一 handler owner，不能再安装一个 valueChangedHandler 覆盖它。旧桥若存在，应先停止、迁移再接管。

进入每个输入域之前取消所有 held 按键，清空中立基线。按钮需要先观察到松开，再接受新的按下。摇杆同样要先回中；连上时一根摇杆被压住，不能让指针立即冲出去。后台输入开关只在至少一台明确启用的设备存在时打开，最后一台停止后恢复进入前的值。

## 事件路由表

|情境|按钮|摇杆|触发器/反馈|
|---|---|---|---|
|默认关闭/未授权设备|忽略，不拦系统行为|没有采样任务|不写反馈|
|桌面域、前台明确允许|按 typed button 意图交给已有桌面适配器|左摇杆 pointer/right scroll 的相对意图|桌面切换必须另有明确开关，本桥未接|
|指挥域|会话、开始/结束语音、返回等语义意图|本份不把摇杆转换成 OS 指针|反馈默认零；可选调用有明确范围|
|命令审批域|不能成为确认；抬起也不能承接旧 press|无位移|清理本桥拥有的反馈|
|游戏在前台或无法判定|停止桌面控制，取消 held|停止任务|只清自己施加过的模式，不清别人的|
|锁屏、睡眠、移除设备、退出|cancel 当前 attachment 的按下|停止并清 lastTime|可联系到设备时归零自己的反馈|

`environmentChanged()` 必须由权威锁态/输入域改变调用。NSWorkspace 的会话通知不足以独立证明系统锁态，所以代码还在每次输入/运动 tick 复核环境。不能只依赖一次开始时的 unlocked。

## 运动与能耗

GamepadMapping 的死区 0.15、指针上限 1000 点/秒、滚动上限 800、帧 delta 上限 50ms 来自前份候选推荐值，不是本轮设备测量。以实际 display 坐标/缩放接到系统动作时需要重新测手感。不能把 dpad 也塞进同一个 60Hz 轮询，导致每个 idle 都醒来。

当前桥只在已启用、桌面域、摇杆回中过且正在偏离时建立约 60Hz 的运动 Task。回中/停用/域变更立即取消；空闲没有周期采样任务。长时间卡帧的运动量限制为 50ms，不把醒来前的数秒积成一次巨大跳跃。这个结构是减少唤醒的设计，不是已测功耗结论。

传给桌面动作的 pointer/scroll 是带 attachment 的相对意图，不是已经发出的系统事件。最后执行器还需看权限、当前输入域和合成防环标记。指挥域没有这条系统指针出口。处理手势时不把节拍识别结果写成全局 Return/Space，以免确认了前台另一个应用。

## DualSense 的归零也要有所有权

S6 与 U1 中的头文件表明可以通过 GCDualSenseGamepad.leftTrigger/rightTrigger 使用 setModeFeedback 和 setModeOff，没有 adaptiveTriggers 这个属性。本份为实际已施加反馈的设备记 ownsFeedback，在取消/切域/锁/退出时归零。

“所有退出都 setModeOff”如果不检查所有权，会在我们从未施力时清掉游戏正在输出的反馈；因此本版只有自己的写入成功进入模式后才清理。默认没有调用者会施力。可选 feedback 的 strength 限制到 0.25 是保守初始值，不是人体安全阈值或硬件能力值。实际强度、USB/蓝牙差别、系统重连是否复位都需真机验证。崩溃后无法保证 App 回调运行，必须验证设备/系统失联自动释放行为，不得宣传绝对不会卡阻力。

## HID 遥控器还有什么不能猜

本份 usage 表沿用委托的候选映射，来源需绑定 exact registryID/VID/PID 和设备报告。consumer page 和 generic desktop page 上的同一 usage 数字不是同一按键；vendor usage 不自动解释成标准按键。当前 map 只接受 0/1 值，未知 usage 返回 nil；它不是主动监听器。

I5 仍需 IOHIDManager 的 device matched/removed/input value 回调、明确的匹配字典、设备生命周期、回调队列和停用清理。先非独占观察用户选中的设备，不使用全局 seizure，不把全部键盘纳入。设备关闭后清理尚未抬起的按键，但不能向系统发送一个没有对应本桥 keyDown 的 keyUp。坐标/音频没有报告证据时，只显示按键可用，不用空数组或零坐标假装能力齐全。

hidutil 是另一条系统映射链。后续 runner 使用绝对可执行路径和参数数组，不经 shell 拼字符串；读取当前设备级映射并记录原值与摘要，在比较仍相同时写入。撤销时再次比较当前值仍是本工具写入的版本，外部工具改过就不覆盖，提示用户冲突。全局 UserKeyMapping 不当作方便的回退路径。

## I3 鼠标、I2 多触点的边界

鼠标平滑主动 tap 仍需实际 CGEventTap 适配器。event 的 continuous 属性不充分证明它来自哪只设备，未知来源先原样放行。辅助功能/输入监控拒绝时不吞原输入；tap 被系统禁用时重建策略要有上限，不无限重试。合成事件带本进程标签、进入 tap 先跳过自身，防止再次平滑。滚轮阶段、惯性、触控板与鼠标需要分开验证，不能统一翻转方向。

多触点框架中有某个 symbol，不代表已知其回调数据结构。未知 stride/packing 的结构体不能在生产 `unsafeBitCast`；先从相同系统 build 的 ABI 证据与只读探针得到字段和长度，再解码，并保留标准输入回退。没有这一证据，I2 维持关闭，但不妨碍先交付公开 GameController 分支。

## 给执行模型的具体退路

只要某来源缺身份、权限或 ABI，设置页显示精确原因，不制造虚假设备。输入共存失败时只停该来源，保留番茄钟和原有窗口管理。一个来源已通过测试不自动准入另一个来源，更不能把手柄连上当作用户身份的第二因素。心率、声调、紧张程度不会在本包转换成授权依据。
