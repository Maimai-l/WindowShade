# A3 / D3 / T2：一个岛的拥有者、输入、内容和几何

## 不再新增第二套浮窗

原 NotchPanel 已承担现有窗口管理和授权交互。本份所有卡片继续走 `setInteraction`，WS2IslandCoordinator 只协调 content 和租约，不创建 NSPanel。AppDelegate 持有一个 WS2AppRuntime，runtime 再持有一个 coordinator 和一个 FocusTimerHost。视图只呈现模型，不私自拥有计时器、CLI 或设备监听器。

“同一个岛”不仅指屏幕上画得相似，还要保证输入所有权也只有一个。旧 view 的回调可以晚到，真实授权可能在设备断开后返回，显示器也可能在动画中拔掉。因此每个 content 的输入 closure 都查当前租约，而不是只看 `window != nil` 或 isHidden。

## 正确的替换顺序

先使旧租约不可用，再清输入/按键绑定/敏感文本，取消属于旧视图的任务，移除旧 content，最后发布新租约。不要先绘制新卡，再等待旧卡异步“收场”。否则旧鼠标抬起或遥控器按键能落到新确认按钮。

本份 `revoked` 清掉 coordinator 自己的引用后才调用外部 onDismiss，避免外部取消回调重入时再次撤销同一票。`dismiss(ifShowing:)` 和 view 的弱引用确保断开的旧审批不能关掉后来打开的番茄钟。需要这一点的调用者不要退回全局 `dismiss()`。

普通显式导航可以关闭自己原先打开的普通内容；新活动通知不能触发这种导航。授权入口可抢占普通详情；普通活动不能抢占正在进行的原生认证。把接口名 isAuthenticating 理解为旧 NotchPanel 的交互排他状态，不将它当成用户已认证的事实。

## 原生身份验证的交接

命令 review 是审阅，不是授权。审阅完成后 `handOffToAuthorization(ifShowing:)` 只撤销自己的 content，并暂时取消“关闭审阅等于拒绝”的回调，随后请求原 NotchAuthenticationController。原生 controller 通过 acquireInteraction/releaseInteraction 与同一 lease coordinator 接起来。

这几个 hooks 在生产 runtime 初始化时安装；独立旧测试可以不安装，但生产不能因为 nil 也能工作就永远跳过共享租约。主模型要核对 runtime 初始化发生在任何新 UI/审批使用前。退出时先 revoke 再拆 observer/hook。不能在原生认证仍在运行时，把 coordinator 释放后留一个默认允许的 closure。

认证失败、显示器移除、锁屏、系统状态未知，均不自动把原票转交到另一屏。用户需要重新明确发起。恢复焦点也只恢复仍存在、仍属于这次交互的旧宿主，不能任意激活之前的终端把按键打进去。

## 几何不应影响授权判定

以前认证 content 的布局写死 68 点，新增 210/280/320/360 点原生卡片后必须让 NotchPanel 和 canvas 同时采用内容高度。本份在物理刘海下扣除摄像头高度，内容放在实际可见矩形内；宽度不超过屏幕可用范围。不能单改某个卡片 frame 就认为父窗口会随之长高。

|内容|本份请求尺寸（点）|溢出行为|
|---|---:|---|
|番茄钟|320×210|固定小控件；小屏幕需核查最小约束|
|会话列表|520×320|滚动，不丢掉超出可见高度的会话入口|
|指挥状态|420×280|滚动容器；草稿与轨迹布局仍需 Mac 观感验收|
|命令审阅|600×360|完整纯文本滚动区，确认/拒绝保持可达|
|既有认证|沿用原尺寸逻辑|不改 LocalAuthenticationEmbeddedUI 的内部布局|

这些是候选起始尺寸，不是 HIG 强制值，也没有宣称通过所有显示器。主模型应在 1280×800、1920×1080、带刘海内屏、外屏、缩放模式、菜单栏自动隐藏和多屏断开下核查。可见区域不够容纳安全审阅时返回 unavailable，不压到看不到完整命令仍启用确认，也不偷偷换一套无身份保障的窗口。

## 新增的具体可用方法

`WS2AppRuntime.showSessions(_:open:stop:)` 可显示真实 AgentSessions 的快照；observed 会话没有 stop 控件，owned 且 running 才显示停止。调用者必须把操作再发给实际 session owner，并在执行时复核 context。summary 只能当显示文字，不参与身份查找。

`showConductor(_:action:)` 可呈现 ConductorNotch。所有 UI 按钮只产生 Action，后端来决定 send/stop/session 等；不由按钮调用 shell。草稿发送改为携带 editor 的最新字符串，避免用户改了文本但发出去的是第一次 render 的旧值。模型/effort 的变更需使旧费用确认失效；不能用一张旧票批准更贵的新配置。

这两种视图已有打开方法，但当前生产 store 的订阅、onEvent 增量刷新和开发入口尚未全部接入。不要把每次活动更新变成 `show...` 重新开一个卡片，尤其不能夺走焦点。打开时建一次 view，状态改变只 render 同一个 view；关闭后取消该订阅而不是取消整个会话。

## 输入与无障碍

command review 可以选中文本、滚动查看、用明确的新操作请求 Touch ID；它不是终端，不解释富文本控制。没有自动复制命令到剪贴板、没有把目录做成运行 shell 的链接。长命令不裁成 160 字摘要来进行批准。

NSButton 有实际文字或 accessibilityLabel；只靠图标的按钮提供暂停/继续/跳过/结束的 label。VoiceOver 顺序为标题、上下文、内容、拒绝、确认；拒绝与关闭可达，不把焦点困在卡片中。系统“减少动态效果”时不呼吸/弹跳；关闭窗口移除动画。对比度、键盘导航、VoiceOver 以及看不见按钮时确认是否仍可触发，都属于 Mac 待验收项，不能由 Linux parse 代替。

按下方向键/遥控器按钮不应发送全局键盘事件来“导航 AppKit”。视图或 reducer 显式维护当前选择并处理 typed input；离开域时清 held 状态。新授权 UI 不允许通过上一页面的连续按键自动同意。

## 需要主模型复核的实际风险

共享租约 hooks 影响原来的认证生命周期，是本份最需要 Mac 回归的位置。必须验证原有设置确认、原有设备密钥登记、取消认证、超时、重复回调和显示器移除。当前候选旧 tests 未加载 AppKit，因此不能说原生授权没有回归。必须使用真实 AuthorizationService 和原 controller，不用一个返回假的 grant 的 mock 把 UI 走通就放行。
