# 工单 02：真实手柄与当前列表

先完成工单01。实际入口只支持具有 extendedGamepad profile 的当前附件。不要从设备名推断支持或设置永久信任；没有设备时保留鼠标入口，代码验收状态仍写未运行硬件。

|编号|操作|必须观察到|
|---|---|---|
|PAD01|仅打开列表，不点启用|可显示库存，不写设备handler、不采用模型|
|PAD02|本地启用且所有键已松开|同一附件启用一次，方向键移动可见行|
|PAD03|启用前压住A，再松开|不会采用；之后一次新按下/松开才能采用|
|PAD04|在首行按上、末行按下|不循环，不停用设备|
|PAD05|压A后方向键移行，再松开A|旧准备取消，新行不采用|
|PAD06|压A后鼠标点当前同一行，再松开|也取消，不重复采用|
|PAD07|换页/失焦/审批/锁屏后松开|旧动作无效，不在别处发Return|
|PAD08|重新前台/解锁|没有自动启用；用户本地重新启用|
|PAD09|相同名字断开重连|新附件，不继承旧状态|
|PAD10|启用第二只|第一只cancel并释放，只有第二只可操作|
|PAD11|已有同进程callback|本桥拒绝接管，不覆盖原callback|
|PAD12|采用模型后返回会话|只改变模型；尚未产生发送，草稿还在|
|PAD13|点击一次本地发送|原会话使用已选模型，只发一次|
|PAD14|关页、关功能、正常退出|handler、观察者和待确认清理，原生系统输入照常|

观察 GameControllerBridge 的 installHandler/releaseHandler、每次 sample 后 gate 状态和 Runtime 的 exact view dismiss。排障只记录本地附件关联号、按钮语义及代次，不写蓝牙地址或长期按键历史。不要全局打开背景事件来解决“窗口不是前台时不响应”；这是本次明确不支持的状态。

目前没有取得可证明任意同进程模块恶意覆写 callback 的所有权API。未来其他功能要用同一host注册，不得另设handler后又期待本桥自动识别。跨应用共存、控制器固件和重映射请记录实际设备/系统，不用本包fake bridge的数据充当。

本工单不验收桌面运动、振动、扳机、HID、鼠标事件tap、遥控器音频、私有多触点、节拍识别或身份。它们不能因为模型页可用就被勾选完成。
