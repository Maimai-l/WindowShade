# 第八份：把手柄接到实际列表，把窗口结果接到实际事务

基线是第七份统一包的 `candidate-repo/`，1157 个文件。统一 v8 已组合完毕，直接使用其 candidate-repo；不要再按序运行前八份补丁。实际开发工作区已有其他修改时，使用本包 base-files、base-sources、overlay 做三方合并，不能清空用户工作区换取“干净通过”。

先读 CHANGELOG、VALIDATION、REMAINING，然后运行 README 中的 input/fold/flow 和组合类型检查。接着在隔离 Mac 执行整应用构建，按工单分别验收输入和窗口。不要因为一条暂时缺外设，就不编译另一条；也不要通过删除新视图、关闭 Swift 6、跳过认证源码或 Sparkle 来制造“整应用构建通过”。

这份不会开放额外权限批准。手柄确认只选模型，不能发送草稿、批准命令或系统解锁。用户仍需在会话页单独点击发送。模型目录、账号、thread、turn、授权账和刘海租约全部复用既有所有者。

阅读路线：docs/01 看实际调用链；02、03 看按键与原生界面；04、05 看窗口副作用和恢复边界；06 看如何继续扩展而不重写。DECISIONS 固定本次已经做出的选择。sources/code-map.md 给出真实路径、哈希和符号行号；sources/SOURCES.md 将代码事实、外部资料和尚未读到的 SDK 正文分开。

# 01 真实调用链和实例归属

## 已落到原程序的路径

```text
WS2SupplementPane → WS2AppRuntime.openOwned → 原 WS2OwnedSessionView
  → “选择模型…” → WS2AppRuntime.openModelPicker
  → 原 WS2IslandCoordinator.show / inputHandle
  → WS2ModelPickerView（NSTableView，来自 owned.models）
  → WS2DeviceActionHost（唯一页面宿主）
  → WS2GameControllerBridge（显式启用后安装 callback）
  → 既有 DeviceInputGate / SemanticInputRouter
  → WS2VisibleListInput → 既有 SelectionModel
  → WS2OwnedLaunchController.chooseModel → 返回原会话页
```

本次没有再造 model store。模型 ID 来自实际连接的 CodexWire 目录，OwnedLaunchController 保持其模型和 effort 一致性。测试后端返回两个合成模型用于验证接线，不能被安装成产品自带模型。新建/恢复 thread 及调用模型服务依然走第七份原有路径。

AppRuntime 强持有当前 deviceHost；host 持有当前模型页 sink 与桥；模型页持有原 OwnedLaunchController。所有反向回调 weak 捕获。页面离开时按 exact view 匹配，先 stop host 再释放引用。后台助手可以继续运行，设备输入不跟着后台页面存活。关闭 UI 与结束进程仍是两种用户动作。

Core/WS2DeviceActionContracts 只是跨平台的类型合同。它把附件、输入、环境和 sink 协议从 GameController/AppKit 类里分出来，因此 Linux 能编译实际 DeviceActionHost；它没有发明另一套系统事件框架。测试 bridge 明确是替身，其余 host、router、selection 与真实进程通道用生产源码。

## 页面租约与附件绑定

pageID 是这个页面实例的局部标识，不单独证明权限。模型页同时核对 expectedLease、Island 返回的当前 exact handle、isShowingInteraction、实际 key window 与 NSApp.isActive。四个事实都成立后，host 才能为该附件取得包含 pageID、selection revision、backendEpoch 的 context。

只有 backendEpoch 相同也不够：模型列表可在同一连接内刷新，页面可被审批抢占，设备可断开重连。反过来，只有页面仍可见也不够：后台已断开再连接，旧手柄确认不能落到新连接。现有 ticket 同时绑定这些代次，不靠一个 enabled 布尔变量承受全部含义。

页面模型更新只在实际 ID、可选状态、连接代次变化时替换 snapshot。单纯重绘不凭空更新 revision。鼠标点选也经过同一个 SelectionModel；键盘、鼠标和手柄不会各保存一个“当前第 N 行”。选项为空或重复 ID 时取消选择，不拿旧行继续提交。

## 哪些同步回调也会使状态改变

按下 A 后，prepare 会显示“松开 A 使用：某模型”。这个 UI 回调也可能同步导致页面关闭、权限撤销或目录状态变化。因此 prepare 之后 host 必须再读 liveContext，不能把“函数没有 await”理解成“事实绝不会变”。VisibleListInput 也在 onArmed 返回后检查自己的 pending 是否仍是原票据。

执行 useSelection 时，chooseModel 会再调用实际 revalidate。真实目录已被替换时，此处拒绝并清理连接。测试 IFLOW06 确实在临时文件系统重命名原目录并创建同名新目录，不使用一个假的目录状态布尔值冒充检查。这个检查仍不是文件沙盒，也不能消除系统调用之间所有文件竞争。

本篇的调用关系来自本轮候选源码，定位见 code-map。Mac 的窗口焦点、目标成员关系和 GameController handler 行为还没有实测，源码关系不能替代它们。

# 02 按下记住目标，松开才采用

## 一次确认跨越了一段时间

只把 A 的释放事件映射成“打开当前选择”仍会出错。用户按住 A 后，列表可能移动、收到新模型、被鼠标点击、切页或断开。若松手时才读当前行，执行的目标可能根本不是按下时看到的那一个。

本次流程是：began 验证来源与当前上下文；prepare 预约现有 SelectionModel.Activation，并保存确切行；界面显示这次准备采用的模型；ended 必须匹配同一 pressID、按钮映射、附件、页面、列表 revision 与连接；最后消费 Activation 得到稳定 ID。任何一次移动、同一行鼠标重选、刷新或失焦，都撤销准备。收到重复 ended 不产生第二次动作。

W3C 关于 Pointer Cancellation 的说明强调让释放阶段的完成可取消，减少意外触发。其适用范围是网页指针内容，并非 macOS 手柄规范。本包仅借鉴“完成前能撤销”的交互原则；本项目的页面票据和 A 键规则属于工程选择，不声称因此符合 WCAG 或取得可访问性认证。[S01]

## 导航与采用不是同一种动作

方向键只改变可见选择。列表开头按上、末尾按下是正常的无移动，不是错误，不能因此撤销整只手柄。原先把 sink 返回 false 一律视为安全失败，会让用户到边缘就被停用。本次边缘导航作为已处理的无副作用输入消耗，保持已启用状态。

采用模型则必须返回实际成功。行被禁用、上下文过期、目录改变或 pending 消失时，不能假装选中了。B/Menu 仅返回原会话，不隐式发送、停止任务或关闭整个应用。未知按钮没有默认的“确认”回退。

手柄刚启用时要求先回到松开状态。启用前已经压住的按钮不被视为一次新按下；断开重连也不继承旧许可。附件 ID 是本次连接对象的 UUID，名称和同型号只能显示，不能用来找回授权。第二只手柄明确启用时先清理第一只的 held、pending、mapping 和 handler。

## 松开采用的提示要说具体对象

界面提示记录的是按下时的 ID，不能每次渲染用当前行覆盖它。取消后提示立即清空，避免看似仍准备采用 A、实际却采用 B。这里使用纯文本且不把模型 ID 当可执行链接；超长 ID 在表格截断，原字符串保留在工具提示供本地核对。

当前候选说明文字用 A/B 表示 GameController 语义按钮。不同设备的印刷符号和用户重映射可能不同。Mac 设备验收时需核对实际符号显示；在没有相应设备事实前不把 A 字母宣传为所有手柄共同标识。可以在同一个 view 替换为系统返回的按钮图形，不能为图形适配重写动作路由。[S02][S03]

本轮 INPUT07–12、20–24、31–33 覆盖错目标、重放和同步撤销，IFLOW02 通过真实本地管道证明采用模型未发 thread/start 或 turn/start。手柄事件本身是合成的，不能据此声称测过硬件去抖、蓝牙延迟或零误触。

# 03 回调所有权、焦点和原生体验

## 发现设备不会自动接管

第七份桥在发现 supported extendedGamepad 时就写 handlerQueue 和 valueChangedHandler。即使业务 gate 未启用，这也是对框架回调入口的占用。本次 reconcile 只建立库存和所需按钮引用，直到用户在可见页点“本次启用”才安装 handler。

安装时先检查现有 handler 为空，记录先前队列，然后把本桥 handler 放到 main。若已有其他同进程功能使用该 callback，拒绝启用，不覆盖它。停用只释放自己标记拥有的入口，并恢复之前的队列。不能声称已经解决任意第三方竞争：另一段代码若在启用期间绕过唯一所有者偷偷改同一 callback，本桥无法证明谁最后写入。项目内部必须约束所有 handler 写入经过这一个 owner。

本次不写 GCController.shouldMonitorBackgroundEvents。我们采用当前页、当前 key window、当前应用在前台三项同时满足的路径，失去其中一项就撤销。该选择不需要一个猜测前台是否游戏的分类模型。历史变量 frontIsGameOrUnknown 在此装配为“这个具体页面不能接收输入”，不能把它的名字当作已经实现了游戏识别。[S04]

## 回到前台可以刷新按钮，不能复活按键

模型页监听自身 didResignKey，清 pending 并通知环境撤销。didBecomeKey 和应用 didBecomeActive 只刷新本地按钮及可用状态，不重新启用手柄。视图挂到另一窗口或被 revoke 时移除这些观察者。这样重新点回页面后本地操作可恢复，但旧 A 释放不会穿过一次失焦继续选择。

框架 handlerQueue 被本桥设置为 main，是现有 MainActor.assumeIsolated 的调用前提；此方法本身不是线程切换器。任何以后把队列改到后台的提交，都必须同步改 actor 桥接并保留事件代次。Task 回到主 actor 后仍需检查 context，不能只 weak self 不为空就派发。

实际按钮采样循环在每一项及 emit 返回后检查 gate 和 ownsHandler，因为一个动作可能同步关闭页面。运动任务也必须有 cancelled/neutral；本次模型页 motionReady 恒为 false，没有移动窗口、振动或扳机阻力调用者。旧反馈候选保留不等于这次已交付反馈功能。

## 原生视图的具体落点

新页是原 Island 内 520×420 的 NSTableView，不创建第二个产品窗口。列表高度 224、行高30、单列初始宽460、最小140，表格随容器宽度变化。选择变化滚到实际行，鼠标与手柄用同一可见选择。它们是布局起点，不是通过 HIG 审核的数值。[S05]

模型页没有文本编辑器。会话页打开模型页前先检查 marked text，组合输入未结束就不跳页；已经完成的草稿留在原控制器。Return 在原会话编辑器继续换行，提交仍是独立本地发送动作。关页不结束助手，选完模型返回同一实例。

无设备时显示“没有检测到游戏手柄；仍可用鼠标选择”。不能弹安装向导假装硬件一定可用，也不把全部会话功能禁用。读屏名称、真实滚动、按钮焦点、短屏、多屏和不同手柄图形仍需 Mac 检查。本轮没有原生截图或可访问性树实测。

# 04 窗口写入和观察是两件事

## 这次进入了原来的收起路径

```text
Notch.finishTuck
  → shadeWithEvidence（同一个 AppDelegate）
  → 原 shade：捕获、既有恢复 intent、最后身份/权限检查
  → markMutation → hideWindow 或原 native resize
  → bind 实际 ShadeState.foldTransactionID
  → 原验证/完成落点 → strictFoldObservation
  → exact ticket 回调 → 原 NotchTile 文案
```

本次没有写第二个恢复器，没有用 tuckAll 的切换行为冒充幂等收起。WS2FoldEvidence 是小型有界的临时完成通知账，只接受本次调用的 ticket；实际窗口状态仍在原 shaded，恢复仍由原 journal 和原 unshade 路径处理。

之前的“已加入刘海数组”只能说明界面登记了窗口。新卡片先写“正在收起”，只有匹配事务的真实观察才去掉这条状态；观察缺失、仍可见或隐藏结果不明确时显示“收起状态未确认”。没有开始修改窗口的失败可移除原占位。不能把未知改成取消成功。

## 最后一次检查放在什么地方

截图可能晚到，期间用户可以释放刘海条目、锁屏或换掉窗口。shadeWithEvidence 保存一个明确 mayCommit 闭包，其内容检查本次 Notch item incarnation 仍在、功能仍可用。installOverlay 到达时先复查；实际 hideWindow 前再检查 AX windowID/pid、当前锁态、期限以及这次 still-current 的 mayCommit，然后才 markMutation。

markMutation 记录“即将发起有副作用的调用”，不表示调用成功。这个顺序使超时能区分未开始与可能已经改变。原恢复 intent 必须仍在 hideWindow 之前写入，不能为了新回执重新排到隐藏后。原 duo-integration-check 已重新运行，但它只是静态顺序断言，不是真实崩溃恢复试验。

未开始就过期，可以输出 notStarted；调用发出后再超时，只能输出 unknown。业务取消不能撤回已经进入别的进程的系统调用。当前改动能阻止旧截图在条目已取消后才发起隐藏，不能保证取消任何时刻都自动恢复。已经存在的 folded overlay、手动展开和原恢复机制继续承担后续处理。

## 哪些观察能够支持什么

新 strictFoldObservation 独立于旧 hideTookEffect。读不到 AX 几何、进程已消失、元素身份不符都返回 unknown。offscreen 必须读到有限且有效的坐标/尺寸并确认不在可见区域；minimized 必须成功读取明确0或1；应用隐藏和私有 alpha 使用其各自实际读取结果。native resize 只是缩小而未隐藏，Quick Look 关闭后的身份也另有问题，均不冒报 verifiedHidden。

即便读到 verifiedHidden，也只是这次观察时成立，不代表以后一直隐藏、用户没手动调整或这个窗口归番茄钟所有。AX API 具体返回类型及私有分支在此平台没有编译，必须在 Mac 验证。[S06] 旧 hideTookEffect 的宽松 nil 分支没有全局重写，其他旧调用者仍需逐项核查；不能把新端口的严格判断扩写成整应用已修好。

## 迟到回调不能结算新事务

原 FoldTransaction 的延迟验证、最小化、Quick Look 与完成闭包，现在逐处核对捕获的 foldTransactionID。rollback 在进入时及同步取消可能重入后再次检查；reveal 发布观察后再次核对再操作 overlay。清理与 unshade 使用 exact transaction 取消新证据账，旧请求不能按相同 windowID 清掉新事务。

观察重试只在0.15、0.6、1.2秒读取，不再隐藏、最小化或恢复。闭包只捕获 ticket/transactionID，不保留整个 ShadeState 的截图和 overlay。30秒请求期限、60秒忘记临时通知、最多64项都是工程预算；主队列阻塞会推迟定时回调，不能宣传为严格实时上界。late 字段明确标出在先前结果之后的更新，不能累计成第二次普通完成。

# 05 完整番茄钟恢复还差的事务

第八份已经给原收进刘海路径装上具体证据，但它不是完整 T3。把 WS2FoldEvidence.Event 直接转换为 WS2FocusWindowOwnership.Receipt 会丢失用户干预和重启身份，因此本包没有开放自动恢复。

## 下一笔应改原事务的身份来源

先在原窗口状态和恢复记录中确定一个共同的稳定键：本机启动代次、窗口来源进程及其开始标记、窗口ID与本程序观察代次。原业务持有这些事实时增加 typed 字段，不再建立旁边一套靠窗口标题匹配的缓存。程序退出重开、相同 PID/windowID 重用、重新发现 AX 元素，都不能被默认为旧对象。

接着把本轮 timerRun、effectGeneration、具体操作 attempt、实际 foldTransactionID 放入同一条原恢复事务关联。谁发起隐藏、谁观察成功、谁后来手动移动，都必须推进明确的 revision。旧内存 ticket 只是相关性，不是这种身份和所有权证明。

## 用户的后续动作优先

只恢复本轮确实改变且所有权未被用户新动作取代的窗口。用户在专注期间主动展开、移动、缩放、关闭或换桌面时，旧恢复权应失效。不能到休息时间把所有启动时截图里的位置重新写一遍，也不能遍历当前 shaded 字典把别的功能收起的窗口一并恢复。

恢复前再次读活身份、revision 与归属；恢复后读实际可见/几何结果。中间失败保留 reconciliation 状态，不能先删 receipt 然后无论系统返回什么都说完成。跨 await 后的新窗口变动必须可使老恢复回调失效。

## 超时后处理的是事实，不是再次点按钮

隐藏超时返回 unknown 时，原动作可能稍后成功。立即重试 toggle 会把它展开，也可能再启动一套并行事务。正确的下一步是只读核对，得到同一 identity/transaction 的实际状态，再决定是否存在用户要求的补偿。未知不能被当作“肯定没做”；迟到成功也不能被当作“可以不经用户意愿立刻展开”。

锁屏时不为了收尾突然显示私人窗口。正常退出、睡眠和崩溃分别处理。跨重启恢复使用原 journal 的 prepare/attempt/observed/unknown 关联，不另建竞争的文件。持久化失败时停止新的自动窗口效果，计时本身仍可继续。

## 与现有计划层的接法

保留 WS2FocusEffectPlan、WS2FocusEffectExecutor 和原 FocusTimerHost。真实窗口 port 负责解析具体目标、最后身份复核、幂等隐藏/恢复以及 typed completion。executor 只串行执行已定计划并接收事实，不伪造 AX 结果。端口尚未就绪时 UI 继续“仅计时”，不把 capability 设 true 再接空闭包。

第八份工单 04 列出具体文件、落点和验收。这里的决定减少执行者需要自行选的分支，但没有声称已经交付强身份/持久恢复代码。晚到结果、用户干预、进程重用、journal写失败和锁中补偿须用真实系统/文件故障逐项验证，不能只增加合成测试数量。

# 06 扩展交互时保留选择和执行的间隔

本次已经实现的一个实用变化是“先指向，再采用”：选择行、按住提示具体目标、松开采用、返回同一会话。它为以后指挥手勢、遥控器、头部动作等提供可复用的低风险目的地，但没有替这些来源建立真实性和身份。

以后接入新来源时，只需它提供明确的开始、变化、结束、取消和当前来源代次，进入同一个 typed sink。不要把一次点头直接变成系统 Return；也不要为了省接口将所有动作折叠为字符串命令。稳定目标票据可以复用，来源准入和意图识别必须各自有证据。

## 三种动作保留不同门槛

浏览和选择仅改变本地可见项，可以使用这个列表 sink。发送一段草稿会启动真实后端工作并可能使用额度，要经过单独明确的本地操作及当前 scope。批准命令、授予文件/网络权限和系统解锁涉及另外的同意与权利，只能走真实审阅、认证、授权账及相应系统端口。前一层成功不能自动替代后一层。

因此本轮 IFLOW 同时检查两件事：手柄采用模型后出站没有 thread/start 或 turn/start；后来本地点击发送时，实际发出的 model 是刚才选中的那个，并且只发一次。这个测试证明本地候选调用关系，不证明模型服务收到真实请求或实际花费。

## 有趣的反馈不必先依赖更多传感器

已实现的准备采用提示，让人在松手前看见具体目标；未知窗口状态文案，让界面不抢先宣告成功。这些变化不需要摄像头、麦克风、云端识别、振动或背景采样。下一次视觉改进可围绕已经存在的状态做，例如给准备中的行加局部边框、将 unknown 作为可展开的原因提示。它们是后续可选表现，不是本包新增已完成动效。

反馈不应藏起状态差异。绿色动画不能使未知成为成功；同一声提示也不能同时表示“本地已入队”“后端已收到”“已经执行”。如果以后使用触觉，必须绑定具体本次附件、当前启用状态和明确反馈含义，断连归零。旧桥内的反馈候选没有生产调用者，本轮没有启用它。

## 让后续工作能停下来

本地助手不再新增协调器，直接做 Mac构建、真实固定CLI和原生布局验收。手柄模型页已有具体 sink，下一步真机验证其准入、失焦和采用过程；其他会话/指挥页面需要自己的有限动作映射，不能未经设计复用模型页的“使用”语义。窗口下一步只补强身份、所有权、恢复端口，不再做第三个纯计划模型。

配对接收、SRP/Keychain、Listener/OPACK/profile、私有触点/HID、BLE/身份/系统锁、全菜单设置、能耗和影片仍留在总清单。不要因本次两条路径前进就说其他都是测试工作，也不要让不依赖遥控协议的本地功能继续等待其全部完成。
