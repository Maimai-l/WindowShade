# 概念片审查与本次落实

前作 `promo/src/timeline.ts` 的一张提示表、60 fps、120 bpm 编辑网格与横竖双版值得沿用。`promo/scripts/audio.ts` 把声音集中到时间线也值得沿用。前作以绘制窗口讲解功能，新片的既有功能要换成真实录屏，不能复用假 UI。

原分镜最大的风险是五个卖点各自变成标题加卡片；同一种整屏卡片连续出现、每章结束清场，会把功能展示剪成幻灯片。新版保留一个全片共享刘海，章界都闭合到同一195×58轮廓。除结尾黑场，主体缩回同一位置，再从那里出现下一章。九章长度为14、16、18、16、10、24、12、6、10秒；指挥模式最长，专注/离席段最短，避免九个等长广告页。

## 五处重点

开盖身份段只画开盖、人物轮廓与候选设备，展示两个条件汇合的概念。删除密码填入、解锁桌面、Face ID 图形。这个概念并未证明摄像头身份识别和系统解锁已实现，必须保留“概念演示”。

刘海段的惊喜应来自真实消息进入同一个轮廓，不能靠把音乐播放器画得漂亮。N1–N3素材目前全部待录；现版只做节奏与容器位置。录屏时先拍无变化的桌面，再拍来源事件到达，勿把系统权限提示剪掉后声称无配置。

启动台段的记忆点是 App 图标被拖到屏边后变成实际窗口。L1–L3须在同一真实会话录制；不把三个静态截图串成“已发生”的拖动。

指挥段先画一笔，再呈现三段真实终端素材位。必须在素材中看到“准备、发送、后端接受、审批、回执”的区分。轨迹图是概念，不伪造实际 effort 生效。当前样片没有接上真实轨迹数据和音频；波形是带概念标记的抽象运动。

CarPlay相关段不画CarPlay界面，只让同一个轮廓打开成抽象路径空间。它说明换一种用法，不证明获得CarPlay协议认证或正在驾驶中操作编程助手。

## 节奏和审美取舍

按上传的 `skills/motion-doctrine/references/doctrine.md` §2–10 与 `reference/aesthetic-rules.md` R1–R4/Q1–Q11，先安排静止段，再安排相机。静止段总计2370/7560帧（31.35%）；是本次编排选择，不是审美合格分。整个SVG在每段首尾相等的检查已加入，但像素、真实视频解码及主模型观感还要另验。

已做：取消手持抖动；只有主角用强调色；文字不承担产品证明；界面素材不仿制；章界共享轮廓；横竖单独放置标题。

尚未达到终片：现版连续的素材占位卡仍显得重复；静止期有些时间花在等待素材而非观看实际结果；身份段完成勾容易被看成“系统解锁成功”，正式版必须和事实字幕一起复核；九章边界的统一回收偏保守，不能把它叫作已完成的五次wow。真正的手势动作、窗口穿越与高光时刻取决于真机素材。
