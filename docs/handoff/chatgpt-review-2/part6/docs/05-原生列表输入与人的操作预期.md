# 05　原生列表输入与人的操作预期

手柄或遥控器输入的目标是用户当前看得见的一项操作。它不应取决于此刻哪个应用碰巧拿到了键盘焦点。这里的设计保留前几份“多输入来源 → 同一语义意图”的方向，先让原生列表可靠，再增加窗口运动与节拍识别。

## 稳定身份比索引重要

实时会话插到列表顶部后，昨天的第 2 项已经不是今天的第 2 项。新 `WS2SelectionModel` 保存稳定 itemID 和 snapshot revision。替换列表时尽量保留原 ID；原项消失或被禁用后，选择第一项可用内容；空列表的选择为空。重复 ID、过大的列表或超长 ID 直接使输入模型失效，不能继续激活旧内容。

最大 512 项和 ID 最多 512 UTF-8 字节是工程上限，不是 UI 建议显示 512 行。大型资料要分页或过滤，原生列表每屏仍保持可读。手柄移动只接受 -1 或 +1，跳过 disabled 行，到边缘停止，不循环跳到另一端。这样用户连续按住也不会在一轮滚动后误落到开头的危险项。

## 确认分为预约和消费

按键按下、松开、UI 出现和列表更新可以交错发生。已有 `WS2SemanticInputRouter` 负责附件和 pressID；新 SelectionModel 负责列表内的目标版本。两者相接时，先验证输入 ticket，再以当前 revision 预约 Activation，最终在本地 typed sink 消费 Activation 得到稳定 itemID。

同一个 Activation 只能消费一次；期间换页、刷新列表、移动选择、禁用、锁屏或撤销均使它失效。它不是 AuthorizationGrant，所以不得传到命令批准或系统解锁。普通列表激活会打开模型详情或会话页；真的发送新 turn 还应走草稿/配置成本确认及本地 scope 检查。

## 原生视图的具体约束

现有 NSView 由 Island 的同一租约持有。更新内容不新建另一份窗口，不在每秒 tick 中销毁重建列表，不在每个 valueChanged 中抢 key window。键盘、鼠标与手柄共享同一 selection store，鼠标点某行也更新稳定 ID。屏幕阅读器的焦点与可见选择需要在同一个更新批次内协调，禁止悄悄激活未滚入视口的行。

选择变动只更新旧行和新行，列表数据改变才计算差量。草稿输入中要保护中文组合输入；存在 marked text 时，远端确认不能被当作提交草稿。按 Esc 是取消本次交互，不应顺带杀掉仍在后台运行的助手任务。切换项目前应明确显示将断开当前连接。

## 持续动作必须有停止边

按钮是离散事件，摇杆是持续量。不要把它们统一成一串重复按下。对于任何持续窗口运动，必须定义 began/changed/ended/cancelled，目标在 began 固定。断连、租约撤销或目标消失都会产生 cancelled，并归零输出。归零要发给确切附件或运动执行器，不遍历操作所有控制器。

死区、重复间隔、曲线、触觉强度都是建议参数。没有设备测试前不宣传“零误触”。保持一次启用一个附件的既定约束；同一型号、同名设备和重新插入的对象不继承旧许可。审批出现时停止输入，不让手柄的 A 键兼作 Touch ID 批准。

## 先做到的可见结果

一条可以验收的路径是：用户本地启用手柄 → 打开现有会话列表 → 上下选择 → 当前可见项打开 → Esc 关闭交互 → 所有旧按键失效。它不要求先完成配对协议、WindowServer 效果或节拍分类。第六份只交 SelectionModel 和测试；NSTableView/现有卡片的实际 sink 仍按施工单接入，不声称已经能用手柄操作桌面。
