# 07　窗口效果是外部事务

窗口在另一个进程里。WindowShade 记录了一个意图，与该窗口真的隐藏、其应用仍存在、用户没有手动改变它，是几件不同的事。本篇基于现有 `FoldTransaction.swift`、`FoldCompletion.swift`、`WS2FocusEffectPlan` 和 executor 的实际代码；定位在 code-map。

## 不能把旧 Bool 当作新回执

当前 `hideTookEffect` 的 offscreen 分支在读不到 AX 几何时返回 true；hidden 分支在找不到 runningApp 时也默认 true。这是旧路径里的既定行为，但它不适合直接作为新番茄钟“我确实完成了隐藏”的证据。

第六份没有冒险直接改变所有旧窗口功能。给新端口的要求是另外建立三态观察：verifiedHidden、stillVisible、unknown。缺失 AX 元素、权限丢失、读超时、目标进程退出或无法核对身份均为 unknown。unknown 不登记所有权回执，也不意味着窗口一定还显示着；它可能已经被隐藏，需要恢复核对。

## 回调要绑到哪一次事务

`registerFoldWaiter` 给单个等待者 UUID，单 token 的超时结算可以避开后来的等待者；但 `settleFoldWaiters(id:success:)` 是按 windowID 批量结算。新 T3 端口不能只注册一个 windowID waiter 就假定回调来自自己的 foldTransactionID。

端口需捕获窗口完整身份、foldTransactionID、timer run、effectGeneration、beforeRevision 和自己的 waiter token。任何结算前重新核对实际 ShadeState 的事务 ID；旧事务晚到的成功只进入旧事务恢复核对，不能结算新事务。窗口 ID 和 PID 可能重复使用，所以当前身份还要带进程开始标记与 windowGeneration。

## 一次写入前后的具体步骤

先观察并确认窗口属于用户指定的目标集，保存 beforeRevision，注册属于这次事务的完成等待，再执行隐藏。完成回调返回后确认身份没有变化，读取实际隐藏结果，只有 verifiedHidden 和 afterRevision 大于 beforeRevision 时才创建 Receipt。Receipt 保存的是这次动作的归属，不是当前所有窗口的快照。

如果等待超时，在执行器中标为 unknown 并暂停该窗口后续效果。不要在 timeout 分支自动再调用一次收起；旧动作可能稍后才生效。晚到成功需要触发一次恢复核对，而不是丢弃后让窗口永远留在屏幕外。目标已经换成用户手动状态时，取消本程序的自动恢复权，保留用户最新操作。

## 恢复不能越权

恢复前比较 receipt.run、effectGeneration、身份以及 liveRevision。任何一项不匹配都不直接移动窗口。恢复成功同样需要 afterRevision 递增并验证可见/几何状态。不要先把 receipt 删除再假称动作完成；一次性取出之后失败，需要保留独立的 reconciliation 记录。

应用退出、睡眠、锁屏和崩溃不是同一种退出。正常退出可以停止新动作并核对已持有 receipt。锁屏时不要为了清理而突然唤起被隐藏的私人窗口。崩溃恢复需要持久 journal 和身份核对；第五份 executor 没有跨重启 receipt，不能借用“内存里曾经有过”承诺崩溃可恢复。

## 建议 journal 事务，不在本轮伪装实现

追加 prepare 记录后才尝试写入；记录 attemptID、窗口身份、前后状态摘要、phase 和校验，不保存窗口标题或截图。动作观察明确后追加 committed 或 unknown。重启先按现有 journal 机制对照活窗口，不凭陈旧坐标重放。写 journal 失败时禁用新自动效果并保留用户原状态，不跳过持久化直接执行。

这需要与原工程的恢复机制共同设计，不能另建一个互相竞争的 restoration manager。第六份只锁定接口与错误分支；实际 AX/恢复端口和 typed completion 仍是源码缺口。

## 用户看到的结果

计时开始不必等所有窗口动画结束。界面可以显示“正在收起窗口”；遇到少数目标失败，计时继续，提示“部分窗口未能收起”，不要自动停整个番茄钟。尚未接实际端口时写“仅计时”，相关自动效果控制不可用。25/5、50/10 和修改预设只影响下一轮的既有规则不变。
