# 08　身份信号、隐私与安全默认

## 不把更多传感器当作更多身份因素

当前任务涉及 Touch ID、人脸、声纹、心率、蓝牙和手势。它们不具有同一证据强度。设备名称、RSSI、出现过的地址、手的移动和心率不能证明某把私钥仍由用户持有，也不能单独绑定这条具体命令的同意。

NIST SP 800-63B-4 将生物特征视为敏感且非秘密的测量，要求在其适用体系中配合物理认证器，并要求人脸呈现攻击检测；该版本不允许基于声纹的生物比较用于该认证体系。这是安全设计参考，不等于本项目获得认证，也不是断言所有桌面应用必须符合它。[S08](../sources/REFERENCES.md#s08)

本项目继续以系统已解锁和原生授权账为执行门槛。人脸和语音研究可以作为独立、默认关闭的实验，不得把“检测到脸”接成“系统解锁成功”，也不得自动输入系统密码。心率没有一条受验证协议能把“紧张”映射成设备不属于操作者；这类推断不进入授权判断。

## 把辅助证据用在合适的地方

蓝牙离开可以降低在场置信度，导致取消输入或缩减功能，不能直接证明用户离开，也不能让另一设备自动取得权限。无数据和低电量不等于身份失败。设备读数陈旧应显示未知，不显示零。相机被遮挡、麦克风权限被拒绝或传感器断开，都允许用户继续使用不依赖该传感器的功能。

风险指标适合触发额外确认，不适合降低原有确认要求。一次配对证明的是建立设备关系的那次过程；一次按键证明的是某个已接纳附件传来输入；一次 Touch ID 证明的是系统返回的一次认证结果。最终批准还要完整目标、期限和授权账的一次性消费。

## 让执行者能实施的数据最小化

默认不保存帧、音频、声纹模板、完整命令日志或应用标题历史。设置页列出来源、使用目的、保存期限、是否离机、关闭后的清理动作。新增诊断尾部是第六份唯一新增的数据保留通道：仅用户本地为本次启动显式开启、内存有上限、默认不导出，不能自动附进错误上报或模型上下文。

Keychain 读取错误不得在普通日志输出完整 item 内容。随机测试私钥只能放 fixtures，不能作为首次初始化失败时的备用身份。日志里记录本地关联号和错误类别，不写 PIN、共享密钥或原始认证载荷。

## 对照检验矩阵

人脸实验必须在明确同意的参与者与预先固定阈值下分别记录真正匹配失败和错误接受，不能用同一批样本调参后又充当独立测试。照片、屏幕重放、视频、变化光照和不同姿态属于不同验证条件；没有测过的条件保持未知。不能从“在我脸上试了十次都成功”推断可替代系统认证。

系统锁/解锁后端同样需要独立证据：请求发出了、动画完成了和系统登录会话真的锁定，分别记录。测试期间保留人工恢复手段。错误恢复不通过尝试更多私有接口、持续输密码或隐藏安全提示解决。
