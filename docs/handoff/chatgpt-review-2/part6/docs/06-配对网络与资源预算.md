# 06　配对网络与资源预算

## 把发现、身份和动作分开

mDNS/Bonjour 提供发现机制，不能用服务名替代配对密钥。RFC 6762 的安全讨论说明链路内发现仍有信任边界。对本项目而言，搜索结果里出现一台设备，最多说明收到了一条候选广告。[S06](../sources/REFERENCES.md#s06)

先保持 Mac 作为目标协议服务端的方向。pyatv 的 OPACK 源码是格式观察来源，不是 Apple 对 Mac 接收原生 Remote 的兼容承诺；它本身也注明未覆盖所有格式。第六份没有将其源码或依赖并入候选，未完成部分仍以独立原创实现和实际向量验证为准。[S04](../sources/REFERENCES.md#s04)

## 为什么单连接有界还不够

第五份每条 TCP 有自己的队列，但十条连接各分配一个队列仍会一起占用资源。第六份新增 `WS2ConnectionBudget`，让唯一 Listener owner 在创建传输前核算总容量：总连接 8，未验证连接 2，同一已验证 peer 同时 1，单连接排队 256 KiB，总排队 512 KiB。

这些是初版预算，不是苹果协议上限。每次接受新连接之前调用 expire，并真实关闭返回的 handle。预算拒绝时关闭本次 accepted connection，不临时提高上限，不驱逐正在处理批准的其他连接。排队成功后计费，实际释放字节时退还；close 或 revoke 清掉该连接全部账。退还两次或超过实际排队量要失败，不允许整数下溢。

Pair-Verify 的未验证期限 10 秒，Pair-Setup 的接入窗口最多 60 秒。期限在接纳时固定，收到一个字节、一次错误消息或重传不能自动续期。Pair-Setup 还要求本地已经打开配对窗；网络包不能让屏幕自行弹 PIN。全局 PIN 失败预算继续是 3 次、冷却 300 秒，与连接预算不同，关 socket 不清零失败计数。

## 身份版本跟每次派发走

`promote` 只接受实际验证器成功、peer repository revision 仍有效后的内部调用。这个 reducer 里的 Peer 是已验证事实的载体，不是验证器。接消息时还要核对该 peer 未撤销、连接代次相同、消息序号和方向正确。配对过一次不代表永远拥有操作权；具有遥控能力也不代表可批准命令。

HKDF 的 info 用于区分上下文；本项目继续使用已记录的协议标签和方向分离，不能把两方向 key 合并。HKDF 不负责证明对端是谁，必须接在正确的密钥协商和身份验证之后。[S07](../sources/REFERENCES.md#s07)

## OPACK 的实现范围先冻结

第一批只实现真实互测向量需要的标量、字节串、字符串和容器。建议限制解码深度 16、总节点 4096、整帧沿用 64 KiB；这三者是新增建议，尚未落到生产解码器。对未知标签、无终止符、不完整长度、非法 UTF-8、无效引用、重复键和超预算值返回 typed error，关闭这次会话，不能静默丢字段后继续认证。

不能仅把 JSONDecoder 前面加一个 OPACK 转换器。二进制对象引用表必须保持消息内作用域，编码器与解码器对宽度、去重和容器登记规则要用不同来源的向量核对。当前读到的参考实现有自己的未完成注释，不能把它的所有边界都当成规范。

JSON 也有对象成员名重复、数值范围与实现限制的问题。RFC 8259 要求互操作注意这些差异；本项目应对授权目标采用更严格的重复键拒绝政策，而不是接受两种解释后只签其中一种。当前 WireJSON 仍交给 Foundation JSONDecoder 生成字典；本轮没有添加原始 JSON 重复键预检，不能声称已经拒绝这类输入。它需要在解码丢失重复项之前实现并测试。[S05](../sources/REFERENCES.md#s05)

## Listener 的生命周期施工顺序

先打开 Keychain 并成功读取现有身份，再建立 verifier 工厂和全局预算，再创建 Listener；只有真实协议 profile 和本地启用都满足时才广告服务。网络等待、权限拒绝、端口冲突和地址变更要有独立状态。退出顺序是撤销输入 → 预算 halt → 关闭所有连接 → 停 Listener → 移除服务广告 → 清临时 key。

Keychain 缺项允许用户显式初始化；读失败、访问拒绝或损坏不允许自动重新生成身份。重配相同 ID 需要本地授权和一次性版本绑定操作，不能把公钥悄悄覆盖。墓碑容量达到上限要显示设备管理入口；删除墓碑会影响撤销语义，未经独立设计不能通过清空数组解决。

此篇给出接线顺序和约束。真正的 Listener、OPACK/session、Bonjour profile、Keychain 重配 UI 和原生 Remote 互操作仍未完成。
