# 02　并发仲裁与过期回调

Swift actor 隔离防止同时访问隔离状态，但 `await` 前后的状态仍可能改变。SE-0306 的 Actor reentrancy 部分明确解释了这一点。这里采用它来检查 WindowShade 的生命周期，不照搬提案里的未来语法。[S01](../sources/REFERENCES.md#s01)

## 本次修复：先关闭旧页会绕过优先级

第五份 `WS2IslandCoordinator.show` 先执行 `dismiss()`，再调用 `leases.acquire(...)`。如果当前是 `agentReview` 的审批预览，它尚未进入原生 Touch ID，`authentication.isPresenting` 仍可能为 false。普通页面先把它释放后，协调器只能看到空闲状态，因而正常放行。即使优先级枚举完全正确，这个调用顺序也绕过了它。

第六份给 `InteractionCoordinator.acquire` 增加 `replacing expected: WS2.LeaseHandle? = nil`。只有当前句柄与 expected 完全相等，且两边都是 `.opened`，同级页面才能进行显式导航替换。新申请比旧申请优先级高时仍可抢占。同级审批、普通页抢审批、普通页抢活跃交互均不放行。句柄过期或已经换成另一页时，不准用旧 expected 去关闭新页。

Island 在申请成功并复查 `isCurrent` 后才挂载新 NSView。失败时旧页保留。审批到 Touch ID 的交接仍走已有 `handOffToAuthorization(ifShowing:)`，不能靠同级替换偷渡。原生认证是否正在呈现只是附加检查，不再是唯一的高优先级保护。

## 没有 await 也可能重入

`withdraw` 同步调用旧内容的撤销闭包。撤销闭包可能触发功能禁用、锁态处理、屏幕变化，也可能尝试打开另一页。这是普通函数回调造成的重入，不需要两个线程。

原先 `invalidate` 在 `inTransition` 时直接返回，可能漏掉这种安全撤销。现在过渡中的撤销仍推进 epoch、清空旧状态。外层 acquire 保存进入时的 epoch，撤销回调返回后发现 epoch 改变就终止申请。回调里的新 acquire 仍拒绝，避免半个状态上建立第二套 UI。过渡中的屏幕删除采用全局撤销，宁可让用户重开，也不让内容挂到失效屏幕。

这不是把所有业务都设成最高优先级。一般提醒继续合并成点，不自动复播。普通页面不能以“需要重新布局”为理由关掉审批。审批应通过完整阅读、取消或认证交接结束。

## 跨异步边界的固定检查表

每次排队前保存不可变 ticket。回调回到 MainActor 后依次核对 boot、连接 UUID、项目 revision、实际 thread/turn、输入租约、目标版本、锁态和截止时间。只核对 `self != nil` 不够，因为旧对象可能还活着；只核对布尔 enabled 也不够，因为禁用后重新启用会再次变为 true。

取消任务只表达不再需要结果。执行者必须让晚到结果自证仍属于当前上下文，否则直接丢弃，并且不得改写新页的状态。不要在取消旧任务时立即重用旧 callback ID。测试里应把“取消回调触发另一个取消”“取消后重开”“屏幕删除发生在换页回调里”排成确定顺序，而不是靠运行一百次碰运气。

`MainActor.assumeIsolated` 不是线程切换器。本包保留它的地方都有明确的 `.main` DispatchSource 队列；以后换成默认队列时必须同时改变桥接。对带 actor 的路径使用 Task 切换后，仍要执行 ticket 检查。不要加 `@unchecked Sendable` 来跳过证明。
