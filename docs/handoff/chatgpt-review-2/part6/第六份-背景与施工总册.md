# 第六份：先把一次真实使用走通，再开放更多来源

你接手的是 `WindowShade2-round2-handoff-v6/candidate-repo/`。它是第五份的精确增量合成，不是公开仓库最新 HEAD，也不是已验收的发行版本。用户上传原仓库及 v5 候选保持不变。本轮只在隔离候选中修复代码和补齐可执行的材料。

先读 `CHANGELOG.md`、`VALIDATION.md`、`REMAINING.md`。代码改动只有 manifest 列出的十个文件，五个修改、五个新增；不要重新叠前五份。你实际工作区已经变化时按 baseSHA 三方合并，不用 stage 覆盖。不要另建第二套 AppRuntime、Notch panel、Wire、授权账或设备 callback。

## 可以直接合入的修复

`InteractionCoordinator` 支持携带当前 lease 的原子换页，并保留取消回调期间发生的撤销；`WS2IslandCoordinator` 不再先关闭旧页再请求权限。`CodexWire` 显式设置只读、按请求人工审批，并在 turn 层限制工具网络；具体消息已校验上传的 0.153.0 schema。`build.sh` 修复全新候选缺少 `.build` 父目录的问题。这些先按工单 01 合并和做 Mac 编译，不以 Linux 通过代替 AppKit 检查。

进程通道新增可选的有界 stderr 诊断及直接子进程终止状态。它仍不是完整的进程树监督器。`PROC04` 在本机确实发现继承描述符造成通知延后的问题，报告为 BLOCKED；不要通过放宽断言、删除 fixture 或把 EOF 改叫“全部结束”来交差。

## 第一条独立交付：本地启动并观察 owned Codex

按工单 02 在既有 Runtime 中持有一个明确的 LaunchController。工单给出的 LaunchController 是待实现的接入层，不是假装本包已有该类。它使用新 `WS2OwnedScope` 和 `WS2ProjectDirectory`，从本地选择项目和可执行文件，生成与本次 connection 绑定的 ticket，再创建既有 OwnedCodexSession。锁态、项目、权限和连接变化必须一起撤销 Scope、输入和待批准。

先让 initialize、model/list、新建 thread、开始 turn 和匹配的最终事件走通；UI 显示真正的结果，不只是绿色的“已连接”。收到停止请求先标记停止中，最终事件或真实退出证据到达后再更新。恢复 thread 另查本地项目关联，不能只凭 ID 字符串合法。第一步不依赖 SRP、手机遥控器、私有多触点或窗口效果，别让它们拖住整条路径。

普通命令批准继续经过完整审阅、原生认证和原有 AuthorizationService.consume。不能直接把 Scope、lease、paired 或 input-confirmed 当 grant。文件、网络和持久规则批准尚缺可信范围与展示，继续拒绝。隔离 CLI 配置及外部工具检查仍是生产工作，Wire 的参数不是整台机器的沙盒证明。

## 第二条独立交付：在当前可见列表里完成一次输入

按工单 04 用新 `WS2SelectionModel` 驱动真实的原生列表；保留稳定 ID、revision 和一次性 activation。实际 device host 必须得到当前列表 sink，不能接空闭包或全局 Return。列表变化、中文输入法组合、审批出现、目标切换、断连和锁屏都要取消旧票据及 held 状态。先证明导航与打开选中项，再接摇杆移动窗口。

## 其余两条路径的先后顺序

网络按工单 05：Keychain/peer 仓库可用，确定协议 profile，验证密码学和消息解释，再创建唯一 NWListener。新 `WS2ConnectionBudget` 只负责资源账，不负责验证身份；过期返回的连接句柄要由真实 owner 关闭。OPACK/session、Bonjour 原生兼容和安全重配仍要实现，不能因为有预算核就显示“已配对”。

窗口按工单 06：先改 typed completion 的真实事务落点，再接 FocusEffectExecutor。新收起操作不能直接调用有 toggle 语义的 tuckAll。缺失的 AX 观察返回 unknown；只有实际改变、验证成功且仍属本轮的窗口进入恢复账。工单中的实际窗口端口仍未交付，不能接恒 true 或空执行器。

## 读资料的方法

`docs/01` 从用户可见结果梳理全项目；`docs/02–07` 解释每条调用链为什么这样处理；`docs/08–10` 补身份、隐私、能耗、失败恢复和证据边界。`DECISIONS.md` 定下 44 项工程默认。`sources/code-map.md` 定位本轮 36 份实际源码及符号，JSON 含 SHA256；外部一手资料与适用范围在 `sources/REFERENCES.md`。

不要把这些材料再改写成一份说明来交差。每个小提交应有一个用户能观察的结果、实际调用者、明确关闭路径和失败证据。查不到设备事实时保持该能力关闭，同时继续不依赖它的工作。

## 每次交回什么

交回具体修改路径、运行的完整命令和退出码、原始输出、真实/替身环境、未完成调用者，以及数据有没有新增去向。每项分别标源码、SDK、运行状态。第六份本机新增 56 个 Swift 场景、133 个断言通过，同时 PROC04 的能力要求仍未通过；这两件事必须同时保留。旧回归、Python 工具测试、schema 检查、语法 parse 和实机功能不能混算。

用户没有授权发布、修改更新源、真实 home 配置、远端命令或采集生物数据。原有影片仍是旧无声动态分镜；不要改名当成本轮成片。

# 01　把产品目标接到可验证的结果

本篇是第六份的工程决策。事实基线为第五份的 candidate-repo，具体定位见 `sources/code-map.md`。它不改变原蓝图里的窗口管理、实时活动、能耗、CarPlay 接收、指挥编程、身份和隐私七条方向，也不把尚未做出的功能从清单里删掉。

## 从用户动作开始验收

一个功能需要连成“入口 → 当前事实 → 决策 → 执行 → 实际结果 → 可见反馈 → 退出清理”。类存在、按钮存在或测试有绿色输出，只覆盖其中一段。第六份先处理最容易独立交付的本地助手路径，同时把没有设备也能做的列表选择、总连接预算、源文件组合和故障复现补齐。

|用户要做的事|启动入口必须读的事实|真正完成的证据|不能替代它的东西|
|---|---|---|---|
|开始一次助手工作|本地选择的项目、固定 CLI、当前锁态、会话代次|真实 thread/turn 与最终状态对应，界面显示同一会话|子进程启动成功、队列接受了文字|
|用手柄选择一个项目或模型|当前可见列表的稳定 ID、列表版本、该附件本次启用状态|同一项收到一次 typed action，旧按键不落在新列表|向当前前台程序发送回车|
|专注时收起无关窗口|用户指定范围、窗口身份和当前所有权|真实隐藏被验证，取得与本轮绑定的回执|shaded 字典出现条目、动画到末帧|
|用手机遥控 Mac|服务端角色、真实协议配置、持久身份、双向验证|原生客户端能发现、配对、重连、撤销，消息得到正确路由|用 Python 客户端控制 Apple TV 成功|
|回来时继续工作|系统会话已解锁、最新设备和项目状态|重新取得当前租约，状态重新读取|重播锁屏前缓存的输入|

## 按纵向小闭环合并

第一条提交只修仲裁和退出诊断，不接网络。第二条提交把选择目录、显式启动、会话状态和停止接到现有 Runtime。第三条提交接手柄到现有原生列表。第四条提交才给窗口效果接真实端口。配对、监听和协议解释另做隔离验证，不作为前面四条的前提。

这不减少产品目标。它让用户先得到一条可以实际使用的路径，同时避免一个尚未确认的遥控协议拖住所有工作。合并单位必须小到能够撤回一条路径而保留其余路径。禁止把数据库迁移、UI 主题重做和网络协议接入塞进同一个提交。

## 同一功能要有三栏状态

`source` 表示源码与调用者是否齐全；`build` 表示对应平台是否完成编译和链接；`runtime` 表示真实系统或设备是否验证。三个状态不能相互推导。另设 `release` 表示这一组合是否允许启用；它不是三栏的平均分。

例如，OPACK 解释层现在仍缺源码，Swift PAKE 还缺依赖准入和互测，原生 Remote 还缺互操作。这三个缺口独立存在。把开关默认关掉并不能把 source 改成 complete。第六份新增的 Scope 和 Selection 是可测试的部件，Runtime 和原生列表调用者未接完前仍标 partial。

## 维持单一事实来源

保留 `AgentSessions` 作为会话数据，`CodexWire` 作为当前 owned 连接的协议状态，`AuthorizationService` 作为批准账，`InteractionCoordinator` 作为刘海独占仲裁。新加的 `WS2OwnedScope` 只保存本地项目/连接绑定，不另建线程生命周期。`WS2SelectionModel` 只决定列表选择，不变成助手状态机。`WS2ConnectionBudget` 只核算资源，不产生可信身份。

执行者容易把跨模块缺口补成另一个“Manager”。这会让同一条完成消息在两个地方各触发一次。判断是否需要新类，先问是否存在同一事实的既有持有者；存在时增加明确的输入端口或观察方法，不复制一份状态。

## 交回材料必须能独立复核

每个闭环给出真实文件差异、固定命令、退出码、输入样本、输出样本、最后一次上下文复核的位置，以及停止后的资源状态。照片或视频只能证明它拍到的时刻；通过一套替身测试只能证明那套输入。第六份的 PROC04 是实测发现的阻断项，不能因为其他测试通过就从总表里拿掉。

# 02　并发仲裁与过期回调

Swift actor 隔离防止同时访问隔离状态，但 `await` 前后的状态仍可能改变。SE-0306 的 Actor reentrancy 部分明确解释了这一点。这里采用它来检查 WindowShade 的生命周期，不照搬提案里的未来语法。[S01](sources/REFERENCES.md#s01)

## 本次修复：先关闭旧页会绕过优先级

第五份 `WS2IslandCoordinator.show` 先执行 `dismiss()`，再调用 `leases.acquire(...)`。如果当前是 `agentReview` 的审批预览，它尚未进入原生 Touch ID，`authentication.isPresenting` 仍可能为 false。普通页面先把它释放后，协调器只能看到空闲状态，因而正常放行。即使优先级枚举完全正确，这个调用顺序也绕过了它。

第六份给 `InteractionCoordinator.acquire` 增加 `replacing expected: WS2.LeaseHandle? = nil`。只有当前句柄与 expected 完全相等，且两边都是 `.opened`，同级页面才能进行显式导航替换。新申请比旧申请优先级高时仍可抢占。同级审批、普通页抢审批、普通页抢活跃交互均不放行。句柄过期或已经换成另一页时，不准用旧 expected 去关闭新页。

Island 在申请成功并复查 `isCurrent` 后才挂载新 NSView。失败时旧页保留。审批到 Touch ID 的交接仍走已有 `handOffToAuthorization(ifShowing:)`，不能靠同级替换偷渡。原生认证是否正在呈现只是附加检查，不再是唯一的高优先级保护。

## 没有 await 也可能重入

`withdraw` 同步调用旧内容的撤销闭包。撤销闭包可能触发功能禁用、锁态处理、屏幕变化，也可能尝试打开另一页。这是普通函数回调造成的重入，不需要两个线程。

原先 `invalidate` 在 `inTransition` 时直接返回，可能漏掉这种安全撤销。现在过渡中的撤销仍推进 epoch、清空旧状态。外层 acquire 保存进入时的 epoch，撤销回调返回后发现 epoch 改变就终止申请。回调里的新 acquire 仍拒绝，避免半个状态上建立第二套 UI。过渡中的屏幕删除采用全局撤销，宁可让用户重开，也不让内容挂到失效屏幕。

这不是把所有业务都设成最高优先级。一般提醒继续合并成点，不自动复播。普通页面不能以“需要重新布局”为理由关掉审批。审批应通过完整阅读、取消或认证交接结束。

## 跨异步边界的固定检查表

每次排队前保存不可变 ticket。回调回到 MainActor 后依次核对 boot、连接 UUID、项目 revision、实际 thread/turn、输入租约、目标版本、锁态和截止时间。只核对 `self != nil` 不够，因为旧对象可能还活着；只核对布尔 enabled 也不够，因为禁用后重新启用会再次变为 true。

取消任务只表达不再需要结果。执行者必须让晚到结果自证仍属于当前上下文，否则直接丢弃，并且不得改写新页的状态。不要在取消旧任务时立即重用旧 callback ID。测试里应把“取消回调触发另一个取消”“取消后重开”“屏幕删除发生在换页回调里”排成确定顺序，而不是靠运行一百次碰运气。

`MainActor.assumeIsolated` 不是线程切换器。本包保留它的地方都有明确的 `.main` DispatchSource 队列；以后换成默认队列时必须同时改变桥接。对带 actor 的路径使用 Task 切换后，仍要执行 ticket 检查。不要加 `@unchecked Sendable` 来跳过证明。

## 本次与未完成边界

ARB01–ARB12 覆盖协调器的合成事件和同步重入。Island 的实际 NSView/NotchPanel 仍待 Mac SDK 编译与真机测试。测试证明新的仲裁规则，不证明整个刘海界面所有布局和认证动作都正确。

# 03　进程停止、诊断与结果语义

本篇依据实际 `WS2DuplexProcess`、第六份本地 Python 子进程测试，以及 Swift Foundation `Process.swift` 的实现观察。Foundation 源码仅解释实现线索，不能代替当前平台的运行证据。[S02](sources/REFERENCES.md#s02)

## 五个不同的完成点

|状态|可以显示什么|绝对不能推导什么|
|---|---|---|
|界面接受草稿|已准备|后端已收到|
|有界队列接纳|正在发送|系统已写完|
|所有字节写进本地管道|等待助手响应|请求已执行或已获批准|
|收到匹配 RPC response|按该方法解释响应|turn/interrupt 的响应不等于整个 turn 已结束|
|收到匹配最终事件|按最终 status 显示完成、停止或失败|不能把任何 turn/completed 都显示成成功|

当前官方 App Server 文档仍区分 thread、turn、通知和请求响应。本项目运行协议保持上传的 0.153.0 快照；当前网页用于校对概念，不允许把网页新字段混入旧绑定。[S03](sources/REFERENCES.md#s03)

## 停止必须先撤销，再关闭通信

本地停止、项目变更、锁屏、睡眠或权限丢失时，先使 Scope ticket 和待批准账失效，再停计时任务和发送队列，取消所有尚未消费的输入，最后关闭管道并请求直接子进程退出。关闭通信后，界面可显示“已断开”；还没有直接子进程退出证据时，不显示“全部进程已结束”。

批准的消息一旦部分写出，既不能撤回，也不能在新连接重发。第六份继续保留每批次的最终 write gate、FIFO 偏移和不重试原则。失败时要保留“结果未知”，而不是为了给用户一个绿色状态把它改成“已取消”。即使用户再点一次，也要重新阅读实际请求并产生新的授权。

## stderr 的实用折中

默认仍写到 null device，不在后台积累命令、路径或模型输出。本次增加每次启动显式选择的 `diagnosticByteLimit`，范围 1…65536 字节；省略时完全不保存。诊断与 stdout 用独立非阻塞读取，各次回调最多读 65536 字节，避免错误洪水卡住输入或界面。

保存的是最后一段内存尾部，不是完整日志。`observedBytes` 只表示本进程实际读到了多少；`droppedBytes` 只表示这些已读字节中有多少不再保留，不能据此宣称子进程一共输出了多少。退出时只追加一次有上限的读取。清除数据不承诺 Swift 分配器做了密码学级内存擦除。

显示使用纯文本，转义终端控制码和双向控制字符；不经过 Markdown、HTML、终端模拟器或自动链接执行。诊断内容仍可能含密钥，转义不等于脱敏。复制、保存和发送给模型都应由用户单独发起，并先展示将要分享的内容。

## 这次真实发现的失败：继承描述符延迟退出通知

`PROC04` 的父进程写一行后退出，子孙进程持有 stdout，0.8 秒后再写一行。本机 Linux 上，观察到约 0.81 秒才结束，两行都被读取。退出通知没有在预期的父进程退出时立即到达。因此“退出后最多 200ms 收尾”只能从 Foundation 实际送达通知时算起，不能描述成从内核父进程退出时算起。

`tests/run-exit-probe.sh` 在当前环境返回 2，报告 BLOCKED。这是未闭合的能力验证，不是通过测试，也不是计划性的故障注入成功。其他九个管道场景通过不能抹掉它。

## 后续怎么解决，不让执行者猜

Mac 首先原样跑该探针，记录 OS 构建号、SDK、Swift、直接子进程状态以及两次回调时刻。若同样失败，需要独立的进程监督端口。推荐在隔离 helper 中使用自己创建并拥有的进程组、自己负责的 wait/reap 和停止升级策略，而不是偷读 Foundation 正在负责的 waitpid；两套 reaper 不得竞争同一个子进程。

监督端口至少提供 starting、running、stopRequested、directChildExited、treeUnknown 五类事实。创建进程组是否成功需要实际证据，不能假定 Process 的内部实现永久保证。禁止保存一个旧 PID 后延迟 `kill(pid)`，禁止对用户原有终端会话 `kill(-pgid)`，禁止全局忽略 SIGPIPE 来掩盖问题。不能把进程名相同的其他 Codex 全部杀掉。

本包没有实现这个 helper，也没有强杀进程树。本机测试用的短命子孙进程会自行退出，测试另留等待窗口避免残留。批准路径在本机尚不得以“直接子进程退出可被即时准确观察”为能力依据。

# 04　本地项目范围与助手权限

## cwd 字符串只是一条路径

`/work/repo` 与 `/work/repo-backup` 有相同前缀，但后者不是前者的子目录。目录被删除重建后，路径没有变，文件对象已经换了。符号链接又可能把用户看见的路径指向另外一个位置。第六份的 `WS2ProjectDirectory.read` 记录解析后的绝对路径、设备号和 inode；`contains` 按路径分隔边界比较，拒绝未解析的 `..`。

这个观察仍然不是文件系统沙盒。目录在检查后还可能被替换，子目录里的链接也可能变化，CLI 还可能根据配置读取其他路径。因此 Scope 的作用是防止旧 UI/旧连接跨项目，不能把它宣传为文件系统访问隔离。不要使用 `hasPrefix(root)` 决定网络请求是否可以访问任意文件。

## 本地选择与不可变 ticket

项目只能来自本机目录选择器及其实际读取结果，不能从 CLI payload、蓝牙设备名或远端路径字符串创建。持久 projectID 用本地 UUID；名称只用于显示，不参与判定。恢复上次选择时重新读身份，身份不匹配就请用户重新选择，不能悄悄跟随被替换的目录。

`WS2OwnedScope` 初始 locked/disabled，没有 active ticket。用户启用后由 Runtime 写入实际环境；每次 select、begin、invalidate、锁态或 enabled 变化均清除旧 ticket 并推进 revision。重新解锁只改变环境，不复活旧连接。`context` 只在当前 ticket 与实时目录身份一致且 backend session 合法时返回既有 `WS2.Context`，继续复用共享类型。

根目录观察可能发生磁盘 I/O，不要在每个摇杆采样中调用。推荐在选择、启动、批准准备及最终提交前的独立校验阶段读取，并通过统一 revision 撤销路径变化。频繁写入循环仍要复核缓存 ticket 和锁态；缓存不能被文案称为再次读取了磁盘。主模型需要明确接受剩余路径竞争，或者引入具备目录句柄约束的监督端口。

## 本次修复：不继承宽泛的助手设置

第五份 `CodexWire.startThread` 只传 cwd/model，resume 只传 threadId。实际生效的执行权限因此可能依赖外部配置。第六份给新建和恢复 thread 明确传 `sandbox:"read-only"`、`approvalPolicy:"on-request"`、`approvalsReviewer:"user"`。开始 turn 时明确传 readOnly 的 sandboxPolicy，networkAccess=false，并重复人工 reviewer 和按请求审批。

这组字段由上传的 0.153.0 schema 实际核对，四条真实编码出来的 params 通过 schema 检查。它是本项目 V1 保守配置，不是对 Codex 所有版本的事实承诺。没有运行真实 CLI，所以未宣称沙盒实际执行、平台后端或自定义工具都受到了验证。

read-only 并不等于只允许读当前项目；networkAccess=false 也不能描述成整个宿主应用离线。模型服务连接与工具执行网络是不同路径。MCP、外部工具、技能和用户配置需另做准入，第一条真实闭环只使用隔离的、已检查配置。读取配置后发现功能无法收窄时停止启动，不用“相信用户配置”让这条验证通过。

## 普通命令的一次性批准

继续由 `WS2CodexApprovalHost` 展示完整原始命令、cwd、上下文，再交原生认证和 `AuthorizationService.consume`。Scope、设备已配对、按键新鲜、UI 有租约都不产生批准权。固定 profile 不撤销已有的逐条批准设计；它不允许自动 reviewer 替用户作决定。

文件 diff、网络范围和持久规则批准仍未得到完整可信 UI 与 scope。遇到这些请求按已有拒绝策略处理，并显示具体不支持的种类。不要生成空 diff 后称用户批准过文件内容；不要把一次命令批准升级成整目录写权限。

恢复 thread 还有额外工作：验证返回的 thread 与本地项目关联、配置和本次连接一致。Wire 对 thread ID 的检查无法替代这些事实。缺关联证据时允许从本地新建安全 thread，不自动恢复一个看起来名字相同的旧 thread。

# 05　原生列表输入与人的操作预期

手柄或遥控器输入的目标是用户当前看得见的一项操作。它不应取决于此刻哪个应用碰巧拿到了键盘焦点。这里的设计保留前几份“多输入来源 → 同一语义意图”的方向，先让原生列表可靠，再增加窗口运动与节拍识别。

## 稳定身份比索引重要

实时会话插到列表顶部后，昨天的第 2 项已经不是今天的第 2 项。新 `WS2SelectionModel` 保存稳定 itemID 和 snapshot revision。替换列表时尽量保留原 ID；原项消失或被禁用后，选择第一项可用内容；空列表的选择为空。重复 ID、过大的列表或超长 ID 直接使输入模型失效，不能继续激活旧内容。

最大 512 项和 ID 最多 512 UTF-8 字节是工程上限，不是 UI 建议显示 512 行。大型资料要分页或过滤，原生列表每屏仍保持可读。手柄移动只接受 -1 或 +1，跳过 disabled 行，到边缘停止，不循环跳到另一端。这样用户连续按住也不会在一轮滚动后误落到开头的危险项。

## 确认分为预约和消费

按键按下、松开、UI 出现和列表更新可以交错发生。已有 `WS2SemanticInputRouter` 负责附件和 pressID；新 SelectionModel 负责列表内的目标版本。两者相接时，先验证输入 ticket，再以当前 revision 预约 Activation，最终在本地 typed sink 消费 Activation 得到稳定 itemID。

同一个 Activation 只能消费一次；期间换页、刷新列表、移动选择、禁用、锁屏或撤销均使它失效。它不是 AuthorizationGrant，所以不得传到命令批准或系统解锁。普通列表激活会打开模型详情或会话页；真的发送新 turn 还应走草稿/配置成本确认及本地 scope 检查。

## 原生视图的具体约束

现有 NSView 由 Island 的同一租约持有。更新内容不新建另一份窗口，不在每秒 tick 中销毁重建列表，不在每个 valueChanged 中抢 key window。键盘、鼠标与手柄共享同一 selection store，鼠标点某行也更新稳定 ID。屏幕阅读器的焦点与可见选择需要在同一个更新批次内协调，禁止悄悄激活未滚入视口的行。

选择变动只更新旧行和新行，列表数据改变才计算差量。草稿输入中要保护中文组合输入；存在 marked text 时，远端确认不能被当作提交草稿。按 Esc 是取消本次交互，不应顺带杀掉仍在后台运行的助手任务。切换项目前应明确显示将断开当前连接。

## 持续动作必须有停止边

按钮是离散事件，摇杆是持续量。不要把它们统一成一串重复按下。对于任何持续窗口运动，必须定义 began/changed/ended/cancelled，目标在 began 固定。断连、租约撤销或目标消失都会产生 cancelled，并归零输出。归零要发给确切附件或运动执行器，不遍历操作所有控制器。

死区、重复间隔、曲线、触觉强度都是建议参数。没有设备测试前不宣传“零误触”。保持一次启用一个附件的既定约束；同一型号、同名设备和重新插入的对象不继承旧许可。审批出现时停止输入，不让手柄的 A 键兼作 Touch ID 批准。

## 先做到的可见结果

一条可以验收的路径是：用户本地启用手柄 → 打开现有会话列表 → 上下选择 → 当前可见项打开 → Esc 关闭交互 → 所有旧按键失效。它不要求先完成配对协议、WindowServer 效果或节拍分类。第六份只交 SelectionModel 和测试；NSTableView/现有卡片的实际 sink 仍按施工单接入，不声称已经能用手柄操作桌面。

# 06　配对网络与资源预算

## 把发现、身份和动作分开

mDNS/Bonjour 提供发现机制，不能用服务名替代配对密钥。RFC 6762 的安全讨论说明链路内发现仍有信任边界。对本项目而言，搜索结果里出现一台设备，最多说明收到了一条候选广告。[S06](sources/REFERENCES.md#s06)

先保持 Mac 作为目标协议服务端的方向。pyatv 的 OPACK 源码是格式观察来源，不是 Apple 对 Mac 接收原生 Remote 的兼容承诺；它本身也注明未覆盖所有格式。第六份没有将其源码或依赖并入候选，未完成部分仍以独立原创实现和实际向量验证为准。[S04](sources/REFERENCES.md#s04)

## 为什么单连接有界还不够

第五份每条 TCP 有自己的队列，但十条连接各分配一个队列仍会一起占用资源。第六份新增 `WS2ConnectionBudget`，让唯一 Listener owner 在创建传输前核算总容量：总连接 8，未验证连接 2，同一已验证 peer 同时 1，单连接排队 256 KiB，总排队 512 KiB。

这些是初版预算，不是苹果协议上限。每次接受新连接之前调用 expire，并真实关闭返回的 handle。预算拒绝时关闭本次 accepted connection，不临时提高上限，不驱逐正在处理批准的其他连接。排队成功后计费，实际释放字节时退还；close 或 revoke 清掉该连接全部账。退还两次或超过实际排队量要失败，不允许整数下溢。

Pair-Verify 的未验证期限 10 秒，Pair-Setup 的接入窗口最多 60 秒。期限在接纳时固定，收到一个字节、一次错误消息或重传不能自动续期。Pair-Setup 还要求本地已经打开配对窗；网络包不能让屏幕自行弹 PIN。全局 PIN 失败预算继续是 3 次、冷却 300 秒，与连接预算不同，关 socket 不清零失败计数。

## 身份版本跟每次派发走

`promote` 只接受实际验证器成功、peer repository revision 仍有效后的内部调用。这个 reducer 里的 Peer 是已验证事实的载体，不是验证器。接消息时还要核对该 peer 未撤销、连接代次相同、消息序号和方向正确。配对过一次不代表永远拥有操作权；具有遥控能力也不代表可批准命令。

HKDF 的 info 用于区分上下文；本项目继续使用已记录的协议标签和方向分离，不能把两方向 key 合并。HKDF 不负责证明对端是谁，必须接在正确的密钥协商和身份验证之后。[S07](sources/REFERENCES.md#s07)

## OPACK 的实现范围先冻结

第一批只实现真实互测向量需要的标量、字节串、字符串和容器。建议限制解码深度 16、总节点 4096、整帧沿用 64 KiB；这三者是新增建议，尚未落到生产解码器。对未知标签、无终止符、不完整长度、非法 UTF-8、无效引用、重复键和超预算值返回 typed error，关闭这次会话，不能静默丢字段后继续认证。

不能仅把 JSONDecoder 前面加一个 OPACK 转换器。二进制对象引用表必须保持消息内作用域，编码器与解码器对宽度、去重和容器登记规则要用不同来源的向量核对。当前读到的参考实现有自己的未完成注释，不能把它的所有边界都当成规范。

JSON 也有对象成员名重复、数值范围与实现限制的问题。RFC 8259 要求互操作注意这些差异；本项目应对授权目标采用更严格的重复键拒绝政策，而不是接受两种解释后只签其中一种。当前 WireJSON 仍交给 Foundation JSONDecoder 生成字典；本轮没有添加原始 JSON 重复键预检，不能声称已经拒绝这类输入。它需要在解码丢失重复项之前实现并测试。[S05](sources/REFERENCES.md#s05)

## Listener 的生命周期施工顺序

先打开 Keychain 并成功读取现有身份，再建立 verifier 工厂和全局预算，再创建 Listener；只有真实协议 profile 和本地启用都满足时才广告服务。网络等待、权限拒绝、端口冲突和地址变更要有独立状态。退出顺序是撤销输入 → 预算 halt → 关闭所有连接 → 停 Listener → 移除服务广告 → 清临时 key。

Keychain 缺项允许用户显式初始化；读失败、访问拒绝或损坏不允许自动重新生成身份。重配相同 ID 需要本地授权和一次性版本绑定操作，不能把公钥悄悄覆盖。墓碑容量达到上限要显示设备管理入口；删除墓碑会影响撤销语义，未经独立设计不能通过清空数组解决。

此篇给出接线顺序和约束。真正的 Listener、OPACK/session、Bonjour profile、Keychain 重配 UI 和原生 Remote 互操作仍未完成。

# 07　窗口效果是外部事务

窗口在另一个进程里。WindowShade 记录了一个意图，与该窗口真的隐藏、其应用仍存在、用户没有手动改变它，是几件不同的事。本篇基于现有 `FoldTransaction.swift`、`FoldCompletion.swift`、`WS2FocusEffectPlan` 和 executor 的实际代码；定位在 code-map。

## 不能把旧 Bool 当作新回执

当前 `hideTookEffect` 的 offscreen 分支在读不到 AX 几何时返回 true；hidden 分支在找不到 runningApp 时也默认 true。这是旧路径里的既定行为，但它不适合直接作为新番茄钟“我确实完成了隐藏”的证据。

第六份没有冒险直接改变所有旧窗口功能。给新端口的要求是另外建立三态观察：verifiedHidden、stillVisible、unknown。缺失 AX 元素、权限丢失、读超时、目标进程退出或无法核对身份均为 unknown。unknown 不登记所有权回执，也不意味着窗口一定还显示着；它可能已经被隐藏，需要恢复核对。

## 回调要绑到哪一次事务

`registerFoldWaiter` 给单个等待者 UUID，单 token 的超时结算可以避开后来的等待者；但 `settleFoldWaiters(id:success:)` 是按 windowID 批量结算。新 T3 端口不能只注册一个 windowID waiter 就假定回调来自自己的 foldTransactionID。

端口需捕获窗口完整身份、foldTransactionID、timer run、effectGeneration、beforeRevision 和自己的 waiter token。任何结算前重新核对实际 ShadeState 的事务 ID；旧事务晚到的成功只进入旧事务恢复核对，不能结算新事务。窗口 ID 和 PID 可能重复使用，所以当前身份还要带进程开始标记与 windowGeneration。

## 一次写入前后的具体步骤

先观察并确认窗口属于用户指定的目标集，保存 beforeRevision，注册属于这次事务的完成等待，再执行隐藏。完成回调返回后确认身份没有变化，读取实际隐藏结果，只有 verifiedHidden 和 afterRevision 大于 beforeRevision 时才创建 Receipt。Receipt 保存的是这次动作的归属，不是当前所有窗口的快照。

如果等待超时，在执行器中标为 unknown 并暂停该窗口后续效果。不要在 timeout 分支自动再调用一次收起；旧动作可能稍后才生效。晚到成功需要触发一次恢复核对，而不是丢弃后让窗口永远留在屏幕外。目标已经换成用户手动状态时，取消本程序的自动恢复权，保留用户最新操作。

## 恢复不能越权

恢复前比较 receipt.run、effectGeneration、身份以及 liveRevision。任何一项不匹配都不直接移动窗口。恢复成功同样需要 afterRevision 递增并验证可见/几何状态。不要先把 receipt 删除再假称动作完成；一次性取出之后失败，需要保留独立的 reconciliation 记录。

应用退出、睡眠、锁屏和崩溃不是同一种退出。正常退出可以停止新动作并核对已持有 receipt。锁屏时不要为了清理而突然唤起被隐藏的私人窗口。崩溃恢复需要持久 journal 和身份核对；第五份 executor 没有跨重启 receipt，不能借用“内存里曾经有过”承诺崩溃可恢复。

## 建议 journal 事务，不在本轮伪装实现

追加 prepare 记录后才尝试写入；记录 attemptID、窗口身份、前后状态摘要、phase 和校验，不保存窗口标题或截图。动作观察明确后追加 committed 或 unknown。重启先按现有 journal 机制对照活窗口，不凭陈旧坐标重放。写 journal 失败时禁用新自动效果并保留用户原状态，不跳过持久化直接执行。

这需要与原工程的恢复机制共同设计，不能另建一个互相竞争的 restoration manager。第六份只锁定接口与错误分支；实际 AX/恢复端口和 typed completion 仍是源码缺口。

## 用户看到的结果

计时开始不必等所有窗口动画结束。界面可以显示“正在收起窗口”；遇到少数目标失败，计时继续，提示“部分窗口未能收起”，不要自动停整个番茄钟。尚未接实际端口时写“仅计时”，相关自动效果控制不可用。25/5、50/10 和修改预设只影响下一轮的既有规则不变。

# 08　身份信号、隐私与安全默认

## 不把更多传感器当作更多身份因素

当前任务涉及 Touch ID、人脸、声纹、心率、蓝牙和手势。它们不具有同一证据强度。设备名称、RSSI、出现过的地址、手的移动和心率不能证明某把私钥仍由用户持有，也不能单独绑定这条具体命令的同意。

NIST SP 800-63B-4 将生物特征视为敏感且非秘密的测量，要求在其适用体系中配合物理认证器，并要求人脸呈现攻击检测；该版本不允许基于声纹的生物比较用于该认证体系。这是安全设计参考，不等于本项目获得认证，也不是断言所有桌面应用必须符合它。[S08](sources/REFERENCES.md#s08)

本项目继续以系统已解锁和原生授权账为执行门槛。人脸和语音研究可以作为独立、默认关闭的实验，不得把“检测到脸”接成“系统解锁成功”，也不得自动输入系统密码。心率没有一条受验证协议能把“紧张”映射成设备不属于操作者；这类推断不进入授权判断。

## 把辅助证据用在合适的地方

蓝牙离开可以降低在场置信度，导致取消输入或缩减功能，不能直接证明用户离开，也不能让另一设备自动取得权限。无数据和低电量不等于身份失败。设备读数陈旧应显示未知，不显示零。相机被遮挡、麦克风权限被拒绝或传感器断开，都允许用户继续使用不依赖该传感器的功能。

风险指标适合触发额外确认，不适合降低原有确认要求。一次配对证明的是建立设备关系的那次过程；一次按键证明的是某个已接纳附件传来输入；一次 Touch ID 证明的是系统返回的一次认证结果。最终批准还要完整目标、期限和授权账的一次性消费。

## 让执行者能实施的数据最小化

默认不保存帧、音频、声纹模板、完整命令日志或应用标题历史。设置页列出来源、使用目的、保存期限、是否离机、关闭后的清理动作。新增诊断尾部是第六份唯一新增的数据保留通道：仅用户本地为本次启动显式开启、内存有上限、默认不导出，不能自动附进错误上报或模型上下文。

Keychain 读取错误不得在普通日志输出完整 item 内容。随机测试私钥只能放 fixtures，不能作为首次初始化失败时的备用身份。日志里记录本地关联号和错误类别，不写 PIN、共享密钥或原始认证载荷。

## 对照检验矩阵

人脸实验必须在明确同意的参与者与预先固定阈值下分别记录真正匹配失败和错误接受，不能用同一批样本调参后又充当独立测试。照片、屏幕重放、视频、变化光照和不同姿态属于不同验证条件；没有测过的条件保持未知。不能从“在我脸上试了十次都成功”推断可替代系统认证。

系统锁/解锁后端同样需要独立证据：请求发出了、动画完成了和系统登录会话真的锁定，分别记录。测试期间保留人工恢复手段。错误恢复不通过尝试更多私有接口、持续输密码或隐藏安全提示解决。

# 09　性能、能耗与渐进启用

本篇的所有数值是建议预算或继承的项目默认，不是实测功耗。运行报告不得把它们写成性能成绩。

## 对吞吐量和交互延迟分别设账

本项目的活动数量不大，但窗口采样、控制器回调、屏幕截图和模型事件可能同时到来。逐个小对象分配和重复重建 UI 会让“单次不慢”的工作叠在一起。建议 MainActor 一次只做边界核对、轻量 reducer 和差量呈现；图像、模型、压缩和重计算不放在按键回调里。

第六份进程每次读写 readiness 的预算 64 KiB，诊断保留最多 64 KiB，网络总排队 512 KiB。公平回调预算控制一次占用，保留上限控制内存，它们不是同一个数值。达到队列上限时采取背压或关闭该连接，不能静默丢一半批准帧后继续发送。

## 把持续唤醒变成按需唤醒

番茄钟显示可以一秒更新一次，离屏后停止绘制，不需要每帧运行整个状态机。截止任务按最早待处理事件安排，不每 10ms 扫描所有模块。网络活跃时保留读事件，功能关闭时移除 Listener、Source 和 handler。手柄关闭后不继续采集运动数据来更新不可见视图。

截图、窗口列表、菜单标题缓存和设备读数分别设刷新原因；一个窗口名称变化不应触发所有屏幕重新截图。先追踪重复注册的观察者、取消不了的 Task、永远不清的 handler 和 NSView，再讨论微小算法优化。这些长期对象在“设置默认关闭”的情况下仍可能工作。

## 可重复的对照方案

同一台 Mac、同一 OS 和构建、同一电源条件、相同显示器与外设、相同后台应用，交替运行原 1.0.15 基线和当前候选。先采空闲，再采正常使用和故障条件；每种条件建议三次。记录 wall time、CPU time、wakeups、内存、数据率和可见卡顿，并保留原始工具输出及采集命令。

建议每段十分钟，预热两分钟；这是为了减少一次短峰值的误导，不保证统计充分。不要比较不同机器截图里的 Energy Impact 数字后宣称降低了百分之几十。外设断连、拒绝权限、后台没有客户端、锁屏及睡眠恢复也要跑，因为泄漏常出现在非正常路径。

## 功能准入按真实能力，而不是一把总开关

每个功能保存 source/build/runtime 三种证据。UI 的 availability 由事实产生：设备不存在、权限未给、后端尚未启动、目标不存在、能力未实测、正在认证、正在停止，应有不同原因。显示不可用的原因即可，不因一个模块未准入而把无关的计时器也关闭。

稳定的第一条 owned CLI 路径可以独立启用，配对实验保持关闭。只读查询先验证，命令批准后验证，设备控制再验证。退出失败的模块可以撤回入口但不能把残留状态删掉；用户仍需要看到是否可能有后台任务未结束。

## 编译门禁也要如实

原 `build.sh --check` 实际包含 Metal、优化 Swift 编译和链接，并非简单 typecheck。本次修正说明并为干净目录补 `.build` 创建，避免 mktemp 的父目录不存在。脚本是否解析正确与 Mac 链接是否通过分开记录。

检查需要 Sparkle 时应准备真实框架，不为了过门禁把它的相关文件排除后仍称完整 App 已构建。新的 Foundation 文件已经在 Linux 严格 Swift 6 下组合检查；这不能覆盖 Network、Cocoa、Security、CryptoKit 或私有 SDK 分支。

# 10　故障恢复与交付可信度

## 用反例保护后续实现

每个状态边界至少一个反例：恰好到期、刚锁屏、相同名字不同设备、旧连接回复、列表换序、目录重建、写一半断管、Keychain 写失败、AX 读不到、同一确认消费两次。反例不要求概率高；它用来证明实现依赖的是正确事实，而不是理想顺序。

安排反例时使用注入时钟和受控事件序列。需要真实系统语义的地方再用子进程、文件系统和设备测试。不能把所有测试换成 Fake 系统然后得出端到端结论。第六份目录测试真实创建符号链接和替换目录；管道测试真实运行 Python；两者都没有操作用户 home、真实 CLI 或桌面窗口。

## 正向通过、预期拒绝和未通过验收要区分

错误基线被 stage 工具拒绝是保护机制正常；这是预期负例。PROC04 要求尽早识别直接子进程退出，却观察到延迟，是功能验证缺口。它不能写成“成功验证能够失败”后算通过。没有 Mac 的 runner 返回 78 是未运行，不是失败也不是通过。依赖下载失败是准备失败，不是编译错误。

`tools/readiness.py` 对证据文件检查来源版本、真实命令、状态、运行环境、日志路径及哈希。它只能确保材料齐备并且相互对应，不能自动判断一段日志是否证明安全行为。因此自测 fixture 的 PASS 不允许替代 Mac/hardware 阶段；手工审核的结论要有责任人和记录。

当前官方文档、当前库 HEAD 与上传 schema 是三个不同版本来源。执行者不能为解决一个字段报错自动升级 CLI 或引入主干依赖。新版本单列兼容分支：读取该版本实际 schema，生成差异，更新 fixtures，跑允许与拒绝两种响应，然后实际连接。未得到兼容证据前保留已固定版本。

已有两条 126 秒无声动态分镜只是以前的成果。第六份没有新增成片、声音或真机录屏。任何新功能只有满足源码、平台和实际路径证据才允许拍成能力演示；否则继续标概念或待录。不能用本次修好的纯核心生成假的“配对成功”“已解锁”画面。

# 工单 02　owned 助手的本地启动闭环

## 目标与文件

让用户在本机明确选择项目后，从现有刘海入口启动、查看并停止一个 owned Codex 会话。禁止自动启动 CLI、修改真实 home 配置或启动第二个平行状态机。修改 `prototype/App/WS2AppRuntime.swift`、`WS2SupplementPane.swift`、`WS2OwnedCodexSession.swift`、`WS2AgentSessionView.swift`、`WS2CodexApprovalHost.swift`。复用 Core/AgentSessions、CodexWire、WS2OwnedScope 与 Support/WS2ProjectDirectory。新增协调文件建议 `prototype/App/WS2OwnedLaunchController.swift`；这是待编写的调用者，本包没有把它计为已实现。

## 强持有关系与唯一实例

AppRuntime 持有一个 LaunchController，后者持有一个 Scope、零或一个 OwnedCodexSession，以及现有 AgentSessions 的入口。Island 由原 Runtime 持有，不由每个 session 创建。所有观察闭包 weak 捕获 owner；stop 先取消业务观察，再断管，最后释放强引用。旧 onEnd 必须比较 connectionID 后才能清空当前 owned 属性。

OwnedCodexSession 的 connectionID 当前在构造时生成。先构造候选 session 但不 start，再用该 connectionID 调 Scope.begin，保存 ticket 和强引用，最后 start。构造失败或 begin 返回 nil 就 stop 候选并返回；不可通过先启动来获得一个 ID。

## 本地入口逐步落地

1. 在现有补充设置页增加“选择项目…”和“启动 Codex”，运行后改为“打开会话”和“停止会话”。初始显示“尚未启动”，不创建假会话行。
2. 目录选择只接受本地目录。读规范路径/设备/inode，保存本地 UUID；显示完整路径供核对，按钮名称用短名称。
3. 在独立预检流程确认实际 executable 路径、可执行文件、版本与固定 0.153.0 协议适配。环境使用明确 allowlist 和本地配置，不把网络载荷当启动参数，不用 shell 拼接。
4. Scope.environment 写入真实 unlocked/enabled。建立 session、Scope ticket、闭包和强引用，再调用 start。
5. 协议处于 initialize/model-list 时显示“正在连接”；Wire.ready 才开放模型选择。只列真实 model 和该项支持的 effort。不要硬编码当前最强模型名称。
6. 收到绑定 thread 后才把它加入 AgentSessions。初始化阶段的 loading 不伪造成一个后端 session。对每条 onEvent 先核对 session.connectionID、Scope ticket 与当前 Wire 的 thread/turn，再更新既有 store。
7. 用户发送草稿经过一次明确动作。线程未就绪、中文 marked text 未提交或模型/effort 未选定时拒绝，保留草稿。

## 三个闭包不能用恒 true

`mayOperate`：当前 instance 与 ticket 相符、用户仍启用、系统已解锁、项目身份未失效。未知锁态返回 false。

`currentContext`：只使用当前后端产生的有效 session key 调 Scope.context。它可在初始化阶段为 nil，审批阶段必须有值。不能提前填一个随机 thread ID 冒充后端事实。

`scopeStillValid(review)`：核对 review 的完整上下文、cwd、项目、当前 thread/turn 与剩余期限。cwd 的规范解析结果必须是用户选择范围内的允许位置；发现符号链接或目录身份变化时先撤销。实际沙盒边界仍由受验证后端负责，路径辅助函数不负责权限隔离。

## 权限与状态决策

Wire 现在对 thread/start、thread/resume 和 turn/start 写明只读起步、on-request、user reviewer。模型返回 completed 通知时读取 status，失败、取消和成功分别显示。不要在 onLocallyWritten 里显示完成。

批准保持完整 review → 原生认证 → consume → 一次性编码 → 同代次 writer。文件、网络和持久规则路径仍明确不支持。当前已有审批列表但未自动绑定可见行时，只能显示待处理并由本地用户打开，不得默认接受或推送到另一处假设存在的原生弹窗。

## 必须同时接的撤销来源

现有 Runtime 的 locked/unknown、sleep、enabled=false、project change、session change、stop 和退出均先调用 Scope.invalidate，再停止 OwnedCodexSession，清当前待处理 UI。解锁不重启进程，用户点启动才创建新代次。后台会话完成不能关闭别的 feature 后来打开的 Island 内容。

## 最小端到端验收

使用用户允许的临时项目和隔离配置，先启动只读无副作用查询；验证真实版本、model/list、thread/start、turn/start、最终状态和停止。然后测试真实取消、锁中晚回调、目录替换、模型列表分页和旧会话回复。最后才测试一条无副作用普通命令的真实人工批准与拒绝。将真正运行样本与本包合成 fixtures 分目录保存；任何一步缺失都不能标为闭环完成。

## 原始 JSON 的额外边界

本轮 WireJSON 仍由 Foundation JSONDecoder 建字典，没有新增重复键预检。开放允许路径前，在完整、限长的原始帧上验证对象键唯一，递归对象都适用，再交既有解码器；不能在字典生成后检查重复。键比较按 JSON 字符串解码值进行，`"id"` 与 `"\u0069d"` 是同一键。仅在同一对象内拒绝重复，两个不同嵌套对象各自使用 id 应允许。不要用正则表达式检查整个 JSON 语法。

至少测试：两次 id；两次 params；转义后相同的 command 键；嵌套对象重复；字符串内出现字面冒号和引号；不同对象复用键；截断输入；超过深度上限。失败时关闭该协议会话并撤销待批准，不从两份值中随意挑一份。本包没有把这个新增预检写成已经实现。

## 已有基础

## 恢复与异常

恢复只消费匹配本轮回执的窗口，比较 liveRevision 与 afterRevision。手动移动/展开/重新收起优先，立即取消本程序的自动恢复归属。超时不等于动作没有发生；晚到完成需要按旧 attempt 做补偿核对，不能触发新 timer phase 的成功。

port 不能永久挂起。建议为一次观察/动作链设明确截止，并在到期时返回 unknown；截止值先按原 FoldVerifier 的真实重试安排和 Mac 测量确定，不把原 30 秒 waiter 兜底当交互延迟目标。取消等待不取消外部 AX 已经接受的动作，继续保留需要核对的记录。

锁屏、睡眠、App 退出、崩溃恢复分别测试。跨重启恢复必须与现有 journal 集成并重新识别窗口，不能持久保存旧 AX 引用或复用 PID。写 journal 失败时停止新的自动效果，计时仍可继续。

## 设置接线

真实 port 准入完成后才把 Focus 设置中的效果项变为可选。未完成时显示“仅计时”；不把不可用开关呈现为已生效。修改预设只影响下一轮，关闭卡片不停止计时，单一 host 不变。

## 验收结果

至少跑两应用、多窗口、多屏、全屏/Space、最小化、目标退出、手动改位置、锁/睡眠与中途退出。每例保存开始身份、事务号、观察三态和最终结果。能看到卷帘条不代表真实窗口已隐藏；恢复坐标正确但焦点错误也应单列失败。先保证原窗口回归，再启用自动专注效果。
