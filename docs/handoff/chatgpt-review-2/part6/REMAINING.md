# 第六份后仍缺什么

本包交付了明确的源码增量和实施依据，六条产品路径并没有都接进实际 App。下面分别记录生产代码、构建和运行，不把它们笼统叫做“等实机”。

## 仍需要写或连接的生产代码

|路径|本轮给出的真实部件|仍缺的具体调用者或实现|工单|
|---|---|---|---|
|owned CLI|Scope/目录身份；显式 Wire 权限；有诊断的进程通道|Runtime 唯一 LaunchController、本地项目/可执行文件选择、真实 store 订阅、恢复 thread 项目关联、配置/工具准入、原始 JSON 重复键拒绝与锁态统一撤销|02|
|进程停止|传输关闭、直接子进程终止状态、通知送达后的收尾|拥有 reaper 和进程组生命周期的独立监督端口、可信退出与停止升级、子孙清理；诊断 opt-in/展示入口|03|
|原生输入|稳定列表 ID、revision、单次 activation；原有设备 host|可见列表 sink、设置与 Runtime 实例、IME/焦点/审批联动；桌面运动、HID、鼠标和多触点生产桥|04|
|配对网络|总连接/未认证/peer 配额，队列预算与绝对握手截止|唯一 NWListener、真实关闭/写入记账、受限 OPACK/session、Bonjour profile、验证后路由、安全重配/Keychain 恢复；SRP 依赖与互测|05|
|窗口效果|前五份事务计划与本轮 typed completion 施工说明|实际 AX 隐藏/恢复端口，run/transaction 身份绑定，unknown 和迟到完成补偿，Focus 计时/范围/设置接线及持久恢复策略|06|
|界面与生命周期|Island 候选优先级修复及取消 barrier|所有页面入口、原生认证与单岛实际布局/焦点回归；会话/指挥 live store 接线|01、02、04|

`PROC04` 是本轮真实发现且尚未通过的行为要求：继承描述符的子孙进程让本机退出通知延后，并使迟到的输出被收到。当前候选不能宣称能够在直接子进程实际退出后固定 200ms 内关闭整条通道；更不能宣称已清理进程树。Mac 情况尚未测试。

## 继承的其他未完项

F1/L3 自有人脸模型、活体与误识率；可靠系统锁/解锁；L2/L4 BLE 身份与动作归属；M1/S1 全部菜单、Option 入口及设置覆盖；D4/I7 真实设备偏好及撤销；番茄钟全部可见入口与窗口效果能力同步，仍按前五份逐项验证。它们没有因为第六份转向使用闭环而自动完成。

影片只有以前两条无声动态分镜，17 项真机素材、声音授权/混音、正式构建和最终观感仍缺。本轮没有新影片。任何“已解锁、已配对、实际执行”的产品文案和镜头要由其对应功能证据支持。

## 已确定的执行顺序

先合入仲裁和固定 Wire 权限修复，完成 SDK 编译。随后用本地目录走通 owned CLI 的真实可观察流程，同时处理进程监督缺口。再接当前可见列表与真实输入；窗口端口和配对网络隔离推进。缺一种外设不能阻止已经独立的本地助手流程，但有审批或终止语义缺口时不能对外宣称允许路径安全可用。
