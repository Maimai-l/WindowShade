# 第六份：先把一次真实使用走通，再开放更多来源

你接手的是 `WindowShade2-round2-handoff-v6/candidate-repo/`。它是第五份的精确增量合成，不是公开仓库最新 HEAD，也不是已验收的发行版本。用户上传原仓库及 v5 候选保持不变。本轮只在隔离候选中修复代码和补齐可执行的材料。

先读 `CHANGELOG.md`、`VALIDATION.md`、`REMAINING.md`。代码改动只有 manifest 列出的十个文件，五个修改、五个新增；不要重新叠前五份。你实际工作区已经变化时按 baseSHA 三方合并，不用 stage 覆盖。不要另建第二套 AppRuntime、Notch panel、Wire、授权账或设备 callback。

## 可以直接合入的修复

`InteractionCoordinator` 支持携带当前 lease 的原子换页，并保留取消回调期间发生的撤销；`WS2IslandCoordinator` 不再先关闭旧页再请求权限。`CodexWire` 显式设置只读、按请求人工审批，并在 turn 层限制工具网络；具体消息已校验上传的 0.153.0 schema。`build.sh` 修复全新候选缺少 `.build` 父目录的问题。这些先按工单 01 合并和做 Mac 编译，不以 Linux 通过代替 AppKit 检查。

进程通道新增可选的有界 stderr 诊断及直接子进程终止状态。它仍不是完整的进程树监督器。`PROC04` 在本机确实发现继承描述符造成通知延后的问题，报告为 BLOCKED；不要通过放宽断言、删除 fixture 或把 EOF 改叫“全部结束”来交差。

## 第一条独立交付：本地启动并观察 owned Codex

按工单 02 在既有 Runtime 中持有一个明确的 LaunchController。工单给出的 LaunchController 是待实现的接入层，不是假装本包已有该类。它使用新 `WS2OwnedScope` 和 `WS2ProjectDirectory`，从本地选择项目和可执行文件，生成与本次 connection 绑定的 ticket，再创建既有 OwnedCodexSession。锁态、项目、权限和连接变化必须一起撤销 Scope、输入和待批准。

先让 initialize、model/list、新建 thread、开始 turn 和匹配的最终事件走通；UI 显示真正的结果，不只是绿色的“已连接”。收到停止请求先标记停止中，最终事件或真实退出证据到达后再更新。恢复 thread 另查本地项目关联，不能只凭 ID 字符串合法。第一步不依赖 SRP、手机遥控器、私有多触点或窗口效果，别让它们拖住整条路径。

普通命令批准继续经过完整审阅、原生认证和原有 AuthorizationService.consume。不能直接把 Scope、lease、paired 或 input-confirmed 当 grant。文件、网络和持久规则批准尚缺可信范围与展示，继续拒绝。隔离 CLI 配置及外部工具检查仍是生产工作，Wire 的参数不是整台机器的沙盒证明。

## 第二条独立交付：在当前可见列表里完成一次输入

按工单 04 用新 `WS2SelectionModel` 驱动真实的原生列表；保留稳定 ID、revision 和一次性 activation。实际 device host 必须得到当前列表 sink，不能接空闭包或全局 Return。列表变化、中文输入法组合、审批出现、目标切换、断连和锁屏都要取消旧票据及 held 状态。先证明导航与打开选中项，再接摇杆移动窗口。

## 其余两条路径的先后顺序

网络按工单 05：Keychain/peer 仓库可用，确定协议 profile，验证密码学和消息解释，再创建唯一 NWListener。新 `WS2ConnectionBudget` 只负责资源账，不负责验证身份；过期返回的连接句柄要由真实 owner 关闭。OPACK/session、Bonjour 原生兼容和安全重配仍要实现，不能因为有预算核就显示“已配对”。

窗口按工单 06：先改 typed completion 的真实事务落点，再接 FocusEffectExecutor。新收起操作不能直接调用有 toggle 语义的 tuckAll。缺失的 AX 观察返回 unknown；只有实际改变、验证成功且仍属本轮的窗口进入恢复账。工单中的实际窗口端口仍未交付，不能接恒 true 或空执行器。

## 读资料的方法

`docs/01` 从用户可见结果梳理全项目；`docs/02–07` 解释每条调用链为什么这样处理；`docs/08–10` 补身份、隐私、能耗、失败恢复和证据边界。`DECISIONS.md` 定下 44 项工程默认。`sources/code-map.md` 定位本轮 36 份实际源码及符号，JSON 含 SHA256；外部一手资料与适用范围在 `sources/REFERENCES.md`。

不要把这些材料再改写成一份说明来交差。每个小提交应有一个用户能观察的结果、实际调用者、明确关闭路径和失败证据。查不到设备事实时保持该能力关闭，同时继续不依赖它的工作。

## 每次交回什么

交回具体修改路径、运行的完整命令和退出码、原始输出、真实/替身环境、未完成调用者，以及数据有没有新增去向。每项分别标源码、SDK、运行状态。第六份本机新增 56 个 Swift 场景、133 个断言通过，同时 PROC04 的能力要求仍未通过；这两件事必须同时保留。旧回归、Python 工具测试、schema 检查、语法 parse 和实机功能不能混算。

用户没有授权发布、修改更新源、真实 home 配置、远端命令或采集生物数据。原有影片仍是旧无声动态分镜；不要改名当成本轮成片。
