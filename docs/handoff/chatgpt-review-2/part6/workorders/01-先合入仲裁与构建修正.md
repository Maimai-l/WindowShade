# 工单 01　先合入仲裁与构建修正

## 读什么与改哪里

以统一包 candidate-repo 为准，先读 `sources/code-map.md` 中 InteractionCoordinator、WS2IslandCoordinator 和 build.sh 的定位。本工单触碰 `prototype/App/InteractionCoordinator.swift`、`prototype/App/WS2IslandCoordinator.swift`、`prototype/build.sh`，不重建 NotchPanel，不修改认证账结构。背景为 docs/02 和 docs/09。

## 已交付的实现

`InteractionCoordinator.acquire(_:replacing:)` 对确切当前 `.opened` 页面允许显式同级替换；对 authorization/interaction 继续按严格优先级处理。`invalidate` 不再丢弃过渡期间的安全事件。`WS2IslandCoordinator.show` 不预先 dismiss，而是在 acquire 与 isCurrent 都成功后挂载。`beginAuthorization` 也复查新租约。build.sh 在 mktemp 前创建 .build，并纠正 --check 的说明。

## 执行顺序

在完整 v6 候选上运行本包 core、wire、process 和 regressions。实际工作区比 v5 新时先三方合并，保留新功能对同一文件的修改。若自己曾为普通页面切换增加无条件 dismiss，把那一层也移除；不能只修本包文件而在另一个调用者提前释放高优先级内容。

Mac 上先检查真实 Sparkle.framework 和 SDK，再运行隔离的 `tests/run-mac-check.sh`。这一脚本不签名、不启动 App。编译失败修具体错误，不能把 arbitration 文件排除。通过后在用户允许的测试实例打开番茄钟、会话、指挥和审批预览，按下表测试。

|场景|预期结果|失败动作|
|---|---|---|
|番茄钟页切会话页|旧页 revoke 一次，新页取得当前 lease|不提交该替换，保留旧页|
|审批预览时打开番茄钟|返回 false，审批继续显示|撤回普通页面入口的预先关闭逻辑|
|原生 Touch ID 呈现时打开普通页|不抢 panel、不重新 makeKey|检查所有原生认证旁路|
|旧页撤销回调里关闭功能|本次 acquire 失败，没有新页|查 epoch 与回调顺序|
|双击入口导致旧页关闭回调晚到|只关闭 exact view/handle，不影响新页|取消按 ownerID 单独匹配|
|移走当前显示器|撤销当前输入，不挂到失效 panel|保持 UI 关闭，用户再开|

关闭显示页并不停止后台番茄钟或助手任务。主动停止仍走各自的 stop 路径。只有认证交接允许静默取消旧预览的 dismiss 回调，其他情况保留 typed revocation 原因。
