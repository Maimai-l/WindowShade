# 工单 05　监听、配对与协议解释的装配顺序

## 本包新增了什么

新 `Core/WS2ConnectionBudget.swift` 提供 admit、expire、promote、reserve/release、revoke、halt。第五份已有 PeerRepository、KeychainPeerStorage、PairSetupServer、PairSetupCrypto、CompanionCrypto 与 accepted TCPTransport。这些类没有替你实现 NWListener、受限 OPACK/session 或真实 Bonjour profile。

## 新调用者与所有者

建议新增 `prototype/App/WS2RemoteListenerHost.swift` 作为唯一 owner；具体名称允许与现有代码保持一致，但同一 Listener/PeerRepository 只能一个强持有者。它持有 budget、连接字典、配对窗口和已核验 profile。连接字典键使用 budget 返回的 Handle，不由客户端提供。profile 的 serviceType/TXT/session 方法来自实测和固定证据，未知时不广播。

## 按这个顺序做

1. 在隔离 target 完成真实 Swift SRP 依赖构建、固定向量和对向实现互测。源码中存在 adapter 不等于这步完成。
2. 接本地 PIN 视图、全局失败计数和 Keychain 明确初始化/错误恢复。配对窗口由本地动作打开，截止/失败不被重连刷新。
3. 接 Listener 的 accepted 回调。先 expire 并关闭对应旧 transport，再 budget.admit；失败立即关闭这次连接，不构造昂贵 PAKE 引擎。
4. 解码层在任何分配前检查长度、深度、总节点和引用。未知格式返回明确错误，不绕过认证继续执行其他消息。
5. Pair-Setup 先成功写持久身份，再返回成功消息。Pair-Verify 要从当前 repository 读取 peer 与 revision，经真实验证才能 promote。
6. 每条已验证消息进入语义路由前重查 peer revision、连接代次、输入当前租约、锁态及目标版本；不得把 verified peer 直接变成 AuthorizationGrant。
7. 撤销设备时先标 repository 不再准入，再关闭 budget 返回的连接并取消所有设备输入。旧连接的缓存“已验证”立即失效。

## 队列账必须和真正传输一致

reserve 在真实 queue admission 之前，admission 失败就退账。当前 transport 的 contentProcessed 是本地发送处理回调，不是业务执行确认；完整发出后释放计费字节。关闭时从总账移除一次；迟到回调查 handle 已不存在就不再退账。不要同时在每个切片和整个帧完成时扣两遍。

## 错误分支

Keychain 不可读：不建 listener；记录不含秘密的错误码并显示本地恢复入口。PIN 失败：沿用全局预算；不能关闭重开重置。未验证连接耗尽：拒绝新连接，不影响已验证会话。对端同 ID 换钥匙：进入需本地重配状态，不覆盖。设备容量满：显示管理入口，不删除撤销墓碑腾位置。库或 SDK 缺失：实验 target 保持 unavailable，不填假 verifier。

## 原生互操作准入

必须分别录下真实原生客户端的发现、PIN、M1–M6、重连验证、加密 session、单次输入、撤销后重连拒绝。记录经过脱敏的消息类型、长度、构建与设备信息，不保存密钥。对向脚本通过只进 protocol-test 栏；原生 Remote 未跑保持 not-run。禁止为演示配对成功而注册假的已配对设备。
