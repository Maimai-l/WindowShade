# 工单 07　证据门禁与发布前留档

## 使用本包工具

`tools/stage.py` 只适用精确 v5 到全新 v6；统一包已合成，不要再运行它覆盖 candidate。`tools/check-source-map.py` 核对源码地图。`tests/run-core.sh`、`run-process.sh`、`run-wire.sh`、`run-regressions.sh` 运行本机验证；`run-exit-probe.sh` 单列已知缺口；`run-mac-check.sh` 在非 Mac 返回 78。

`tools/readiness.py` 读取 `fixtures/readiness-current.json`，结果应为 BLOCKED。填入真实证据后才能重新评估；不能把当前样本 status 改成 passed 而不填日志和 hash。该工具是证据完整性检查，不是自动安全认证。

## 记录格式

每条能力至少写 id、source、build、runtime、environment、command、exitCode、logPath、logSHA256、candidateRevision 和 reviewer。status 使用 missing/partial/not-run/failed/passed；不得用含义模糊的 done。路径限制在报告根目录内，拒绝绝对路径和 `..`。source、build、runtime 各自是带上述字段的对象；expectedEnvironment 为各阶段指定环境名。没有实机的日志不能把 environment 写成 macos-hardware。reviewer 必须包含 name 和 decision: accepted。日期和审阅者只是自述，工具不能鉴别其真实性。

核心测试、Mac 类型检查、真实优化链接、CLI 端到端、设备互操作、窗口行为、能耗和影片分别登记，不进行分数平均。某个安全必需能力失败就阻断该功能，不以十个不相关测试通过抵消。

## 编译和静态检查

看 --check 的实际实现：它编译 Metal，并做优化 Swift 编译及链接。缺 SDK、Sparkle 或依赖时登记准备失败，禁止改为只 parse 后交作 Mac 通过。isolated checkout 排除用户 local-codesign.env，检查不签名、不写 app bundle；需要运行 App 时再按已有授权和签名流程操作。

## 能耗、隐私与影片

沿 docs/09 的同机对照方案留原始数据。权限拒绝和外设断连必须进入回归，关闭功能后不能继续偷偷采集。诊断尾部的 opt-in、上限、可见清除和不自动离机要有记录。

影片本次无新增成片。所有声称已配对、已解锁、实际执行或窗口恢复的镜头须有相应运行证据；概念片继续有概念标记。授权、签名、更新源和 1.0.16 发布都不在本次权限内。

## 主模型复核顺序

先看三处本轮修复的语义：原仲裁预先 dismiss、过渡中漏掉 invalidation、助手继承宽权限。再看进程 PROC04 的实际失败及清理边界。接着检查 Scope 不是沙盒、Selection 不是授权、Budget 不是身份验证。最后审各真实 adapter 的调用点与失败恢复。出现新安全结论时提供反例和证据，不用“经验上没事”取消门禁。
