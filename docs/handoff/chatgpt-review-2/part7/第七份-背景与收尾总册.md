# 第七份：接通本地助手使用流程

交付基线：第六份统一包的 `candidate-repo/`，1145 个文件。当前不是公开仓库 HEAD，不是已编译的发行版本。完整 v7 候选已经叠好，直接从统一包 `candidate-repo/` 开始；不要再逐份执行 part1 至 part7。

这次已有实际 `WS2OwnedLaunchController`，不再要求你重新设计这个类。它连接本地选择、版本预检、独立配置、登录、真实模型目录、会话创建与恢复、一次提交、流式显示、停止和锁态撤销。Runtime 强持有它；设置页“编程会话…”进入同一刘海宿主。新的 C 监督端口负责唯一子进程回收，实际正常退出入口也已经连接更新器与助手的联合门槛。

## 先交到用户手上的范围

本地入口目前是**只读查询**。它拒绝请求提升权限的命令和文件操作。此前的完整命令审阅、原生认证与授权账保留在独立适配器中，但没有接成新入口的默认允许路径。不能为了显示“全能编程”而把默认 host 换成自动批准，也不能把这条只读阶段说成整个 WindowShade 2 已完成。

操作顺序已经落实到源码：打开入口 → 本地选择项目和可执行文件 → 勾选运行与账号使用确认 → 点击启动 → 核对固定版本和配置 → 必要时点击登录 → 选择实际返回的模型 → 输入文字并点击发送 → 看匹配的最终结果 → 停止本轮或断开。关闭页面不等于断开；锁屏、睡眠或禁用会撤销并清除界面私密内容，解锁不自动启动。

第一步，运行 `tests/run.py` 的 core/native/flow 三套测试，再按 `tests/regressions.py` 运行旧回归。命令在 README 中。受控后端只存在于测试目录，不能安装成 Codex 或伪装真实账号。

第三步，按 `workorders/01-Mac与真实CLI验收.md` 用用户明确允许的空测试项目、实际 0.153.0 CLI 和独立账号状态运行。实际 `config/read` 若缺少所需字段，入口会拒绝；这时记录原始结构、按固定 schema 研究，不用恒 true、宽权限配置或修改测试期待来绕过。

`COMPLETION-CONTRACT.md` 把本地试用、允许路径、整个原项目分开。停止增加泛用 Manager；后续改动必须消除表中的一个具体源码缺口，或取得一个真实平台证据。不能用第八份、第九份这种序号代替完成条件。详情看 `REMAINING.md`，它没有删除远端接收、窗口效果、手柄、身份、能耗和影片等原目标。

# 实际调用链与所有权

## 原先断在哪里，这次接在哪里

第六份已有 Scope、Wire、管道、审批宿主和会话视图，但 Runtime 没有本地启动控制器，页面没有真实项目/账号/模型的来源。这次的组合路径如下，名称都对应候选中的实际文件：

```text
WS2SupplementPane 的“编程会话…”
  → AppDelegate.ws2OpenOwned()
  → WS2AppRuntime.openOwned()
  → 已有 WS2IslandCoordinator.show(WS2OwnedSessionView)
  → 唯一 WS2OwnedLaunchController
      → WS2LocalLaunchProfile / WS2ProjectDirectory
      → WS2VersionProbe (--version，等实际回收)
      → WS2OwnedCodexSession
          → 默认 WS2ReadOnlyProtocolHost → 唯一 CodexWire
          → WS2DuplexProcess → WS2Child.c
      → 既有 AgentSessions
      → onChange → 当前可见 WS2OwnedSessionView
```

AppRuntime 是唯一强所有者。关闭刘海页面只取消页面输入和观察，不销毁正在运行的连接。控制器持有一个预检或一个真实会话；取消后的预检仍放在 `retiringProbe`，直到回收通知到达。新启动不能抢在旧进程清理期间发生。没有回收证据的监督错误不会被转换成可重新使用的空槽。

## 从真实事实形成可见状态

阶段 enum 只是 UI 投影，不重新实现协议状态机。`CodexWire` 管请求、回复、分页、thread/turn；`AgentSessions` 管已观察到的后端会话；`WS2OwnedScope` 管本地项目/连接代次。三者的事实不能互相冒充。

|实际事件|更新|不允许推导|
|---|---|---|
|本地选中了目录和程序|显示路径，仍尚未启动|已经连接、已有会话|
|真实版本预检通过且进程回收|开始 app-server 连接|账号可用或配置有效|
|initialize + model/list 完成|保存实际模型目录|可以发送请求|
|config/read 符合本地政策 + account/read 已登录|允许本地选模型/发送|额外权限已授权|
|thread/start 或 resume 返回匹配 ID|写入现有 AgentSessions|一轮工作已经成功|
|匹配 turn 启动|显示运行中|所有工具均可用|
|匹配最终 status|分别显示完成、停止、失败|失败/中断也叫完成|
|管道关闭|断开、等待回收|系统已清除所有子孙|
|原生 reaper 返回事实|直属进程回收完成|外部服务、脱离组的子孙也结束|

官方 App Server 资料区分请求响应、通知、thread 和 turn；具体 JSON 形状仍使用本包固定的 0.153.0 schema，不从当前网页复制新字段。[S3](sources/SOURCES.md#s3)

## 草稿只在明确动作后提交

`Submission` 捕获按下发送时的文字、模型和 effort。如果尚无 thread，先创建，再将这份不可变请求发送给返回的 thread。途中再次按发送会拒绝；不能把用户随后编辑的文字偷偷换进已经准备的请求。中文组合输入未完成时不提交，回车只换行。

模型和 effort 来自当前连接的目录。若没有选择有效模型，发送保持禁用。默认 effort 仅在该模型真的返回 medium 时用 medium，否则选其支持集合里的第一项；这只是界面默认，不是模型质量推荐。

本地记录最多 64 个项目和 64 个 thread 关联，只在内存保存。恢复按钮只接受自己见过、属于同一目录身份的 thread。换项目后即使 thread 名字相似也不恢复。应用重启后不凭磁盘上任意 thread ID 自动恢复，避免把尚未实现的持久索引藏在字符串里。

## 登录是一次请求，不是任意链接入口

用户点击登录后才发 `account/login/start`。仅匹配当前请求的 HTTPS 链接能交给系统浏览器，主机限定 auth.openai.com 或 chatgpt.com，拒绝用户信息、非标准端口、fragment、任意文件链接和超长 URL。登录完成通知还需匹配 loginID，再读一次账号状态。

取消登录先绑定原请求。取消结果到达后关闭本次连接，重新连接时再次读账号状态。不要显示“取消后凭据必定不存在”：浏览器与 CLI 的持久化可能已经发生。退出登录则等待对应 RPC，再结束本地连接。本次 schema 检查发现 logout 不接受空对象 params，已改为省略该字段。

## 撤销顺序

锁态未知、锁屏、睡眠、功能禁用、换项目、主动断开、应用退出都先使 scope/ticket 无效，然后取消待提交和登录期限，再关闭通道。解锁只允许用户重新发起；不会复活旧 ticket。读到旧连接的回复不能更新新连接的视图。

代码中 `currentIsValid` 在真实写入路径仍复核当前目录身份。它会做同步元数据读取；在网络卷或慢磁盘上可能影响主线程。没有本次能耗/慢卷测量，不能承诺零开销。下一步优化须保留写前代次门槛，不能为了省 stat 把身份检查改成恒 true。

# 进程监督与正常退出

## 先修复观察方式

原 PROC04 用一个直接子进程退出、子孙继续持有 stdout 的情形，暴露了“把 EOF/延后的 Foundation 通知当退出”的问题。本轮保持同一探针不变，替换了进程启动和回收端口。

C 模块使用 posix_spawn 创建自己拥有的进程组。Swift 保留非阻塞、有界读写，不再让 Foundation.Process 同时回收该子进程。waitid 的 WNOWAIT 可以观察退出而暂时保留待回收状态，这为稍后的组信号保留了身份锚点；waitpid 最后完成直属子进程回收。[S1](sources/SOURCES.md#s1) 组的创建参数来自 POSIX 语义，Mac 分支仍须实际 SDK 和运行验证。[S2](sources/SOURCES.md#s2)

本轮是一个与 App 同进程链接的原生监督模块，**不是已经安装的独立守护进程或登录项**。App 被强制杀死或崩溃时，不能依靠这个模块继续清理。因此正常退出已接入等待，异常退出仍是明确边界。

## 当前状态与动作

|触发|立刻做什么|后续|失败状态|
|---|---|---|---|
|主动停止|撤销写许可、关闭通道、向自有组 TERM|500ms 工程宽限后向同组 KILL，随后回收直属子进程|没有证明回收就不放行新启动|
|检测到直属子进程退出|记录退出事实，有限读完当前已到字节，关闭业务通道|清理同组剩余进程，再回收 leader|不等所有继承 fd 自行 EOF|
|getpgid 不匹配、waitid 出错|停止继续使用该监督对象|释放失败的内存账，不发成功回收回调|界面仍表明结果未确定|
|正常应用退出|同时等待旧更新器门槛和助手清理|两者都就绪才 reply(true)|35 秒仍无证据则取消退出，不伪造结束|

500ms、20ms 轮询、5ms leeway、35 秒联合退出期限都是本项目的工程值，不是系统保证或实时上界。轮询仅在明确启动的子进程仍需监督时存在。它有唤醒成本，必须用真实 Mac 比较；不能因 idle 时不启动就声称运行时没有功耗影响。

## 为什么不随意 kill 一个 PID

监督器只接自己 posix_spawn 的对象，不接受外部 PID。最终组信号之前不回收 leader，使其 PID 尚不能被重用。每次信号都核对 group 等于 leader PID、不是当前 App 的组、且编号有效。失败时不猜另一个 PID，不按进程名遍历杀工具，不对用户终端组发信号。

这能覆盖仍留在本次组里的普通子孙，不能覆盖自行 setsid/setpgid 脱离的进程，也没有宣称回收所有非直属子孙。原始进程树无限扩张、故意逃逸、同 UID 恶意代码和宿主崩溃属于另外的问题；当前选择程序的 UI 明确表示运行的是用户选择的本地代码。

## 描述符与线程边界

父端管道非阻塞且有 CLOEXEC。子端只收到预定的 stdin/stdout/stderr；Mac 用 CLOEXEC_DEFAULT，Linux 用支持平台的 closefrom 动作，其他 libc 返回不支持。没有修改 App 全局当前目录，没有安装全局 SIGCHLD 回收器，也没有全局忽略 SIGPIPE。写入仍有每批上下文和期限复核，部分写出后断开绝不重试批准。

诊断默认不捕获；明确开启后只保留 64 KiB 尾部。stdout/stderr 每次回调的工作量都有上限。有限尾部是为排障，不是完整审计记录，更不做自动上传或自动喂给模型。

## 与现有更新器合并，而非替换

`AppDelegate.applicationShouldTerminate` 现在交给 Runtime。Runtime 仍调用原 UpdaterController 的终止决定，并通过新增的 `terminationResponse` 接住它的异步回复。`WS2QuitBarrier` 将 updaterReady 与 childrenReady 合并，拒绝旧 token、重复 begin、晚回复和超时成功。原更新器其余逻辑不变。

若停止版本预检时把对象立即丢掉，App 会误以为没有子进程。因此 `retiringProbe` 必须保留到原生回收；版本检查超时也必须等回收后才报告最终失败。这两种路径已有整条流程测试。

## 本次证据及仍缺的证据

原 PROC04 在本次最终回归约 0.023 秒识别直接退出，未收到 0.8 秒后的迟到行。另测了忽略 TERM 后升级、自有组子孙不能完成迟到写、无关 fd 不继承。测试发生在 Linux，不能推广成 Mac 23ms 性能承诺。

Mac 还要测试与 Sparkle/Foundation 其他子进程并存、连续退出/取消退出、系统睡眠、权限失效，以及 App 原生 quitLater/reply 的真实顺序。语法 parse 不能覆盖这些行为。

# 配置、权限与隐私边界

## 运行程序的同意早于版本检查

`--version` 本身就在执行用户选择的文件。因此选择文件、点击启动前的确认不能被“只是探测版本”绕过。没有同意不创建子进程。版本输出符合固定字符串只证明这个程序自称该版本，不证明签名、供应链或善意。本轮没有自动下载、升级或替用户选择可执行文件。

项目路径、程序路径都来自本地文件选择器。远端消息不能改变 cwd 或启动参数；native spawn 不经过 shell 拼字符串。目录记录规范路径、设备号、inode；程序另记大小和修改时间。这是会话错配检查，不是防同 UID 攻击的强沙盒，也不能消除检查与使用间的文件系统竞态。

## 独立配置实际保存在哪里

点击启动后，候选创建 `~/Library/Application Support/WindowShade/OwnedCodex-v1/` 下的 home、codex、tmp。目录 0700，配置文件 0600，要求同 UID、非链接。已有配置若被改动，停止启动而不是覆盖。没有读取或复制原 `~/.codex` 的凭据和配置。

运行环境是明确的 HOME、CODEX_HOME、TMPDIR、系统 PATH 与 locale 列表，不继承 API key 等任意环境变量。当前策略明确选择 CLI 的文件凭据存储方式；官方资料说明该方式使用 CODEX_HOME 下的 auth.json。[S4](sources/SOURCES.md#s4) 因此不能写“所有内容仅在内存”：凭据和 CLI 自己的会话文件会留在独立目录，关闭刘海页面或断开不删除这些文件。用户注销由 CLI 的真实 RPC 处理，本次没有操作真实凭据。

## 配置收窄有用，但不能过度承诺

配置明确指定 read-only、on-request、user reviewer、禁用 web_search、shell_tool、unified_exec、shell_snapshot。新建/恢复 thread 和每次 turn 再携带已固定的权限参数；默认 host 对额外权限请求只会拒绝，不会调用授权账或自动批准。

项目及祖先存在 .codex/.agents、已知 /etc/codex 配置存在时，初版保守拒绝。它没有删除 AGENTS.md，也不把提示词当权限。官方配置有多层优先顺序，独立 CODEX_HOME 不等于排除系统、受管理和服务端的所有配置来源。[S5](sources/SOURCES.md#s5) 因此握手后还校验 config/read；缺少必要字段、取值不符或外部能力非空就关闭，不默认为安全。

这个服务端投影仍不能证明选中的程序诚实，也不能追溯阻止其启动时已经执行的恶意动作。Mac 的受管理配置、当前版本返回哪些字段、沙盒实际行为均未实测。生产准入必须依赖可信可执行来源和真实运行验证。read-only 不等于只可读项目；工具网络禁用也不等于模型服务不联网。

初版只读入口的存在不取消后续普通命令一次性批准目标。旧认证适配器仍走完整审阅和 AuthorizationService.consume。只有完成真实范围、权限展示与原生认证验收后，才能另行开放这一入口；不能仅修改工厂默认值来宣称完成。

## 原始 JSON 先拒绝歧义

RFC 8259 提醒重复对象成员会导致实现间行为差异；本项目选择比一般兼容更严格的拒绝策略。[S6](sources/SOURCES.md#s6) 检查发生在 JSONDecoder 形成字典之前，包括嵌套对象、转义后的键相同、非法 UTF-8、孤立 surrogate、额外尾随值、深度和节点预算。

`"id"` 与 `"\u0069d"` 必须视为重复。Swift String 的等价比较还会保守拒绝规范等价的 Unicode 键，这不是宣称所有 JSON 实现都必须如此。请求 ID 的整数/字符串类型保留；同一消息同时出现 result/error 或 method/result 会直接关闭连接。帧长度与原有 outbox 上限继续有效。

## 新增数据去向

新增登记在 `sources/privacy-signals.json`，并同步进候选 `docs/handoff/round2-part7/`。本轮实际测试没有采集真实用户账号、项目内容、外设或生物信息。

|数据|读取时机|保留与去向|
|---|---|---|
|项目/程序身份、路径|本地选择、启动和相关复核|控制器内存；路径显示本地，不自动分析目录内容|
|版本 stdout|明确点击启动|最多 8 KiB，校验结束清空；不是登录或工作结果|
|账号是否可用、模型目录|真实协议返回|本次连接内存；不把邮箱用于显示或日志|
|草稿/回复|本地输入及 stdout|各有上限的本地内存；用户点击发送会交选中的 CLI，可能转给模型服务|
|stderr|本次显式 opt-in|64 KiB 内存尾部，可能仍有敏感内容，无自动导出或上传|
|CLI 凭据和自己的历史|用户实际登录或运行时|独立 CODEX_HOME 磁盘目录；由 CLI 管理，不谎称关闭页面即擦除|

清空 Swift Data/String 不等于密码学级内存擦除。拒绝传感器、未登录、未装外设不会触发重试采集。之前的人脸、声纹、心率、BLE 项目没有因为这份新增一个账号入口就获得任何身份授权能力。

# 界面、性能与失败处理

## 页面使用已有宿主

原生视图由现有 Island/NotchPanel 持有，不创建新的产品浮窗。文件选择器和浏览器登录属于用户明确触发的系统交互。620×560 是候选展开尺寸，不是已核验的 HIG 标准；页面外层加入滚动容器，避免总内容高度把底部停止按钮挤出可见范围。Mac 仍需检查缩放、刘海、安全区、短屏和多屏。

回复是纯文本，不作为 Markdown、HTML、终端控制序列或可执行链接处理。模型菜单来自实际目录；选择项和 effort 对应当前会话，而不是硬编码新型号。诊断要另外点击查看，不自动混入模型回复。

状态推送最多合并至每 60ms 绘制一次，只有视图活着才绘制。不在每次字符 delta 重建页面，不改变正在组合输入的草稿。只在用户本来就在底部时滚到新回复末尾，不强行打断向上阅读。外层滚动与文本框滚动的触控板体验仍须真机看，不能以代码存在代替交互验收。

## 失败后保留什么

|失败|界面/状态|下一次允许动作|
|---|---|---|
|拒绝运行同意|不创建子进程、不显示假会话|用户自行确认后重试|
|版本不匹配|显示固定版本要求，不自动升级|换实际匹配程序|
|版本超时|终止并等回收；不能提前释放启动槽|清理完成后用户重新选择|
|配置已被外部修改|拒绝启动，保留文件原字节|审查改动后显式处理，不能自动覆盖|
|未登录|显示登录入口，禁止发送|用户本地发起登录|
|登录链接/ID 异常|不打开链接，不认证|停止，记录错误类别|
|stream 失败/结果未确定|保持失败或断开状态|不能自动重发原请求|
|停止本轮 RPC 成功|仍显示停止中|等匹配最终通知或明确断开|
|监督错误|不宣称进程清理完成|保留不确定状态，正常退出不能自动放行|

## 应用整体的退出仍需回归

Updater 的原 terminateLater 与助手清理现在共用一条最终回复。测试了纯核双方就绪、单方就绪、否决、过期 token 和晚回调。AppKit delegate 的调用顺序、Sparkle 下载/安装期间、用户重复退出、菜单栏退出和 Dock 退出必须在同一真实 App 中验证。

锁屏和睡眠是撤销原因；通知不直接证明系统解锁。真实 AuthorizationService 返回未知时仍不可使用。关闭页面不停止任务，因此设置入口重新打开时应显示同一实际运行实例。不能为了复现“页面关闭后不再更新”而偷换成杀掉任务。

## 能耗指标还没有测量

新的 native 监督使用存活期间 20ms 轮询，可能带来 CPU/wakeups 成本；代码已明确无任务时不创建轮询。选中项目和写前身份检查会读文件系统元数据；慢卷可能影响 MainActor。不要用理论上的字节上限和刷新间隔写性能成绩。

Mac 基线仍按原同机同屏同电源对照。至少区分无会话、空闲已连接、持续输出、停止清理、拒绝权限和锁/唤醒。看实际 CPU、wakeups、内存、主线程停顿和是否残留任务。若成本不合格，优先把原生退出通知和目录观察移到有明确 ticket 的串行后台端口；保持 final gate，不通过删检查或强杀其他工具来提高指标。
