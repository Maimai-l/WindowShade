# 进程监督与正常退出

## 先修复观察方式

原 PROC04 用一个直接子进程退出、子孙继续持有 stdout 的情形，暴露了“把 EOF/延后的 Foundation 通知当退出”的问题。本轮保持同一探针不变，替换了进程启动和回收端口。

C 模块使用 posix_spawn 创建自己拥有的进程组。Swift 保留非阻塞、有界读写，不再让 Foundation.Process 同时回收该子进程。waitid 的 WNOWAIT 可以观察退出而暂时保留待回收状态，这为稍后的组信号保留了身份锚点；waitpid 最后完成直属子进程回收。[S1](../sources/SOURCES.md#s1) 组的创建参数来自 POSIX 语义，Mac 分支仍须实际 SDK 和运行验证。[S2](../sources/SOURCES.md#s2)

本轮是一个与 App 同进程链接的原生监督模块，**不是已经安装的独立守护进程或登录项**。App 被强制杀死或崩溃时，不能依靠这个模块继续清理。因此正常退出已接入等待，异常退出仍是明确边界。

## 当前状态与动作

|触发|立刻做什么|后续|失败状态|
|---|---|---|---|
|主动停止|撤销写许可、关闭通道、向自有组 TERM|500ms 工程宽限后向同组 KILL，随后回收直属子进程|没有证明回收就不放行新启动|
|检测到直属子进程退出|记录退出事实，有限读完当前已到字节，关闭业务通道|清理同组剩余进程，再回收 leader|不等所有继承 fd 自行 EOF|
|getpgid 不匹配、waitid 出错|停止继续使用该监督对象|释放失败的内存账，不发成功回收回调|界面仍表明结果未确定|
|正常应用退出|同时等待旧更新器门槛和助手清理|两者都就绪才 reply(true)|35 秒仍无证据则取消退出，不伪造结束|

500ms、20ms 轮询、5ms leeway、35 秒联合退出期限都是本项目的工程值，不是系统保证或实时上界。轮询仅在明确启动的子进程仍需监督时存在。它有唤醒成本，必须用真实 Mac 比较；不能因 idle 时不启动就声称运行时没有功耗影响。

## 为什么不随意 kill 一个 PID

监督器只接自己 posix_spawn 的对象，不接受外部 PID。最终组信号之前不回收 leader，使其 PID 尚不能被重用。每次信号都核对 group 等于 leader PID、不是当前 App 的组、且编号有效。失败时不猜另一个 PID，不按进程名遍历杀工具，不对用户终端组发信号。

这能覆盖仍留在本次组里的普通子孙，不能覆盖自行 setsid/setpgid 脱离的进程，也没有宣称回收所有非直属子孙。原始进程树无限扩张、故意逃逸、同 UID 恶意代码和宿主崩溃属于另外的问题；当前选择程序的 UI 明确表示运行的是用户选择的本地代码。

## 描述符与线程边界

父端管道非阻塞且有 CLOEXEC。子端只收到预定的 stdin/stdout/stderr；Mac 用 CLOEXEC_DEFAULT，Linux 用支持平台的 closefrom 动作，其他 libc 返回不支持。没有修改 App 全局当前目录，没有安装全局 SIGCHLD 回收器，也没有全局忽略 SIGPIPE。写入仍有每批上下文和期限复核，部分写出后断开绝不重试批准。

诊断默认不捕获；明确开启后只保留 64 KiB 尾部。stdout/stderr 每次回调的工作量都有上限。有限尾部是为排障，不是完整审计记录，更不做自动上传或自动喂给模型。

## 与现有更新器合并，而非替换

`AppDelegate.applicationShouldTerminate` 现在交给 Runtime。Runtime 仍调用原 UpdaterController 的终止决定，并通过新增的 `terminationResponse` 接住它的异步回复。`WS2QuitBarrier` 将 updaterReady 与 childrenReady 合并，拒绝旧 token、重复 begin、晚回复和超时成功。原更新器其余逻辑不变。

若停止版本预检时把对象立即丢掉，App 会误以为没有子进程。因此 `retiringProbe` 必须保留到原生回收；版本检查超时也必须等回收后才报告最终失败。这两种路径已有整条流程测试。

## 本次证据及仍缺的证据

原 PROC04 在本次最终回归约 0.023 秒识别直接退出，未收到 0.8 秒后的迟到行。另测了忽略 TERM 后升级、自有组子孙不能完成迟到写、无关 fd 不继承。测试发生在 Linux，不能推广成 Mac 23ms 性能承诺。

Mac 还要测试与 Sparkle/Foundation 其他子进程并存、连续退出/取消退出、系统睡眠、权限失效，以及 App 原生 quitLater/reply 的真实顺序。语法 parse 不能覆盖这些行为。
