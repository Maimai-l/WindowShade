# 界面、性能与失败处理

## 页面使用已有宿主

原生视图由现有 Island/NotchPanel 持有，不创建新的产品浮窗。文件选择器和浏览器登录属于用户明确触发的系统交互。620×560 是候选展开尺寸，不是已核验的 HIG 标准；页面外层加入滚动容器，避免总内容高度把底部停止按钮挤出可见范围。Mac 仍需检查缩放、刘海、安全区、短屏和多屏。

回复是纯文本，不作为 Markdown、HTML、终端控制序列或可执行链接处理。模型菜单来自实际目录；选择项和 effort 对应当前会话，而不是硬编码新型号。诊断要另外点击查看，不自动混入模型回复。

状态推送最多合并至每 60ms 绘制一次，只有视图活着才绘制。不在每次字符 delta 重建页面，不改变正在组合输入的草稿。只在用户本来就在底部时滚到新回复末尾，不强行打断向上阅读。外层滚动与文本框滚动的触控板体验仍须真机看，不能以代码存在代替交互验收。

## 失败后保留什么

|失败|界面/状态|下一次允许动作|
|---|---|---|
|拒绝运行同意|不创建子进程、不显示假会话|用户自行确认后重试|
|版本不匹配|显示固定版本要求，不自动升级|换实际匹配程序|
|版本超时|终止并等回收；不能提前释放启动槽|清理完成后用户重新选择|
|配置已被外部修改|拒绝启动，保留文件原字节|审查改动后显式处理，不能自动覆盖|
|未登录|显示登录入口，禁止发送|用户本地发起登录|
|登录链接/ID 异常|不打开链接，不认证|停止，记录错误类别|
|stream 失败/结果未确定|保持失败或断开状态|不能自动重发原请求|
|停止本轮 RPC 成功|仍显示停止中|等匹配最终通知或明确断开|
|监督错误|不宣称进程清理完成|保留不确定状态，正常退出不能自动放行|

## 应用整体的退出仍需回归

Updater 的原 terminateLater 与助手清理现在共用一条最终回复。测试了纯核双方就绪、单方就绪、否决、过期 token 和晚回调。AppKit delegate 的调用顺序、Sparkle 下载/安装期间、用户重复退出、菜单栏退出和 Dock 退出必须在同一真实 App 中验证。

锁屏和睡眠是撤销原因；通知不直接证明系统解锁。真实 AuthorizationService 返回未知时仍不可使用。关闭页面不停止任务，因此设置入口重新打开时应显示同一实际运行实例。不能为了复现“页面关闭后不再更新”而偷换成杀掉任务。

## 能耗指标还没有测量

新的 native 监督使用存活期间 20ms 轮询，可能带来 CPU/wakeups 成本；代码已明确无任务时不创建轮询。选中项目和写前身份检查会读文件系统元数据；慢卷可能影响 MainActor。不要用理论上的字节上限和刷新间隔写性能成绩。

Mac 基线仍按原同机同屏同电源对照。至少区分无会话、空闲已连接、持续输出、停止清理、拒绝权限和锁/唤醒。看实际 CPU、wakeups、内存、主线程停顿和是否残留任务。若成本不合格，优先把原生退出通知和目录观察移到有明确 ticket 的串行后台端口；保持 final gate，不通过删检查或强杀其他工具来提高指标。
