# 实际调用链与所有权

## 原先断在哪里，这次接在哪里

第六份已有 Scope、Wire、管道、审批宿主和会话视图，但 Runtime 没有本地启动控制器，页面没有真实项目/账号/模型的来源。这次的组合路径如下，名称都对应候选中的实际文件：

```text
WS2SupplementPane 的“编程会话…”
  → AppDelegate.ws2OpenOwned()
  → WS2AppRuntime.openOwned()
  → 已有 WS2IslandCoordinator.show(WS2OwnedSessionView)
  → 唯一 WS2OwnedLaunchController
      → WS2LocalLaunchProfile / WS2ProjectDirectory
      → WS2VersionProbe (--version，等实际回收)
      → WS2OwnedCodexSession
          → 默认 WS2ReadOnlyProtocolHost → 唯一 CodexWire
          → WS2DuplexProcess → WS2Child.c
      → 既有 AgentSessions
      → onChange → 当前可见 WS2OwnedSessionView
```

AppRuntime 是唯一强所有者。关闭刘海页面只取消页面输入和观察，不销毁正在运行的连接。控制器持有一个预检或一个真实会话；取消后的预检仍放在 `retiringProbe`，直到回收通知到达。新启动不能抢在旧进程清理期间发生。没有回收证据的监督错误不会被转换成可重新使用的空槽。

## 从真实事实形成可见状态

阶段 enum 只是 UI 投影，不重新实现协议状态机。`CodexWire` 管请求、回复、分页、thread/turn；`AgentSessions` 管已观察到的后端会话；`WS2OwnedScope` 管本地项目/连接代次。三者的事实不能互相冒充。

|实际事件|更新|不允许推导|
|---|---|---|
|本地选中了目录和程序|显示路径，仍尚未启动|已经连接、已有会话|
|真实版本预检通过且进程回收|开始 app-server 连接|账号可用或配置有效|
|initialize + model/list 完成|保存实际模型目录|可以发送请求|
|config/read 符合本地政策 + account/read 已登录|允许本地选模型/发送|额外权限已授权|
|thread/start 或 resume 返回匹配 ID|写入现有 AgentSessions|一轮工作已经成功|
|匹配 turn 启动|显示运行中|所有工具均可用|
|匹配最终 status|分别显示完成、停止、失败|失败/中断也叫完成|
|管道关闭|断开、等待回收|系统已清除所有子孙|
|原生 reaper 返回事实|直属进程回收完成|外部服务、脱离组的子孙也结束|

官方 App Server 资料区分请求响应、通知、thread 和 turn；具体 JSON 形状仍使用本包固定的 0.153.0 schema，不从当前网页复制新字段。[S3](../sources/SOURCES.md#s3)

## 草稿只在明确动作后提交

`Submission` 捕获按下发送时的文字、模型和 effort。如果尚无 thread，先创建，再将这份不可变请求发送给返回的 thread。途中再次按发送会拒绝；不能把用户随后编辑的文字偷偷换进已经准备的请求。中文组合输入未完成时不提交，回车只换行。

模型和 effort 来自当前连接的目录。若没有选择有效模型，发送保持禁用。默认 effort 仅在该模型真的返回 medium 时用 medium，否则选其支持集合里的第一项；这只是界面默认，不是模型质量推荐。

本地记录最多 64 个项目和 64 个 thread 关联，只在内存保存。恢复按钮只接受自己见过、属于同一目录身份的 thread。换项目后即使 thread 名字相似也不恢复。应用重启后不凭磁盘上任意 thread ID 自动恢复，避免把尚未实现的持久索引藏在字符串里。

## 登录是一次请求，不是任意链接入口

用户点击登录后才发 `account/login/start`。仅匹配当前请求的 HTTPS 链接能交给系统浏览器，主机限定 auth.openai.com 或 chatgpt.com，拒绝用户信息、非标准端口、fragment、任意文件链接和超长 URL。登录完成通知还需匹配 loginID，再读一次账号状态。

取消登录先绑定原请求。取消结果到达后关闭本次连接，重新连接时再次读账号状态。不要显示“取消后凭据必定不存在”：浏览器与 CLI 的持久化可能已经发生。退出登录则等待对应 RPC，再结束本地连接。本次 schema 检查发现 logout 不接受空对象 params，已改为省略该字段。

## 撤销顺序

锁态未知、锁屏、睡眠、功能禁用、换项目、主动断开、应用退出都先使 scope/ticket 无效，然后取消待提交和登录期限，再关闭通道。解锁只允许用户重新发起；不会复活旧 ticket。读到旧连接的回复不能更新新连接的视图。

代码中 `currentIsValid` 在真实写入路径仍复核当前目录身份。它会做同步元数据读取；在网络卷或慢磁盘上可能影响主线程。没有本次能耗/慢卷测量，不能承诺零开销。下一步优化须保留写前代次门槛，不能为了省 stat 把身份检查改成恒 true。
