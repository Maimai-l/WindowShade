## 5. `docs/handoff/deepseek-dynamic-lock.md`

### 5A：替换“锁屏用系统公开的办法”一行

### 5B：替换L1规则2、规则8、规则9、规则11，并追加组合条件

```text
规则2：2秒超时从某一次具体read发出时开始算，不从上次成功时间连续计算。每连接最多一个挂起read，回应匹配epoch与请求；旧回包不刷新在场。读取间隔、检测延迟、1.5秒宽限、10秒倒数分开计时。Bluetooth关闭、权限失效、系统睡眠和传感器故障为sensorUnavailable，不偷换成已证明设备离开。

规则8：重连后回应和连续2秒RSSI过阈值仅产生回来候选，不能直接输出系统解锁许可。本人身份及锁屏会话政策必须由F1/L3/L5提供有效证据；缺脸/其他必要证据就是未通过，不使用“需要认脸时”绕过。原生设备标识、名字、RSSI不能证明用户身份。

规则9：同次动态锁会话的解锁尝试计数由L5权威流程持有，最多3次；重连、UI重建不能清零。L1候选通知去重，不消耗或重置真正密码尝试次数。用户手动锁永不产生动态锁解锁许可。

规则11：仅对本轮确实由本工具暂停、来源/会话/曲目未变且用户未更改的播放会话恢复。旧playPause是toggle，不能当pause用；无法可靠确认就不联动。

主模型先冻结手机/手表/摄像头与sensorUnavailable组合真值表：手机+手表AND规则不变，摄像头独立触发是否启用及故障策略明确写出。摄像头“有人”不等于本人。倒数截止与输入同刻时按确定顺序取消优先，避免竞争锁。收窗口和播放效果有独立上限，不无限阻塞安全锁。
```

### 5C：替换L2的“连接与保持”和真机检查段

```text
先做只读可行性探针：列真实发现的service/characteristic UUID、read属性、绑定设备身份、读取成功/错误与时间。不能读取“服务”本身，也不编标准iPhone/Watch特征。没有配套手机App的前提不变；未找到可靠特征就报告路线未成立，不偷偷扩范围。

成立后才实施5秒读取间隔和每次2秒超时；服务发现最多6秒只是本项目等待上限，不能表示期间设备已可信。没有物理请求ID的CoreBluetooth回调由串行队列的唯一挂起请求关联，超时/断连后丢弃旧上下文。CBPeripheral.identifier只用于系统提供的本机设备引用，不作为密码学身份。

读取RSSI只在已锁且确有回来检测候选的受限窗口进行，按能耗实测定生命周期，不把0.5秒轮询变成全锁屏常驻负担。iOS后台恢复文档不能当作macOS自动拉起承诺。

真机记录“断开/发出read/超时/宽限开始/倒数/发锁/系统确认”各时刻。约11.5秒只覆盖宽限和倒数，实际从物理离开起还可能含读取检测时间，例如5+2+1.5+10秒，不能作统一硬上限。分别测手机设置关闭蓝牙、Mac蓝牙关闭、走远、睡眠、权限失效、手表并存、同名设备，Aaron在场。
```

### 5D：替换L4的URL scheme一条；在L4末尾追加

windowshade://lock若保留，只标为外部锁屏请求。本地URL不能证明来自iPhone，也没有自动建立跨设备通信。不得写“从iPhone锁上的”，不得给予动态锁自动解锁来源。真正的远端认证通道另属主模型范围。
