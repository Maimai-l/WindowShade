# D5 · 控制中心遥控协议探针

**目标与验收：**先证明Swift服务端能被iPhone发现、配对并收到可解释的事件；密码学与身份失败一律不进入D1。

**入口：**不再自动新建Rust目标。主模型冻结Swift方案；itsytv-core只是客户端协议零件候选。 路径以原包 `code/prototype/` 为基准，`Core/` 新文件遵守原包允许列表。

## API 与最低系统
Network/Security/CryptoKit，最低macOS14；`NWListener(using:on:)`、`NWListener.Service(name:type:domain:txtRecord:)`、`NWConnection.receive(minimumIncompleteLength:maximumLength:completion:)`。Bonjour service名和Companion帧字段按固定提交抓包验证，不能猜。PIN用系统随机；长期私钥进Keychain。

## 最小骨架
下列是原创边界示例，不是完整功能。编译范围见 [validation.md](../validation.md)；Apple SDK 片段没有在本次环境编译。

```swift
import Foundation
// 这里只生成 PIN；协议证明必须使用已审计的服务端配对实现。
func makePairingPIN() -> String {
    var rng = SystemRandomNumberGenerator()
    return (0..<4).map { _ in String(Int.random(in: 0...9, using: &rng)) }.joined()
}
struct PairingWindow {
    let deadline: Double
    private(set) var failures = 0
    mutating func failedAttempt() { failures = min(3, failures + 1) }
    func mayAttempt(now: Double) -> Bool {
        now.isFinite && now < deadline && failures < 3
    }
}
```

## 坑与绕法
现有 itsytv-core README 声称 MIT，但 LICENSE链接本次取不到，不能据此批准拷代码。客户端PairSetup/PairVerify不能改几个名称变服务端。verify必须核对已登记客户端签名、公钥、完整transcript、nonce方向计数；未知key/重放/错tag拒绝。

## 测试与真机
纯解析测试：TLV8分片、重复字段、溢出、截断、AEAD失败、重放、并发配对、3次/60秒/300秒冷却。Aaron在场真实发现→配对→重连→撤销→拒绝；取证不留PIN/密钥。

## 不做与未决
不复用上游WebInspector/控制HTTP端口，不接shell，不广播项目名，不把控制中心可连上等同通过第二因素认证。没有真机协议回放只能交探针，不宣称可用。
