# D6 · Codex App Server 适配

**目标与验收：**一条受控stdio连接管理请求、通知和服务端审批；正常结束、失败、断流、未知提交结果可区分。

**入口：**原包后端适配文件；先用fixtures假进程，不启动真实付费任务。 路径以原包 `code/prototype/` 为基准，`Core/` 新文件遵守原包允许列表。

## API 与最低系统
Foundation `Process`、`Pipe`、`FileHandle`，最低macOS14。JSON行协议省略jsonrpc字段。顺序initialize→response→initialized→model/list分页→thread/start或resume→turn/start；活动轮中`turn/steer`必须expectedTurnId；终止用turn/interrupt。精确字段/回包见 reference/hooks-and-app-server.md。

## 最小骨架
下列是原创边界示例，不是完整功能。编译范围见 [validation.md](../validation.md)；Apple SDK 片段没有在本次环境编译。

```swift
import Foundation
struct JSONLinesDecoder {
    enum Failure: Error { case frameTooLarge }
    var maxBytes = 1_048_576
    private var buffer = Data()
    mutating func feed(_ bytes: Data) throws -> [Data] {
        var frames: [Data] = []
        for b in bytes {
            if b == 0x0A {
                if !buffer.isEmpty { frames.append(buffer) }
                buffer = Data()
            } else {
                guard buffer.count < maxBytes else {
                    buffer.removeAll(keepingCapacity: false)
                    throw Failure.frameTooLarge
                }
                buffer.append(b)
            }
        }
        return frames
    }
}
```

## 坑与绕法
stdout只收协议，stderr独立有界脱敏；不可等termination后才读管道。server request和client response按是否有method分流，ID可能同数但不同方向。收到turn/start回应不等于已完成；断流后不自动重放提交。thread/resume也不证明接管原终端当前活动进程。

## 测试与真机
假后端：半帧/合帧/超长、错误JSON、重复ID、initialize失败、分页、旧turn回包、serverRequest/resolved、断线时审批、interrupt与完成竞争。全通过后Aaron确认真实CLI和小任务。

## 不做与未决
不填凭据、不加bypass、不请求acceptForSession、不修改sandbox/approvalPolicy来方便测试。自有会话和旁观会话能力分开，旁观只能显示和“去看看”。
