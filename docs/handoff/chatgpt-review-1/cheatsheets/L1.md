# L1 · 离开状态机

**目标与验收：**只有已建立的有效存在信号丢失才进入宽限和倒数；取消、手动锁屏、旧连接回包都不能误触发自动解锁。

**入口：**新增 Core/PresenceLock.swift；读取 Core/SessionLockState.swift 的实际定义位置。 路径以原包 `code/prototype/` 为基准，`Core/` 新文件遵守原包允许列表。

## API 与最低系统
Foundation，最低 macOS 14；仅值类型事件。建议 `readStarted(epoch:requestID:at:)`、`readCompleted(epoch:requestID:at:)`、`lockObserved(source:sessionID:)`；输入时间来自同一连续时钟。输出 `requestLock(sessionID:)` / `requestIdentityCheck(sessionID:)`，不输出“解锁成功”。

## 最小骨架
下列是原创边界示例，不是完整功能。编译范围见 [validation.md](../validation.md)；Apple SDK 片段没有在本次环境编译。

```swift
import Foundation
// 只管理一次读请求；连接身份、连续失败和锁屏归属由外层状态机处理。
struct PresenceRead {
    struct Pending { let epoch: UInt64; let id: UUID; let deadline: Double }
    private(set) var pending: Pending?
    mutating func begin(epoch: UInt64, id: UUID, now: Double) -> Bool {
        guard pending == nil, now.isFinite else { return false }
        pending = Pending(epoch: epoch, id: id, deadline: now + 2)
        return true
    }
    mutating func reply(epoch: UInt64, id: UUID, now: Double) -> Bool {
        guard let p = pending, p.epoch == epoch, p.id == id,
              now.isFinite, now < p.deadline else { return false }
        pending = nil
        return true
    }
    mutating func expire(now: Double) -> Bool {
        guard let p = pending, now.isFinite, now >= p.deadline else { return false }
        pending = nil
        return true
    }
    mutating func invalidate() { pending = nil }
}
```

## 坑与绕法
“每5秒读”和“2秒没响应”须按单次在途请求解释；一次读取超时不证明人离开。蓝牙状态用 unknown/available/unavailable，而不是默认 disconnected。手机+手表的组合策略、摄像头独立触发条件需要主模型冻结。锁屏来源只能依据自己发出的锁请求与系统回执关联。

## 测试与真机
纯逻辑：2秒边界、迟到/重放回包、取消优先于截止、60秒重入、双设备一离一在、Mac自身蓝牙关闭、休眠、手动锁屏不能自动解锁。真机锁屏和故障注入必须 Aaron 在场。

## 不做与未决
不得把 RSSI、看到一张脸、设备名字当作身份。F1/L3 尚未证明第二因素前，只交付状态机与默认关闭的探针。
