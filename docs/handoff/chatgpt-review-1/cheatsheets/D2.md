# D2 · 能力快照与一次性确认票

**目标与验收：**只显示当前后端真实支持的 model/effort；换模型、项目、草稿或连接后，旧确认票全部失效。

**入口：**新增 Core/BackendCapabilities.swift 等原包允许文件；不改现有 gesture 分类阈值。 路径以原包 `code/prototype/` 为基准，`Core/` 新文件遵守原包允许列表。

## API 与最低系统
Foundation，最低 macOS 14。Codex `model/list` 的 `supportedReasoningEfforts` 是含 `reasoningEffort` 的对象数组；还有 `model`、`id`、`defaultReasoningEffort`、`nextCursor`。正式请求使用协议定义的 model 标识，不按展示名构造。

## 最小骨架
下列是原创边界示例，不是完整功能。编译范围见 [validation.md](../validation.md)；Apple SDK 片段没有在本次环境编译。

```swift
import Foundation
struct EffortTicket {
    struct Binding: Equatable, Sendable {
        let peerKeyDigest: Data
        let projectIdentity: String
        let session: UUID
        let connectionEpoch: UInt64
        let model: String
        let capabilityRevision: UInt64
        let effectiveEffort: String
        let workflow: String?
        let draftDigest: Data
    }
    let binding: Binding
    let deadline: Double
    private(set) var consumed = false
    mutating func consume(for current: Binding, now: Double) -> Bool {
        guard !consumed, current == binding,
              now.isFinite, now < deadline else { return false }
        consumed = true
        return true
    }
}
```

## 坑与绕法
不要把 low/medium/high/xhigh 固定映射成所有提供商通用档位。UI 的 max/ultra 是用户意图，必须有明确 capability 绑定；ultracode 只是尚未核准的工作流配置，不能冒充官方原生参数。确认票不是生物或设备授权。

## 测试与真机
测分页、空能力、未知 effort、id/model 不同、能力 revision 更新、不同 draftDigest、过期时刻、新连接、重复消费。真实能力验收需固定本机 CLI 版本和完整脱敏响应。

## 不做与未决
不悄悄降级高 effort，不用旧能力缓存执行新请求；不靠按钮文案改变模型配置。
