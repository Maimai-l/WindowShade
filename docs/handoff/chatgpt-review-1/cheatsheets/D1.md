# D1 · 指挥会话与异步边界

**目标与验收：**所有输入都先经过会话、连接代次和序列验证；长按、手势、草稿与后端回调不会串台或重复提交。

**入口：**新增 Core/ConductorSession.swift；复用已有 Core/ConductorGesture.swift。先依赖 D2 和 I1 的归一事件契约。 路径以原包 `code/prototype/` 为基准，`Core/` 新文件遵守原包允许列表。

## API 与最低系统
Foundation，最低 macOS 14。复用 `ConductorRecognizer.recognize(_:)`、`normalized(_:yAxisDown:)`。新事件 envelope 必含 peer/session/connectionEpoch/sequence，异步结果再带 commandID、backendTurnID。Touch ID 只产生 `requestAuthorization` effect。

## 最小骨架
下列是原创边界示例，不是完整功能。编译范围见 [validation.md](../validation.md)；Apple SDK 片段没有在本次环境编译。

```swift
import Foundation
struct ConductorBoundary {
    struct Envelope: Sendable {
        let epoch: UInt64
        let session: UUID
        let sequence: UInt64
    }
    let epoch: UInt64
    let session: UUID
    private(set) var lastSequence: UInt64 = 0
    private(set) var strokeInProgress = false
    mutating func accept(_ e: Envelope) -> Bool {
        guard e.epoch == epoch, e.session == session,
              e.sequence > lastSequence else { return false }
        lastSequence = e.sequence
        return true
    }
    mutating func cancelInput() { strokeInProgress = false }
}
```

## 坑与绕法
中心确定键在原 D1 枚举漏了。Play 长按切模式不能再发短按的媒体或提交动作；短按必须等松手判定。取消后等所有接触点抬起再重新武装。旧 epoch 的后端完成也不能重写新会话。“voiceCheck 两个 true”不得直接 allow。

## 测试与真机
测5/6拍必须完整结束后另一次新点击、超长按一次、释放不再点击、取消后残余触点、切模型/项目时在途回调、断线后未知提交状态、序号回退。Aaron 真机只在假后端控制下先校验按键。

## 不做与未决
无系统输入合成、网络、音频采集或真实执行。双 Back 清草稿的有效时间窗由主模型给值；不擅自把“第二次”解释成永久有效。
