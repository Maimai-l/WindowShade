# A1 · 会话与待批准请求

**目标与验收：**同项目不同助手/会话不串线；批准、超时、断连都只结束对应请求。状态能显示未知，不编造完成或断线。

**入口：**新增 Core/AgentSessions.swift；共用主模型冻结的审批 envelope，不另建第二套授权账。 路径以原包 `code/prototype/` 为基准，`Core/` 新文件遵守原包允许列表。

## API 与最低系统
Foundation，最低 macOS 14。会话键 `(provider, sessionID)`；请求键再加 connectionEpoch、requestID。事件接收时间、本地单调序号由桥生成；外部 eventID 若存在只作去重证据。风险判定返回 `normal/high/unknown`，没有 `autoAllow`。

## 最小骨架
下列是原创边界示例，不是完整功能。编译范围见 [validation.md](../validation.md)；Apple SDK 片段没有在本次环境编译。

```swift
import Foundation
struct AgentApproval {
    struct Key: Hashable, Sendable {
        let provider: String
        let session: String
        let request: UUID
        let epoch: UInt64
    }
    let key: Key
    let actionDigest: Data
    let deadline: Double
    private(set) var resolved = false
    // 仅匹配/消费 UI 请求；返回 true 不等于已获 AuthorizationLedger 授权。
    mutating func take(key: Key, digest: Data, now: Double) -> Bool {
        guard !resolved, self.key == key, actionDigest == digest,
              now.isFinite, now < deadline else { return false }
        resolved = true
        return true
    }
}
```

## 坑与绕法
10分钟没事件只能标“暂未更新”，长任务可能仍在执行。120秒是本产品等待上限，须小于 hook 宿主实际超时并预留传输时间。命令字符串前缀无法可靠判断脚本的全部副作用；分类只能提高警惕，不能降低宿主审批。丢事件时保留未知。

## 测试与真机
测同项目两会话、两提供商同 ID、乱序、重复、过期回答、切换项目、锁屏、并发两批准、队列容量溢出。真机先用假事件，无需真实 CLI；授权有效性由 A4 专项测试。

## 不做与未决
骨架 take 只消费 UI 请求，不构造 AuthorizationGrant。不得解析或读整份 transcript；不得让不受信任的 hook 文本变成下一条系统指令。
