# L2 · 蓝牙存在信号适配

**目标与验收：**先证明有可读取的真实 characteristic，再让请求/回复进入 L1；没有证据就显示未知且不开自动锁。

**入口：**新增原包 PresenceMonitor 与主模型冻结的 capability 接口；不越界实现登录密码。 路径以原包 `code/prototype/` 为基准，`Core/` 新文件遵守原包允许列表。

## API 与最低系统
CoreBluetooth，工程最低macOS14；`CBCentralManager(delegate:queue:options:)`、`scanForPeripherals(withServices:options:)`、`stopScan()`、`connect(_:options:)`、`cancelPeripheralConnection(_:)`；`CBPeripheral.discoverServices(_:)`、`discoverCharacteristics(_:for:)`、`readValue(for: CBCharacteristic)`、`readRSSI()`；delegate 用串行队列。

## 最小骨架
下列是原创边界示例，不是完整功能。编译范围见 [validation.md](../validation.md)；Apple SDK 片段没有在本次环境编译。

```swift
import Foundation
import CoreBluetooth
// 所有 CB 对象留在串行队列内；此骨架不扫描、不申请权限、不伪造 iPhone 服务。
final class PresencePeripheralReader: NSObject, CBPeripheralDelegate {
    let queue = DispatchQueue(label: "windowshade.presence.reader")
    func read(_ characteristic: CBCharacteristic, on peripheral: CBPeripheral) -> Bool {
        dispatchPrecondition(condition: .onQueue(queue))
        guard peripheral.state == .connected,
              characteristic.properties.contains(.read) else { return false }
        peripheral.readValue(for: characteristic)
        return true
    }
    func peripheral(_ peripheral: CBPeripheral, didUpdateValueFor characteristic: CBCharacteristic,
                    error: (any Error)?) {
        // 在这里关联唯一在途 request/epoch；只把值类型结果交给状态机。
    }
}
```

## 坑与绕法
0x180A 是 service，不是可读值；不能假定原生 iPhone/Watch 始终广播这个服务。identifier是本机外设检索句柄，不是加密身份。每个特征最多一笔在途 read，回调没有你的 requestID，桥须自己关联；重连推进 epoch。RSSI127等异常值用未知。

## 不做与未决
不照搬 iOS 状态恢复自动后台重启承诺到 macOS。先证明 F1/L2 路线，无法证明时不另加手机 App 或扫描所有设备交差。
