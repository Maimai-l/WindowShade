# 流程审查：侧拉和启动台

用户确认方向：iPadOS 26 单扇浮窗，连续拖动、换边、收放。下面区分源码可证实的问题、当前修复及未验证范围；不把 DeepSeek 的原始静态猜测直接当 bug。

| 流程 | 原有问题 | 本轮处理 |
| --- | --- | --- |
| 进入侧拉 | 普通窗口没有直接拖入入口 | 标题栏拖到空闲侧边中段，停250毫秒后松手；离开取消，窗口未跟随不接收 |
| 从把手拉出 | mouseDown立即打开，滚动过阈值才启动动画；没有连续位置 | 接入开始、增量、松手、系统取消；位置写入合并为最新目标 |
| 手势退出 | 退出必须保留拖放落点，不被旧动画或临时置顶接回 | 标题栏拖到中间停下松手退出，实窗检查验证位置、尺寸和置顶清理 |
| 动画中重新拖标题栏 | 标题栏只停普通手势动画，没有停侧拉自己的动画 | 抓住窗口即取消侧拉滑行，取消旧完成回调 |
| 往另一边移动 | 向内甩退出侧拉并平铺半屏；换边重新拉满高度 | 横向甩换边仍保持侧拉，保留宽高；普通点击不触发布局 |
| 拖动后恢复 | 慢应用积压位置、取消时旧写入追上来 | 串行前序屏障，停止后等待正在写的那一次结束，再交给落定动画 |
| 快速收放 | 正在创建的置顶无法停止，旧启动结果晚到 | 给置顶启动加请求标识并取消在途请求，侧拉回调核对代数 |
| 更换目标/跨桌面 | 镜像异步失败与延时回调可能操作新对象 | 核对镜像实例、请求代数与当前窗口 |
| 用户调整大小 | 收放/换边可能强行重置尺寸 | 从真实窗口记录宽高，初次进入与后续换边分开 |
| 退出/屏幕拔除 | 边缘窗口可能留在屏幕外 | 正常退出恢复；显示器失效终止侧拉并夹回可见区域 |
| 异常退出 | 只露4点的窗口没有恢复记录 | 进入前耐久写入，重启核对两个进程启动时间和窗口编号，恢复成功才清记录 |
| 启动台拖出边界 | 在另一屏/菜单栏外松手仍启动应用 | 边界外松手取消，AppKit 回归测试已通过 |

## 还要区分的事情

- 同时运行两个开发版属于运行环境冲突，会使快捷键和全局手势观察难以归因。新版本交付时应只保留一份运行实例。
- 其他 Space 上看到的是实时画面，不是真正可编辑的浮窗。这是 Mac 窗口权限边界，不应包装成完整 iPadOS 同款。
- 慢应用的 AX 写入延迟无法凭纯函数测试保证。必须检查真实中间位置、反向、松手与退出。
- 原有用户置顶与侧拉临时置顶已区分，退出恢复原置顶；生产探针已验证此路径。
- 真实多指触控、跨屏拖动与全套辅助功能操作尚未全面实机覆盖，不能称“全部 bug 已消灭”。

## 独立审计的验收

DeepSeek 的原始启动台报告中存在虚构的 silent 开关、忽略 guard 的不可达路径和已修行为的误报。仅接受“屏幕外松手仍启动”这一项，其他不直接据此改代码。其后测试任务长度耗尽且没有写文件，主代理接手编写同步屏障测试并验证。

## 尚未通过的检查
