# niri：卷动平铺，和我们怎么超过它

2026-09-28 调研。Aaron 把 niri 加进竞品，要求做到超越。

## niri 是什么

Linux 上的 Wayland 合成器（Rust 写的，GPL-3.0，GitHub 约 2.8 万星），最新是 26.04 版。它的核心是**卷动平铺**：

- 一块屏上的窗口排成一条横着、没有尽头的卷轴，一列挨一列；新开的窗口接在当前这列右边，**别的窗口不变窄**。
- 列宽有几档，默认 ⅓、½、⅔，Mod+R 在几档之间换；一列里可以上下叠几扇，也可以叠成标签页。
- 触控板三指左右滑，整条卷轴跟着手指走；三指上下滑换工作区；四指上下滑打开概览（25.05 起）。
  鼠标 Mod+拖动挪窗口，屏幕左上角是打开概览的热角；25.11 起按住标题栏横着拖也能滑动卷轴。
- 工作区上下排、按需增减，每块屏各有一套。概览把所有工作区和窗口缩小铺开，可以拖着窗口换工作区。
- 25.11 加了带实时画面的 Alt-Tab、真正的最大化；26.04 加了背景模糊。边框、间距、动画、着色器都能配置（KDL 配置文件，改了立刻生效）。

它自己说是从 GNOME 的 PaperWM 学来的。macOS 上已经有好几家照它做：

- Paneru（开源，MIT，约 2.3 千星）：同样的卷轴，要求打开“显示器具有单独空间”，建议把显示器上下排——
  macOS 不让窗口整个离开屏幕，停在外面的窗口要在屏幕边上露一条边，左右挨着别的显示器时会被系统挪过去。
- PaperWM.spoon（Hammerspoon 插件，Lua 配置）、OmniWM（只支持 macOS 26 起）、ChainYourMac（$9.99，有图形设置）。

## 超过它的地方（本地，未发布）

WindowShade 不是合成器，没法替别的 App 画窗口。所以不是去做第二个 niri，而是把它最好的那一点——**开新窗口不挤别人，
手指一滑就过去**——接进我们已有的同一套动作里，再补上它没有的：

| | niri | WindowShade（本地） |
| --- | --- | --- |
| 窗口不挤：一条横着的卷轴 | ● 一直是卷轴 | ● 放得下就一屏排好（魔法平铺 5:5、6:4、7:3），放不下才接成卷轴 |
| 新开的窗口 | ● 接在当前列右边 | ● 同样；关掉、最小化、被人拖走的让出位置 |
| 手指滑卷轴 | ● 三指在哪都行 | ● 两指在标题栏上（这台 Mac 的三指给了三指拖移，四指给了切桌面） |
| 列宽几档 | ● Mod+R：⅓ ½ ⅔ | ● 上下滑或 ⌃⌘↓↑：⅓ ½ ⅔ 整屏，最窄再往上推收起——还是那架“变大一级、变小一级”的梯子 |
| 新窗口多宽 | ◐ 统一默认，按 App 要自己写窗口规则 | ● 按 App 定：浏览器、写代码、做设计 ⅔，写作、笔记、终端 ½，访达这类 ⅓，不用配置 |
| 聊天窗口 | — | ● 自动放进侧拉，不占卷轴 |
| 撤回 | — | ● 捏合整条放回原处 |
| 收起、看一眼、刘海收纳 | — | ● |
| 停在屏幕外的列 | — 看不到 | ● 露一条边；指针停上去看一眼它此刻的样子（实时画面，只供看），单击那一条把那一列滑出来 |
| 走到左右那一列 | ● Mod+方向键 | ● ⌃⌘←→；点到露着一条边的窗口它自己滑出来 |
| 概览 | ● 缩小所有工作区、能拖放 | ◐ 卷轴里任何一扇的标题栏上两指张开：整条卷轴缩小铺开，点哪扇去哪列（←→ 挑、回车去、Esc 收）；不能拖着换位置 |
| 工作区 | ● 上下排、按需增减 | — 用 macOS 自己的桌面 |
| 标签页式的一列 | ● | — 不做 |
| 动画、模糊、边框、着色器 | ● 合成器自己画 | — 做不到：别的 App 的窗口不归我们画 |
| 配置 | KDL 文件，热重载 | 不用写配置 |
| 平台 | Linux（Wayland） | macOS 14 起 |

对 macOS 上照它做的几家，多出来的是：放得下时不强行卷动；按 App 定宽不用配置；挪窗口放在每个 App 各自的后台队列上，
慢 App 跟不上时跳过中间几帧，不拖慢手指；有一边挨着别的显示器时不硬排，放不下的收进刘海；整条能撤回。

## 边上那一条、卷轴概览（本地，未发布）

**看一眼边上那一条。** 指针停在停靠列露出来的那一条上（停够 0.3 秒，路过不算），旁边出现那扇窗此刻的样子，
整扇按比例缩小、最宽占半屏；指针离开那一条就收回。真窗口不动、不激活。
和卷帘条上的看一眼是同一件事，跟着同一个开关（设置里关掉看一眼，这里也不出；卷轴开着时拨这个开关立刻生效）。

- 卡片只供看、不接点击：它盖着屏幕边那一列的一部分（比如那一列的滚动条），点下去照旧落在底下的窗口上；
  指针一离开那一条，哪怕是往卡片上移，卡片就收。要那一列就单击那一条本身（原来就这样：点到停在边上的窗口，
  卷轴把它整列滑出来），按下去那一刻卡片就收，滑出来之前不再冒。
- 两边各只给离屏幕最近的那一列（滑一下就到的那列）；更远的几列叠在它底下，在概览里看。
  更远那列的窗口恰好在上层时（⌘Tab 过去又滑回来），指针下露着的是它，看的也是它。那一列叠着几扇，每扇各占自己那一段。
- 那一条被别的 App 的窗口、侧拉的把手盖着时不开：指针是在用上面那扇。
- **停靠的那一边让出 10 点。** 挨着停靠列的那一列，边正好停在屏幕边上时（差 2 点以内也算，吃掉取整误差），卷轴让它在那一边缩进 10 点，
  停靠列那一条露在外面，间隙为 0（默认）时指针甩到屏幕边也能开。
  滑动途中不改窗口大小：停着时让出的那 10 点一路保留，只有停靠列滑进屏幕时才撤掉，免得两扇之间空出一道缝。
- **伸出屏幕边的那一列：借屏幕边最外面 4 点。** 列宽不一样时（⅔ 旁边接 ½）挨着的那一列常伸出屏幕边，它保持原宽
  （要让出 10 点就得缩掉几百点），两扇在那里重叠。停靠的那扇在上层，整条都能开；伸出来的那一列在上层，只有屏幕边最外面
  4 点还算那一条——指针甩到屏幕边就停在那里；往里一点是在用那一列，不开。借这 4 点不抢那一列的东西：列宽只有几档，
  伸出去的列至少伸出六分之一屏，它的竖滚动条、拖着改大小的边都在屏幕外；盖着的那扇边离屏幕边不到 24 点时照样不开。
  卡片不接点击，在那里按下去照旧落在那一列上（卡片立刻收）。不改任何窗口大小、滑动时也不多做事，只在停够时多比一次外框。
  单测把 ⅓ ½ ⅔ 整屏四列的所有组合、每个吸附位置、三档留缝都过了一遍：指针甩到有列停着的那一边，总能落在那一条上。
- 换桌面、切到别的 App、锁屏、屏幕睡了就收，实时流一起停（原有的看一眼也是这时收）。
- 画面：先放一张后台截的截图，同时开一路只有卡片那么大的实时流接替，卡片一收流立刻停；没有屏幕录制权限时不开。
- 只在卷轴开着、而且有列停在边上时才听指针移动、按下和上面这几条系统通知（不轮询）；卷轴一动就先收掉。
- 真机：`--strip-peek` 已按上面这些改过，先照真实遮挡停一次、打出间隙和指针下是哪扇、开没开，再只按几何测其余几条；
  最后把第一列加宽一档摆出“伸出屏幕边的那一列在上层”，照真实遮挡测屏幕边最外面那几点开、往里 5 点不开。改过之后还没在真机上跑。

**卷轴概览。** 卷轴里任何一扇的标题栏上两指张开（张开走满、松手），整条卷轴缩小铺在这块屏上，列间留空，
此刻露在屏幕上的那一段框出来；点哪扇就把它那列滑出来、焦点给它。←→ 换列、↑↓ 在一列里换、回车去选中的那扇，
Esc、点空白处、切到别的 App、换桌面、锁屏就收起，窗口一扇不动。

- 为什么是张开：卷轴里的窗口张开原本不做事（已经排好了），普通标题栏上张开是“把窗口铺开排好”，这里是“把整条铺开看”，
  意思一致；捏合照旧是整批撤回。它不改任何已有手势。鼠标没有张合，要靠菜单或快捷键（见下）。
- 画面是打开那一刻的截图（后台截，不开流）：概览只停一下，不为每扇窗各开一路实时流。
- 面板不激活 WindowShade：前台 App 不变，键盘先交给概览，收起后还给它。

## 还差的，和不追的

- 还差：卷轴概览的菜单项和快捷键（快捷键默认关）；概览里拖着换位置。
- 竖着放的屏幕上下卷：不做，照旧收进刘海。卷轴靠“停在屏幕外、露一条边”，往下停可以（窗口上沿还在屏幕里），
  往上停不行：macOS 让有标题栏的窗口上沿待在屏幕里（NSWindow.constrainFrameRect 在窗口放上屏幕、改大小时把上沿拉回来，
  菜单栏上面也放不进去）。滑出上沿的行没处停，只能跳到下面去，一条卷轴就断成两截。AeroSpace 藏窗口也只停在下面两个角上。
- 不追：合成器才做得到的（所有窗口 120 帧动画、模糊、边框、着色器）、自己的工作区、标签页式的列、脚本和 IPC。
