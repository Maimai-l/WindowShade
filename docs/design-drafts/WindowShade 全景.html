每条线只管把真实发生的事交上来；呈现、仲裁、放行、登记各只有一处。哪条线先做都接在这四处上，不另造第二套。

刘海此刻听谁的

七条线同时有话说时，从上往下，先到先占。上面的让出位置后，下面的接着原样回来，不补播。

要你放行的事

刷脸解锁、Touch ID 确认、agent 审批。独占交互，其它活动暂存；一结束就恢复仍有效的那一个。只认进入审批之后的新动作，之前那一下 Select 不算。

你正在做的事

指挥手势画到一半、按住说话、拖着标题栏到刘海（落点小岛）。手离开之前，什么提醒都不进来。

你主动打开的

指针停在刘海上展开的那一排、看一眼、展开的详情。普通更新不能把它顶掉，只能在原处更新数字。

短暂提醒

“妙控鼠标已连接”、电量低、有变化时提醒、卡住时提示。约 4 秒；0.6 秒内的合成一句；遇到上面三层就进次区域，留一个小点，不抖不闪。

持续活动

音乐、CarPlay、录音、隔空投送、路线、agent 在跑。最多三个，两指横扫切换；内容更新不打乱选中项。

什么都没有

刘海和实体刘海重合，一个像素都不画，不刷新。

锁屏、切换用户、关掉功能：清掉所有可见内容和输入。解锁后只显示当前状态，并给一条“离开期间”的摘要。

五种形状，一套弹簧

数值沿用设计规范 v2 的动效记号。形状先动，内容在形状走到四成后淡入；减少动态效果时只淡入淡出。

最小

只露一个点或图标，在刘海一侧。多个活动时其余的退到这里。

calm 0.34 / 1.0

紧凑

刘海左右各长一段：左边是谁，右边是数（3 扇、12 分钟、82%）。

settle 0.38 / 1.0

短暂提醒

一句话，约 4 秒。主句说事，副句给数。

bloom 0.42 / 0.84

展开

指针停住或点开：那一排窗口、详情、摘要、审批。

expand 0.40 / 0.92

交互

正在认你、正在画手势、正在录音、正在倒数。给每一步即时反馈，结果出来前不打对勾。

pop 0.30 / 0.75 · 逐拍

信任：要做的和不做的

要做

  • 刷脸解锁照 Glance 的方式真正解锁，开启前写明风险；脸（含严格活体和注视）和手机或手表的蓝牙因素都对，才输入密码。
  • 每次放行绑定一件事：用途、目标摘要、随机数、期限、会话代次，用一次就作废；取消后晚到的成功不算。
  • 因素算对：脸加指纹是两种生物特征，不自动算两个因素；设备私钥加系统生物识别，才是一个多因素认证器。
  • 离开就锁、偷看收私人窗口，都给倒数，碰一下就取消；系统的 Touch ID 和密码永远是出路。
  • 声纹作辅助因素：脸的分数落在门槛附近、或放行高风险的事（agent 推送、关安全设置）时，说一句随机短语补一道。只加不减：不单独放行，不顶替手机或手表；随机短语加活体，挡录音重放。
  • 私有 API 能达成目的就用（Aaron 定：不走 App Store）；用了就登记到隐私一栏的第三层，系统更新后失效时有退路。
  • 设置里的“隐私”把读到的每一样摊开：原值、为什么、去了哪里。

不做，或先过审查再说

  • 心率、脸红不当解锁依据：生理反应说明不了是谁、诚不诚实（美国国家研究委员会的测谎审查）。
  • 声纹不单独放行：NIST SP 800-63B-4 不把声纹当认证因素，所以它只在脸和手机之外补一道，不能替代它们。
  • 健康数据不进放行：Apple 协议限制 HealthKit 的用途，转成蓝牙或 JSON 也不变。
  • atv-core 的“已验证”不当授权：它没验客户端签名就发了 Verified，接 agent 前先补好。
  • 不往前台窗口盲发回车；不偷偷开一段空对话冒充接管原会话；不默默降档还写着 xhigh。
  • AirBattery（AGPLv3）只作研究来源，不拷代码；Loupe 的名字、图标、图片不用。

Aaron 定（2026-10-03）：不走 App Store 分发，Apple 协议里 Face Data 的用途限制不作为门槛；私有 API 能达成目的就大胆用。

能耗预算

“M 系芯片用好”的意思是：重活放到合适的单元，闲着就真闲着。数字都要实测，不抄论文。

线什么时候干活放在哪验收
窗口画面看一眼、那一排展开时ScreenCaptureKit + GPU 缩放收回后不再截图
实时活动事件来了才读；播放器只在有变化或 30 秒兜底时问后台串行队列，E 核空闲时为零查询
设备电量连上 / 断开靠匹配通知；连着时 2 分钟一读后台，不进绘制和输入回调待机没有 display-link
刷脸解锁停手 30 秒后才看；每秒 2 帧Vision + ArcFace 在 ANE停手一小时的耗电实测
蓝牙因素认你、离开判断时扫描有占空比和不开时比，差值实测
指挥模式打开指挥模式时才连遥控器识别器纯计算，输入到反馈 p95 ≤ 50 毫秒（目标，未测）关掉后连接也断
整体现在实测：空闲约 3.3% CPU、约 4550 次唤醒/秒（性能文档第七节），已定位并修了音频进程扫描，待换新构建复测空闲 CPU 和唤醒都不高于 1.0.15

写给接手的人：照这个方向走，不要绕开

这一页是 WindowShade 的总图，仓库里的同一份是 docs/blueprint.md，AGENTS.md 第一行指向它。接手的模型或人，先读这一节和下面四份，再动代码。做不到就停下来写明卡在哪，不要换一个更容易的东西交差。

隐私一栏、核对表、P1–P6
  1. 七条线都是目标，没有一条是偏航。窗口、实时活动、电量、CarPlay、指挥模式、刷脸解锁、隐私，进度各记各的，谁也不替代谁。觉得哪条“不该做”，先读 direction.md 再说。
  2. 一个宿主，一个协调器。所有东西都长在已有的刘海面板里，经活动协调器按仲裁顺序出场。不新建浮层、认证窗口、菜单栏小工具，不拿预览窗口当成果。
  3. 状态来自数据，不来自动画。动画回调不决定连上没有、认出没有、放行没有。结果出来前不打对勾。
  4. 未知就是未知。没读到不写 0%，没跑的场景不写通过，没核的话不上界面和官网，模拟数据不冒充真机。
  5. 放行只走授权账。一次性、绑定用途和目标、可撤销；心率、健康数据、atv-core 的 Verified 都不放行；声纹只作辅助因素，不单独放行。
  6. 读什么都登记。新加一个读取点，先登记到信号登记表，隐私一栏自动多一行。
  7. 能耗写进验收，只做纯赚的改动。空闲 CPU 和唤醒不高于 1.0.15；已有的行为不许变差。
  8. 文案照 copy-guide。一个东西一个名字：收起窗口、收进刘海、看一眼、实时活动、刷脸解锁、指挥模式。
  9. 不碰 Aaron 的东西。不动他的真实窗口，探针只用临时窗口、只在他离开或空闲时跑；不退出他日常用的 WindowShade；不提交、不推送、不发布，除非他说。
  10. 许可干净。Glance、Loupe 代码 MIT，带版权声明；AirBattery 只读不拷；Loupe 的名字、图标、图片不用；Apple 的机身素材只用来量，不进仓库。
  11. 便宜模型交来的东西要复核。DeepSeek 等交来的改动和数字，主模型自己看差异、自己复现，再算数。
  12. 每一步都留证据。改完更新对应文档和 1.0.16 对照表：做了什么、怎么测的、真实结果、还差什么。
