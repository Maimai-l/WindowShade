六条原则

系统永远是出路

系统的锁屏、密码框、Touch ID 不被遮挡、不被仿冒。刘海认不出、手机不在、戴口罩、连续 3 次失败，都清清楚楚把人交回系统，不让人对着一颗转圈的岛干等。

两样都对才放行

每次刷脸解锁都要“是你的脸”加“是你的手机或手表”。刘海上两枚小圆点分别亮起，人看得见是哪一样还差。

结果不由动画决定

对勾只在真的认出、真的放行之后出现；密码一个点一个点填进去是真的在输入；桌面展开要等系统确认已解锁，用解锁后的新画面。

从哪里去，就从哪里回来

合盖时桌面折进刘海，解锁后从刘海展开；偷看时私人窗口收进刘海，人走了再从刘海放回。空间关系一路不变。

天天用的不加戏

一天几十次的解锁：短、不回弹。一天上百次的刘海悬停：0.12 秒展开。只有录脸、合盖这种少见时刻，才允许多一点表现。

摄像头可见、可控、少开

只在开盖、唤醒、锁屏、按空格，和你停手 30 秒以后才开；系统绿灯照常亮；每秒 2 帧、在 ANE 上看；图像不落盘。

每一刻的规格

弹簧用设计系统的令牌（response 秒 / 阻尼比）。“减少动态效果”时一律换成 0.18 秒交叉淡化，位置不动。“现在”一栏是 2026-10-03 的实际进度。

时刻看到什么怎么动失败或打断现在

写给接手的人：照这个方向走，不要绕开

这一页是 Aaron 2026-10-03 四轮问答后的定稿方向（逐项决定在 docs/direction.md“刷脸解锁：吸收 Glance”）。接手的模型或人，先读这一节，再动代码。下面每一条都是硬要求：做不到就停下来说明卡在哪，不要换一个更容易的东西交差。

  1. 只有一个刘海宿主。录脸、认你、补光、倒数、偷看提示、窗口那一排，全部长在已有的刘海面板里（App/Notch.swift 一系）。不新建认证窗口、不另起第二套浮层、不再交一个普通预览窗当成果。
  2. 两样都对才代打密码。ArcFace 特征比对（跑在 ANE 上）+ 严格活体 + 注视 + 手机或手表的蓝牙因素，全部通过才在锁屏上输入密码。任何一样只是“看起来通过”（动画对勾、信号强、名字对得上）都不算。
  3. 先把最没把握的做掉。第一件事是蓝牙第二因素的可行性实验：Mac 扮成蓝牙配件、和 iPhone 配对一次、之后靠加密重连证明“是那台手机”；Apple Watch 能不能用要实验说话。做不成就如实写下卡在哪一层，再和 Aaron 定替代，不要悄悄去掉这个因素。
  4. 攻击测试决定说明怎么写。照片、手机屏幕、录像、换人、换手机，每一种都实测；风险说明只写测过的结果。没测过的，一个字都不承诺。
  5. 系统永远是出路。戴口罩、光线太暗补光也不够、手机不在、连续 3 次失败，都回到 Touch ID 或密码；刘海说清下一步，不挡系统的密码框。
  6. 耗电写进验收。摄像头常开只在停手 30 秒后、每秒 2 帧、ANE 推理；蓝牙扫描有占空比；空闲时 CPU 和唤醒次数和 1.0.15 比，不许变差。性能文档第七节的测法照用。
  7. 密码只在授权会话里解开。加密的钥匙由 Touch ID 保护，只在会话期间留在内存，空闲后自己重新上锁；日志里不出现密码、特征、图像、完整设备标识。
  8. 每一步都要能装上、能试、能撤回。先给 Aaron 能装的构建，再写下一步；每一步附真机探针或攻击测试的实际结果，单元测试和模拟数据不冒充真机。

做的顺序

步做什么算完成
F1蓝牙第二因素可行性实验（iPhone、Apple Watch 分开）写清哪条路能走、走到哪一层；能走的给出配对一次、之后加密重连的真机记录
F2把 Glance 的锁屏状态判断、锁屏上抬起面板、按显示器选摄像头，对照接进已有模块锁屏、唤醒、睡眠、换屏都撤得干净；和已有锁屏开合效果不打架
F3在刘海里录脸（九个方向，可录几种样子）；ArcFace 在 ANE 上；特征加密存本机录、删、重录都在刘海里完成；图像不落盘；主线程不卡
F4锁屏认你：补光圈、严格活体、注视、手机因素、3 次失败上限，Touch ID 保护的密码会话两样都对才输入；每种失败都把人交回系统；实测开盖到桌面的耗时
F5攻击测试与风险说明照片、屏幕、录像、换人、换手机都有实测结果，说明只写测过的
F6离开就锁（手机手表走远、摄像头看不到你）、偷看时收起私人窗口倒数可取消；误锁率实测；私人窗口按 App 标、可改
F7回来时的“离开期间”摘要，接上窗口那条线不补播；摘要里每一项都能点到对应的窗口或设备
