层这一行为什么读代码里用的去了哪里开关核对

写给接手的人：照这个方向走，不要绕开

接手的模型或人先读这一节，再动代码。每一条都是硬要求，做不到就停下来写明卡在哪，不要换一个更容易的东西交差。仓库里的同一份在 docs/privacy-page.md。

  1. 先修日志，再上页面。运行记录移到 ~/Library/Logs/WindowShade/，权限 0600；12 处写窗口标题的日志改成不写标题。修完用另一个账户实测读不到。
  2. 清单从代码里来，不手写。每个读取点在一张登记表里登记（照 Loupe 的 SignalProvider 和三层 Sensitivity）；加一个检查：代码里出现名单上的接口却没登记，构建检查就失败。页面和官网都从这张表生成。
  3. 只写核过的。每一句承诺都在 docs/privacy-page.md 的核对表里有证据：联网用 nettop 实测，“不存图”查磁盘写入，“只看键位”查代码和日志。没核过的句子不上页面。
  4. 打开这一页才读。不为这一页加轮询、不常驻。空闲 CPU 和唤醒次数照 performance.md 第七节测，不许变差。
  5. 不新开窗口，不复制开关。“隐私”替换设置里的“权限与启动”，两项授权和“登录时自动启动”都并进来；每个开关仍是原来那一个，改这里那里也变。
  6. 文案照 copy-guide。一个东西一个名字（实时活动、看一眼、刷脸解锁……）；接口名只出现在“显示技术细节”里，这个例外 Aaron 不同意就删掉。
  7. 刷脸解锁的那几行跟着它一起上。蓝牙、人脸特征、存的密码，在功能开着时才出现，写法照 face-unlock.md，不提前承诺。
  8. 每一步都能装上、能试、能撤回。先给 Aaron 能装的构建；Loupe 的代码是 MIT，借结构要带版权声明，它的名字、图标、图片不能用。

做的顺序

步做什么算完成
P1修日志：换位置、改权限、去掉窗口标题另一个账户读不到；日志里搜不到任何窗口标题
P2联网实测：开、关“自动检查更新”各跑一天nettop 记录里只有更新地址；关掉后为零
P3登记表 + 构建检查下表每一行都登记；故意加一个没登记的调用，检查会失败
P4设置里的“隐私”一栏照本页做；原值、展开、开关、深色都对；打开这一页前后耗电不变
P5逐句核对核对表每行都是“已核”，才在发布说明和官网写这一页
P6官网同一份从登记表生成，和 App 里一字不差
