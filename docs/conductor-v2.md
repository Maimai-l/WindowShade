# 指挥模式（WindowShade 2）：交互规格

2026-10-03。Aaron：“指挥手势是在 iPhone 上做的……你先设计好这一整套交互，所有环节都想好……这一整套 experience 将作为 WindowShade 2 来发布，惊艳众人。”

- 可交互设计稿（能在页面上画声调、打拍子、按键试）：[指挥模式](https://claude.ai/artifact/Ku2E7n1xFuXWWjDiF8Ddp1)
- 上游规格：Aaron 的 v3《遥控器、声调与拍子手势、语音编程、灵动岛反馈》和 `CONDUCTOR-ACCEPTANCE.json`（64 个场景），
  在本机交接包 `~/Downloads/WindowShade-Authentication-MFA-Handoff-v4.zip` 的 `prior-v3/` 里，未纳入公开仓库。本文在它之上改了三处，见“和 v3 不同的地方”。
- 已有代码：`prototype/Core/ConductorGesture.swift`（声调、拍子识别纯逻辑），测试 `tests/run-conductor-gesture-tests.sh`。
- 给 DeepSeek 的提示词：[handoff/deepseek-conductor.md](handoff/deepseek-conductor.md)。

**一句话**：打开 iPhone 控制中心里的遥控器，选这台 Mac；在触控区画一个声调选思考档位，打几拍选更高的档或换模型；按住侧边按钮说一句，
松开是草稿；按播放键发出去。每一步刘海都即时说清：画到哪、认出了什么、后端真的接受了没有。不动光标，不碰前台窗口。

## 和 v3 不同的地方

1. **按 Aaron 给的真实遥控器截图排键。**iOS 控制中心的遥控器上是：静音、选择电视、电源；触控区；播放/暂停、返回、电视键。
   **没有 Siri 键**：Apple 的说明是按住 iPhone 侧边按钮用 Siri（[Apple 支持](https://support.apple.com/en-us/102337)）。音量是 iPhone 侧面的音量键。
2. **声纹进高风险放行**（Aaron 2026-10-03 定：声纹作辅助因素）。v3 原来不让声纹产生授权。
3. **加了两条新路**：静音键管 Mac 上的提示音；iPhone 键盘（含听写）可以改草稿（要实验 E3）。

## 手势

| 手势 | 档位域 | 模型域 |
| --- | --- | --- |
| 一声 → | low | 位置 1 |
| 二声 ↗ | medium | 位置 2 |
| 三声 ˇ | high | 位置 3 |
| 四声 ↘ | xhigh | 位置 4 |
| 一到四拍 | low…xhigh | 位置 1–4 |
| 五拍（3+2） | max，点一下确认 | 拒绝：“模型只有四个位置” |
| 六拍（3+3） | ultra：后端有原生值才给；Claude 是“ultracode · xhigh · 工作流程开启”；都没有就“没有 ultra，保持原设置” | 同上 |

四个模型位置在设置里定（provider + model ID），不随后端列表的排序变。判定规则、拒识条件照 `ConductorGesture.swift` 和 v3 §5；
五拍画到第四拍只亮第四个点，不先切到 xhigh。速度不改档位。

## 放行

- **普通**（读文件、跑测试、改工作区里的文件）：审批出现后点一下 = 允许这一次；返回 = 不允许。
- **高风险**（推送、删除、联网、改工作区外的文件、关安全设置）：点一下后刘海给一句随机短语，按住侧边按钮念。
  **配过对的 iPhone（持有）+ 声纹 + 短语（活体）**三样都对才放行；或者到 Mac 前按 Touch ID。声纹不单独放行。
- 审批出现前的那一下不算；遥控器上没有“始终允许”；每次放行绑定请求号、命令、范围，走授权账，用一次作废。

## 提示音（静音键开关）

每完成一拍轻敲一下；认出声调回一个同走向的短音（一声平、二声升、三声先降后升、四声降）；没认出一声低闷的“咚”。跟系统音量走。

## 出岔子

| 情况 | 刘海 | 处理 |
| --- | --- | --- |
| 遥控器关了 / Wi-Fi 断 | 遥控器断开了 | 手势、候选、录音取消；后端照跑；重连只显示现状 |
| 后端断了 | 连不上 Claude | 草稿留着；不重发可能已执行的提交，先查状态 |
| 没认出 | 没认出，保持 high | 不猜最近的档位 |
| 麦克风没声音 | 没有收到声音 | 分清“安静”和“没回调” |
| 后端改了档位 | 要的 xhigh，实际 high | 照实显示读回值 |
| 另一台也在指挥 | 另一台 iPhone 正在指挥 | 同一时间只有一台能发 |
| Mac 锁屏 | — | 清掉项目名和草稿；输入作废；解锁后不自动发 |

## 结构

> 2026-10-03 补：协议层优先用 Swift，零件取自 itsytv-core（MIT），atv-core 只当参考；实体 Siri 遥控器是第二个输入来源（触控面经 MultitouchSupport、麦克风在 `0xFA`），可能先于 iPhone 那条路跑通。见 [input-devices.md](input-devices.md)。

```text
control/remote-host（Rust，atv-core 分支：宣告、配对、原始事件；不碰任何项目和模型）
   ↓ 版本化、验过签名的事件：touch(begin/move/end/cancel)、button(down/up/cancel)、connection
prototype/Core/ConductorSession.swift（纯逻辑：状态机，输入事件 → 新状态 + 要做的事）
   ├─ ConductorGesture（已有）
   ├─ ConductorCapabilities（后端能力 → 允许的档位、ultra 的含义、高开销确认票据）
   ├─ 已有活动协调器（新增活动种类，不另起浮层）
   ├─ 语音采集 + 转写（来源可选）
   └─ Agent 适配器：Codex App Server（initialize、model/list、thread/start|resume、turn/start|steer|interrupt、审批）；Claude Agent SDK 持续会话
```

协议层不接收 shell 字符串、项目路径或模型密钥；它崩了不影响 WindowShade 找回窗口。

## 隐私登记（进 privacy-page 的登记表）

遥控器的触摸轨迹（只在指挥模式开着时，不存）；按住侧边按钮时的声音（转写后丢弃，不写日志）；声纹模板（加密存本机）；配对密钥（钥匙串）。

## 能耗

只在指挥模式开着时宣告和监听；遥控器没连时不轮询；Mac 收到输入到刘海有反应 p95 ≤ 50 毫秒、抬手到结果 p95 ≤ 100 毫秒是目标，实测前不写进宣传。
