- **修了一个真机功能 bug**：刘海「朝刘海甩进去、再拿出来」原来停在拖到的位置，没回到拖之前的地方——
  unshade 的落点取的是（隐藏的）卷帘条位置，而回位校正又把它按回拖到的位置。改成把卷帘条摆到 home
  （按 AX 差值挪，避开卷帘条与窗口的高度差）。`--notch` 的这一条现在通过。
- **卷轴停下来那一段改成和官网一样丝滑**（Aaron 9/30 提）：官网那段是 `requestAnimationFrame`
  驱动的解析阻尼弹簧（ζ=0.88、ω=2π/0.42，投影减速率 0.998）；App 这边原来是 60Hz `Timer`
  每帧固定走 1/120 两小步，掉一帧就慢一截、也不跟刷新同步。现在换成显示器的刷新时钟
  （`CADisplayLink`，最高 120Hz）+ 同一条解析曲线，位置只跟经过的时间有关；减速率也对齐 0.998。
  弹簧公式搬进 `Core/FlickMotion.swift` 的 `FluidMotion`，加了单测（和细步长数值积分逐点对上）。
  重跑 `--strip` 8/0；`--strip-peek` 这次因为有人在用电脑没跑成，等空闲补。
- **卷轴每半秒的对账挪出主线程**：原来是主线程上问 `CGWindowListCopyWindowInfo`（一次约 3 毫秒）
  再对新窗口问 `appWindows(pid:)`（代码里记着一次约 20 毫秒，碰上不响应的 App 能等到 2 秒消息超时）。
  现在这些都交给后台线程（`gatherWatchFacts`），主线程只拿结果对账（`applyWatch`）——动画不再被对账顶掉帧。
- **修了上一轮改动画时带进来的一个回归**：`advanceMotion` 原来每帧都把 `strip.offset` 设成当前位置；
  可 `offset` 是「停稳时在哪」，滑动中正是拿它和当前位置比才知道挨着停靠列的那一列什么时候该让回原宽。
