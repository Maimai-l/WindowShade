## 最终签名构建与门禁（2026-09-29）

- **构建**：`.build/duo-validation/WindowShade.app`，1.0.16 / build 16，Team FVGLY6W6S4；
  SUFeedURL `https://windowshade.aaronlau.me/appcast.xml` 与 EdDSA 公钥与仓库一致；
  `--self-check` 返回 `WindowShade self-check build=16 ok`。
- **类型检查**：`prototype/build.sh --check` 通过。它已改成和发布构建同样的
  `-O -whole-module-optimization`（旧的 `-typecheck` 会漏掉整模块优化下才报的隔离错误——
  真构建过不了的 `App/TrackpadGestures.swift` 隔离错误就是这么漏过去的，已修）。
- **单测**：27 个 `tests/run-*.sh` 全部通过。
- **官网**：`site/` 下 `npm run build && npm run check` 通过（40 个部署资源）；中英文页都改成
  `1.0.16 · ZIP 6.49 MB`。
- **卷轴停下来那一段改成和官网同一条曲线**（2026-09-30）：位置按经过的时间解一条阻尼弹簧
  （ζ=0.88、ω=2π/0.42），帧由显示器的刷新时钟给（`CADisplayLink`），不再是 60Hz 定时器
  每帧固定走一小步；惯性投影的减速率也对齐官网（0.998）。弹簧的解析解有单测，和细步长数值积分对上。
  重跑 `--strip` 8/0（同一签名构建）。
- **卷轴每半秒的对账挪出主线程**：`CGWindowListCopyWindowInfo`（约 3 毫秒）和新窗口的
  `appWindows(pid:)`（约 20 毫秒，碰上不响应的 App 能到 2 秒消息超时）原来都在主线程上，
  现在交给后台线程问、主线程只拿结果对账；同一轮还修了 `advanceMotion` 每帧写 `strip.offset`
  带进来的回归（它会让挨着停靠列的那一列不再让回原宽）。
- **更新器本地隔离验证**（`tests/run-update-integration.sh`，新增）：在临时 store 里跑真东西——
  自检、状态迁移（写出并读回样例状态）、换回（坏版换成备份那一版、store 记 `restored`、
  `refused` 记下坏版），以及坏备份（SHA-256 对不上 → `restoreFailed` 且装着的包一动不动）。
  1.0.16 / build 16 的签名构建上 13 通过 / 0 失败。**Sparkle 那一端的集成（真下载真安装）仍未做**，
  需要 Sparkle 2.10.0 发布包里的 `sign_update` / `generate_appcast`。
- 本轮**未提交、未打标签、未发布、未部署**。
