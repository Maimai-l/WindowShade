## 识别器（C2，`prototype/Core/ConductorGesture.swift`）

输入是一次连续接触的完整轨迹（秒、0…1 归一化坐标、y 向上；屏幕坐标先用 `normalized(_:yAxisDown:)` 翻过来）。
抬手后 `recognize` 才给结果；画的过程中 `beatPreview` 只给已完成的拍数，用来逐拍亮起，不执行任何东西。

| 手势 | 判定 | 请求档位 |
| --- | --- | --- |
| 一声 → | 从左往右，斜率在 ±0.25 内，偏离直线不超过水平距离的 20% | low |
| 二声 ↗ | 同上，斜率 ≥ 0.45 | medium |
| 三声 ˇ | 恰好一个谷，谷底在中段，下降和上升都 ≥ 水平距离的 25% | high |
| 四声 ↘ | 同一声，斜率 ≤ −0.45 | xhigh |
| 一到四拍 | 每拍落下 ≥ 0.12 并回弹 ≥ 落差的 40%，水平漂移小 | low…xhigh |
| 五拍 / 六拍 | 同上，必须完整 | max / ultra（唯一来源） |

一律拒识、不猜最近档位的情况：太小（< 触控区 15%）、太短（< 0.12 秒，当误碰）、整句超过 6 秒、竖直滑动、
从右往左或中途折返、斜率夹在两档之间、碎折线、最后一拍没回弹、拍点间隔不在 0.15–1.1 秒、超过六拍、
声调和拍子两种解释都成立（比如很窄的 V）、坐标非有限或越界、时间倒流。速度不改变档位。

这些阈值都是候选值，来自 v3 §5.3 的建议范围，要拿真实遥控器轨迹回放后再调（`tests/ConductorGestureTests.swift` 现在用的是合成轨迹）。

测试：`tests/run-conductor-gesture-tests.sh`，覆盖 CONDUCTOR-ACCEPTANCE 的 C-011…C-022 中纯逻辑能判定的部分。
C-023（轨迹里带 Select 不算确认）、C-024（选择域切换）、C-025（模型槽位）属于界面与会话层，接界面时再做。
